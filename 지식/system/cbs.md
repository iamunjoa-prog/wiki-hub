> 적용대상 **공통** · 관련 시스템 CBS

## 요약

**CBS(Contents Billing System, 가입자관리시스템)** 는 프로모션용 **쿠폰, B캐쉬, B포인트** 를 생성·승인·발급·관리하는 사내 시스템이다. 프로모션 운영 프로세스의 **Step 3 쿠폰 생성** 단계에서 쓴다.

## 쿠폰 적용대상 관리

> 적용대상 **공통** · 관련 시스템 CBS

### 요약

쿠폰을 쓸 수 있는 **세부 제약 조건** 을 설정하고 **대상 상품·컨텐츠를 매핑** 하는 화면이다. 적용대상을 등록하지 않으면 **승인요청을 할 수 없다.**

### 제약 조건

| 항목 | 설명 | 기본값 |
| --- | --- | --- |
| 가격대 | 쿠폰을 쓸 수 있는 가격대 | 제한 없음 |
| 사용 가능 요일·시간 | 특정 요일(월~일)·시간대 | 제한 없음 |

### 매핑대상구분

| 구분 | 적용 범위 | 사용 가능 쿠폰 |
| --- | --- | --- |
| **상품** | 특정 상품 (쿠폰 정책 생성 시 PPM 선택) | PPM 중심 |
| **약정** | 특정 약정(3/6/12개월). 해당 약정 외 다른 약정·무약정에는 적용 불가 | **월정액 쿠폰만** |
| **전체** | 모든 PPV 컨텐츠 (PPM 상품에는 미적용) | PPV |
| **컨텐츠** | VOD 단건 컨텐츠 단위 | **단건 쿠폰만** |
| **CP** *(추가)* | 특정 '컨텐츠 계약처명' 공급 컨텐츠 | PPV |
| **카테고리** *(추가)* | 특정 카테고리 매핑 컨텐츠 (한국영화, 해외영화, MBC, KBS, 애니메이션 등) | PPV |
| **시리즈** *(추가)* | 상위 시리즈 단위 ('김부장' 선택 시 1~10회차 전체) | PPV |
| **메타유형** *(추가)* | 특정 메타 유형 (영화, 드라마, 예능, 교양 등) | PPV |

> 무약정 쿠폰을 발급한 경우에는 **약정 상품 구매에도** 쓸 수 있다.

### 수정 규칙

- 적용대상이 입력된 상태에서는 **쿠폰 정책을 수정할 수 없다.** 정책을 고치려면 적용대상을 먼저 삭제한다.
- 적용대상은 **승인 완료 후에도 수정 가능** 하며, 수정하면 **이미 발급된 쿠폰에도 즉시 반영** 된다.

- 정책 관점: [PPV 컨텐츠 단위 매핑 기준](PPC-P-03), [약정상품 쿠폰 정책](PPC-P-02)

## P1 — 쿠폰·B캐쉬 정책 등록 및 승인요청

> 적용대상 **공통** · 관련 시스템 CBS

### 요약

신규 프로모션에서 **가장 먼저** 하는 프로세스다.

**1단계 정책 등록 → 2단계 적용대상 등록 (쿠폰 필수) → 3단계 승인요청 → 4단계 승인 완료 후 랜딩·추천순위 설정**

> 사전 조건: **시행 품의 승인 후** 에 등록한다. 품의 승인 전 CBS 선등록은 자제한다. → [운영 프로세스 Step 2](PPC-P-01)

### 단계별 절차

| 단계 | 화면 | 작업 | 주의사항 |
| --- | --- | --- | --- |
| **1. 정책 등록** | 쿠폰/B캐쉬 상품관리 → **신규** 또는 **복사** | 대/중/소분류 지정 → 정책 기본정보 입력 → 저장 | **쿠폰정책 시작/종료일** = 고객이 쿠폰을 등록(인증)할 수 있는 기간. **유효기간** = 등록 후 실제 사용 가능한 기간 |
| **2. 적용대상 등록** | 쿠폰적용대상관리 | 검색으로 정책 조회 → 적용대상 탭에서 매핑대상구분 선택 → 대상 등록·저장 | **필수**. 없으면 승인요청 불가. 적용대상이 있으면 정책 수정 불가 (수정하려면 적용대상 삭제) |
| **3. 승인요청** | 쿠폰정책관리 (또는 각 상품관리) | 정책 조회·선택 → 화면 하단 **승인요청** | 승인요청 상태부터 **정책 수정 불가**. 승인 후 기본 정책 수정은 **CSR** 로 별도 요청. 적용대상은 승인 후에도 수정 가능 (기발급 쿠폰에 즉시 반영) |
| **4. 랜딩·추천순위** | 쿠폰랜딩설정관리 / 쿠폰추천순위관리 → 신규 | 정책 기본정보 입력 → 저장 | **승인 완료 후** 설정 가능. 아래 참고 |

### 4단계 상세

- **쿠폰 랜딩 설정 (필수)**: 설정해야 쿠폰함과 스마트알림에 **[쿠폰 사용하기]** 버튼이 노출된다. 사용률에 직접 영향을 준다.
- **쿠폰 추천순위**: 등록하면 쿠폰함 기본 노출 순위보다 우선 노출된다. 노출 순서: **추천순위 > 만료임박순 > 할인율순**

### 다음 단계

승인요청 직후 담당자에게 메일을 보낸다. → **P2 승인·반려 처리**

### 관련 문서

- **쿠폰정책 핵심 필드**, **쿠폰 적용대상 관리**
- 반려 후 재신청 → **CBS 예외처리**

## P2 — 승인·반려 처리

> 적용대상 **공통** · 관련 시스템 CBS

### 요약

상위 결재권자가 승인요청된 정책을 검토해 **승인** 또는 **반려** 한다.

### 승인요청 후 필수 메일

승인요청을 올린 뒤 **류*영 매니저** 에게 메일로 승인을 요청한다. 본문에 아래 3가지를 적는다.

1. 쿠폰명
2. 쿠폰정책번호
3. 정산방식

→ [담당자·결재 라인](PPC-R-02)

### 승인 / 반려 절차

| 처리 | 화면 | 절차 | 결과 |
| --- | --- | --- | --- |
| **승인** | 쿠폰승인현황관리 | 승인요청 상태 목록 조회 → 정책정보 검토 → **승인** → 팝업 확인 | 승인·반려가 끝난 정책은 하단 승인/반려 버튼이 비활성화 |
| **반려** | 쿠폰승인현황관리 | 승인요청 상태 목록 조회 → **반려 사유 입력** → **반려** → 팝업 확인 | **승인대기(수정 가능)** 상태로 돌아감. 수정 후 재승인요청 가능 |

### 관련 문서

- 이전 단계: **P1 정책 등록 및 승인요청**
- 반려 후 재신청 요령: **CBS 예외처리**

## P3 — 발급취소·만료 처리

> 적용대상 **공통** · 관련 시스템 CBS

### 요약

발급된 **B캐쉬** 에 문제가 생겼을 때 회수(발급취소)하거나 만료시키는 기능이다.

> **쿠폰은 CBS에 만료 처리 기능이 없다.** 이미 발급된 쿠폰을 만료시켜야 하면 **CSR** 로 개별 쿠폰 만료 처리를 요청한다.

### 발급취소 (B캐쉬)

1. **B캐쉬 발급취소** 메뉴 진입
2. 취소할 상품과 대상 고객(서비스관리번호 등) 조회
3. 취소 실행
   - **개별 취소**: 목록 하단에서 해당 건 체크 → **개별취소**
   - **전체 취소**: 하단 **전체취소** → 조회된 모든 내역 일괄 취소

> 상태가 이미 **인증(30)** 또는 **사용완료(40)** 인 건은 전체취소를 해도 **취소되지 않는다**.

### 만료 처리 (B캐쉬)

1. **B캐쉬만료처리** 메뉴 진입 → 서비스관리번호 입력·조회
2. 만료 가능한 목록에서 대상 체크 → **만료처리**
3. 완료되면 하단 만료/취소 목록에 결과가 자동 반영

## 발급 방식별 가이드 (관리자·상담원·인증번호)

> 적용대상 **공통** · 관련 시스템 CBS

### 요약

승인 완료된 쿠폰·B캐쉬를 CBS에서 **직접** 고객에게 지급하는 방법이다.

> **대량 쿠폰 발급은 대부분 ACS로 한다.** → [ACS 간편 캠페인 등록](PPC-ACS)

| 방식 | 언제 쓰나 |
| --- | --- |
| 관리자 예약 발급 | 타겟 리스트를 뽑아 일괄 지급 |
| 상담원 예약 발급 | 고객센터 상담원이 통화 중 즉시 지급 |
| 인증번호 발급 | 인쇄물·제휴사 프로모션으로 코드를 먼저 배포 |

### 1. 관리자 예약 발급

발급 방법이 **'관리자발급'** 인 정책에서 사용한다.

**대량 발급 (엑셀 업로드)**

1. 쿠폰/포인트 발급관리 메뉴 → 관리자발급 정책 선택
2. **Sample** 버튼으로 업로드용 표준 엑셀 양식 다운로드
3. 엑셀에 고객 **서비스관리번호** 기입 → 업로드 → 즉시/예약 발급

**소량 발급 (10건 이하)**

- 엑셀 없이 팝업창에 서비스관리번호를 직접 입력해 발급

### 2. 상담원 예약 발급 및 권한 설정

발급 방법이 **'상담원발급'** 인 정책에서 사용한다.

**발급**

1. 상담원발급 정책 선택
2. 배포할 유통망 지정 → 배포 수량 입력 → 즉시발급 또는 예약발급
3. 여러 유통망에 대량 배포할 때는 **유통망엑셀발급처리** 체크 후 엑셀 업로드

**상담원 권한 설정**

1. 예약발급 버튼 옆 **상담원권한설정** → **신규**
2. 정책 상세와 대상 상담원 ID 입력 → 저장

**상담원 ID 입력 규칙 (중요)**

| 규칙 | 내용 |
| --- | --- |
| **A** | ID 앞자리가 **300B** 이면 **30B** 로 바꿔 입력 |
| **B** | ID가 **10자리를 넘으면 앞 10자리까지만** 입력 |
| **C** | 반드시 **A → B 순서** 로 적용 |

> 예시(가상 ID): 300B12345678 → A 규칙 적용 30B12345678 (11자리) → B 규칙 적용 30B1234567 (10자리)

> 대상 ID를 할당하면 **권한을 받은 상담원 외에는 쿠폰을 적용(발급)할 수 없다.**

### 3. 인증번호 발급

인쇄물·제휴사 프로모션으로 **난수 코드를 먼저 배포** 하고 고객이 직접 등록하게 한다.

- 발급 수량만 입력하면 고유 인증번호가 대량 생성·발급된다 (쿠폰 상태 **'등록'**).
- 시스템 구조상 **소량 발급 기능은 없다.**
- 모바일 전용으로 제한하려면 **모바일전용발급여부** 체크 → **CBS 핵심 필드**

### 관련 문서

- Swing 공지 시 상담원 권한 사전 준비 → [운영 프로세스 Step 4](PPC-P-01)

## 예외처리·장애방지

> 적용대상 **공통** · 관련 시스템 CBS

### 발급이 안 된다 — 최대발급수량 초과

정책에 입력한 **최대발급수량** 을 넘겨 발급하면 시스템이 막는다. 프로모션 타겟 모수를 정확히 확인한 뒤 설계한다.

- 이미 승인된 정책의 수량을 늘려야 하면 기본 정책 수정이므로 **CSR** 요청이 필요하다. → **P1 3단계**

### 즉시 발급 중 "처리 중" 표시가 계속 떠 있다

발급 대상이 많거나, 같은 시스템에 다른 예약 발급이 대기 중일 때 즉시 발급을 실행하면 완료될 때까지 **Progress Bar** 가 계속 표시된다.

> **화면을 강제로 닫지 말고** 완료될 때까지 기다린다. 중간에 닫으면 데이터가 누락될 수 있다.

### 반려된 정책을 다시 올리고 싶다

완료되었거나 반려된 정책은 기존 정보를 수정할 수 없다.

1. 기존 정책에서 **복사** 로 값을 불러온다
2. 적용 기간, 중복 여부 등 필요한 항목을 고친다
3. **신규 정책번호** 로 저장하고 승인요청을 처음부터 다시 진행한다

→ **P1 정책 등록 및 승인요청**

> 참고: **P2**에서는 반려 시 "승인대기(수정 가능)" 상태로 돌아간다고 되어 있어 원문 내 설명이 엇갈린다. *(보완 필요: 반려 건을 그대로 수정해 재요청할 수 있는지 확인)*

### 그 밖에 자주 막히는 지점

| 증상 | 원인·조치 | 문서 |
| --- | --- | --- |
| 승인요청 버튼이 안 눌린다 | 적용대상 미등록 | **P1 2단계** |
| 정책 수정이 안 된다 | 적용대상이 입력되어 있음 → 적용대상 삭제 후 수정 | **적용대상 관리** |
| 이미 발급된 쿠폰을 만료시켜야 한다 | 쿠폰은 만료 기능 없음 → CSR 요청 | **P3** |
| 상담원이 쿠폰을 발급하지 못한다 | 상담원 ID 규칙(A→B) 미준수 또는 권한 미할당 | **발급 방식별 가이드** |
| 쿠폰함에 [쿠폰 사용하기] 버튼이 없다 | 쿠폰 랜딩 미설정 | **P1 4단계** |
