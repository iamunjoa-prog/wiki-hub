> 적용대상 **공통** · 관련 시스템 Swing

## 이 문서는

**Swing 접점공지**는 프로모션·상품 변경 내용을 **고객센터 상담원(상담M)**이 알 수 있도록 전파하는 공지 요청 기능입니다. 프로모션 운영 프로세스의 **Step 4 Swing 공지**에 해당합니다.

**왜 필요한가** — 고객이 쿠폰·할인을 문의했을 때 상담원이 응대할 수 있으려면, **프로모션 시작 전에** 공지가 고객센터까지 전파되어 있어야 합니다. 공지 요청을 늦게 하면 상담원이 모르는 채로 고객을 맞이하게 됩니다.

## 접속 경로

**Swing ▶ PLM(상품관리) ▶ 접점공지 ▶ 접점공지 등록요청**

> 등록 화면에서 **주황색 영역은 필수 입력** 항목입니다.

## 전체 흐름

1. **등록 요청서 작성** — 공지 구분, 유형, 대상, 기간, 제목·본문 입력 → 아래 **접점공지 등록 입력 항목**
2. **체크리스트 작성·저장** — 12개 항목 체크 → 아래 **사전 체크리스트**
3. **공지요청** — 요청 후에는 **수정 불가**
4. **고객센터 검토·등록** — 아래 **공지요청 이후 프로세스**

## 공지요청 이후 프로세스

| 순서 | 담당 | 내용 |
| --- | --- | --- |
| ① | 고객센터(이**컴) 접점공지 승인권한자 | 1차 확인 — **승인 또는 반려** |
| ② | 고객센터(이**컴) 담당자 | 2차 확인 → 등록자와 **MKIS 등록 내용 최종 확인** (NateOn 쪽지로 전달) → 사업부서 확인 |
| ③ | 사업부서 | confirm 완료된 내용으로 **MKIS 등록·공지** |

> 등록자는 ②단계에서 NateOn 쪽지로 오는 MKIS 등록 내용 확인 요청에 응답해야 공지가 최종 게시됩니다.

## PPC 프로모션과 연결되는 준비 사항

- 상담원이 직접 쿠폰을 발급해야 하는 프로모션이면 **CBS 상담원 권한 설정**을 미리 준비하세요. 상담원 ID는 **A→B 순서 규칙**을 지킵니다. → [CBS 발급 방식별 가이드](PPC-CBS#h-발급-방식별-가이드-(관리자·상담원·인증번호))
- 공지 요청일은 고객센터 **전파 완료 기한**이므로 프로모션 시작일보다 앞서게 잡습니다.

## 접점공지 등록 입력 항목

> 적용대상 **공통** · 관련 시스템 Swing

접점공지 등록요청 화면의 입력 항목을 순서대로 정리했습니다.

### 1. 공지사항 구분 — 6개 중 1개 필수

| # | 구분 | 선택 기준 |
| --- | --- | --- |
| ① | 실시간 공지 | 아래 5개 유형에 속하지 않는 대다수 공지 |
| ② | SMS/MMS 발송 | 프로모션, **쿠폰 만료 안내**, 서비스 무료체험 안내, 서비스 개편, 설문조사 등으로 고객에게 문자를 보낼 때 |
| ③ | 신문/보도 | 당사 서비스와 직·간접적으로 관련된 기사·보도자료 안내 |
| ④ | 오류/작업/업데이트 | 작업·점검·오류로 인한 서비스 일시 중단, UI·STB·AP 업그레이드, 특정 오류 응대 지침 전파 |
| ⑤ | **이벤트** | **B tv 관련 각종 이벤트/프로모션 진행 시** |
| ⑥ | 상품 공지 | 신규 상품·서비스 출시, 기존 상품 종료, 신규 가입 일시 중단 |

**긴급공지** (선택 체크): 계획되지 않은 갑작스러운 상황 (타사 장애로 인한 당사 서비스 이용 불편, CEO 긴급 지시 등)

> PPC 온스크린 프로모션은 원문 기준상 **⑤ 이벤트**에 해당합니다. 고객 대상 문자 발송이 함께 있으면 **② SMS/MMS 발송**을 확인하세요.

### 2. 템플릿

**'기본공지요청서'** 상태를 그대로 둡니다 (변경 불가).

### 3. 공지 요청일

접점공지 내용이 고객센터에 **전파 완료되어야 하는 마감일(End-Time)**을 선택합니다.

### 4. 공지 유형 — 2개 중 1개 필수

| # | 유형 | 선택 기준 |
| --- | --- | --- |
| ① | 서비스/상품 공지 | 상품·**할인**·마케팅 프로그램·APP 관련 변경·추가 사항 |
| ② | 기타 | 서비스/상품 외 공지 |

'서비스/상품 공지' 선택 시 **공지 대상 상품**을 고르는 화면이 뜨고, **상품 / 할인 / 마케팅프로그램 / APP** 중 선택하면 각각의 팝업 화면에서 대상을 지정합니다.

> 확인 필요: 팝업 화면별 입력 방법은 원본 문서에 화면 캡처로만 있습니다. 할인·마케팅프로그램 팝업 입력 항목을 확인해야 합니다.

### 5. 업무 구분 — 복수 선택

| # | 구분 | 범위 |
| --- | --- | --- |
| ① | 무선 | SKT 무선 서비스 (스마트폰, SKT 앱 서비스 등) |
| ② | **유선** | 유선 Mass 서비스 (초고속인터넷, **IPTV**, 전화 및 부가서비스) |
| ③ | 기업솔루션 | 기업용 서비스 (S-market, Biz 솔루션 등) |

> B tv 프로모션은 IPTV이므로 **② 유선**에 해당합니다.

### 6. 공지 대상 회사 — 복수 선택

| # | 회사 | 대상 |
| --- | --- | --- |
| ① | SKT | SKT 무선 전용 고객센터 또는 SKT 유선 고객센터 |
| ② | SKB | SKB 유선 고객센터 |

### 7. 공지 기간

공지 내용이 대상 고객센터에 전파되어 **상담M이 인지하고 있어야 하는 기간**입니다. 보통 프로모션 운영 기간을 포함하도록 잡습니다.

### 8. 공지 조회 채널 — 복수 선택

① 고객센터 (상담M) · ② 지점 (홈앤서비스 지점) · ③ 대리점 (영업점) · ④ 기업고객센터(SKB) · ⑤ 솔루션고객센터(SKT)

### 9. 제목 및 본문

제목 앞에 공지 대상 고객센터를 표기합니다.

| 대상 | 제목 형식 |
| --- | --- |
| 106 고객센터만 | `(106) 제목` |
| 7000번(CATV) 고객센터만 | `(7000) 제목` |
| 106·7000번 모두 | `(공통) 제목` |

### 10. 체크리스트 → 공지요청

1. 하단 **'체크리스트'** 버튼 → 12개 항목 작성·저장 → 아래 **사전 체크리스트**
2. **'공지요청'** 버튼 클릭 — 팝업 3개가 순서대로 뜹니다: "공지 요청 이후에는 수정할 수 없습니다. 진행하시겠습니까?" → "저장되었습니다." → "요청 처리되었습니다."

> **요청 후에는 수정할 수 없습니다.** 요청 전에 내용을 최종 확인하세요.

이후 절차는 위 **공지요청 이후 프로세스**를 보세요.

## 사전 체크리스트

> 적용대상 **공통** · 관련 시스템 Swing

공지요청 전에 등록 화면 하단 **'체크리스트'** 버튼으로 12개 항목의 체크결과를 **예 / 아니오 / 해당없음** 중 하나로 선택하고 저장합니다.

> - 체크결과가 적합하지 않으면 저장 후 공지요청을 해도 **체크리스트가 다시 뜹니다.**
> - **①번 항목에 '아니오'를 선택하면 다음 단계로 진행할 수 없습니다.**

### 체크리스트 12개 항목

| # | 질문 |
| --- | --- |
| ① | **개인 고객에 대한 이슈는 없는가?** (명의도용, 임의가입, 개인정보 유출 등) |
| ② | 기존 고객에 대한 이용자 차별 항목은 없는가? |
| ③ | 기존 고객이 서비스를 이용하는 데 불편함은 없는가? |
| ④ | 서비스에 대한 안전성은 확보되었는가? (사전 Test 등) |
| ⑤ | 서비스 이용을 위해 별도 고객 동의가 필요 없는가? — 서비스 신청·해지·응대 신청권자 범위 확인 |
| ⑥ | 고객에게 사전 커뮤니케이션이 진행되는가? (E-mail, SMS 등) — 커뮤니케이션 내용 첨부 |
| ⑦ | 홈페이지에 공지가 되었는가? |
| ⑧ | 방송통신법, 공정거래법 등 GR 이슈는 없는가? (방통위 가이드 준수) |
| ⑨ | 이용약관 준수 및 신고가 완료되었는가? |
| ⑩ | 재판매 고객에게도 동일하게 적용하는가? |
| ⑪ | VoC 발생이 예상되며 처리 방안(응대 시스템)은 준비되어 있는가? |
| ⑫ | 전산으로 처리 불가한 경우에 대한 처리 방안은 준비되어 있는가? |

### PPC 프로모션에서 특히 볼 항목

여러 항목이 프로모션과 무관해 보이지만, 실제로는 이렇게 연결됩니다.

| 항목 | 연결되는 PPC 기준 |
| --- | --- |
| ② 이용자 차별 | 타겟 한정 쿠폰·배너 프로모션인 경우 대상 선정 기준 확인 |
| ④ 사전 Test | 테스트 STB 발송 검증 → [ACS P2](PPC-ACS#h-P2-—-테스트-STB-검증-및-승인요청) |
| ⑤ 별도 고객 동의 | 월정액 정가 전환동의 → [다크패턴 대응](PPC-P-02#h-다크패턴-대응-및-정가-전환동의) `[PPM]` |
| ⑧ GR 이슈 | 다크패턴 규제 → [다크패턴 대응](PPC-P-02#h-다크패턴-대응-및-정가-전환동의) `[PPM]` |
| ⑪ VoC 대비 | UI 버전 미지원 고객의 쿠폰 미적용 등 → [UI 버전표](PPC-R-01) |
| ⑫ 전산 처리 불가 | 기발급 쿠폰 만료는 CSR 처리 → [CBS P3](PPC-CBS#h-P3-—-발급취소·만료-처리) |

> 위 연결표는 PPC 관점에서 참고용으로 정리한 것입니다. 체크 기준 자체는 원문 12개 항목을 따릅니다.
