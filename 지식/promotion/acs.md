## 이 문서는

**ACS(Advanced Campaign System, 통합 캠페인 시스템)**를 실제로 조작하는 방법을 다룹니다. 가입자 타겟팅 설계, 할인 오퍼(쿠폰) 할당, TV팝업·토스트 팝업·모바일 푸시 등 접점 채널로 메시지를 발송·제어하는 화면이 전부 여기 있습니다. 프로모션 운영 프로세스의 **Step 6 캠페인 실행** 단계에서 씁니다.

정책 자체(무엇을·왜)는 여기 없습니다 — [프로모션 정책·업무 개요](PPC-P-01)를 먼저 보세요.

## 이 문서 안의 챕터

**보통 이 순서로 씁니다.** 캠페인 기획·타겟팅 변수를 정하고, 접점 채널을 연동하고, P1로 등록해서, P2로 검증·승인받습니다. 여러 세그먼트·Wave가 얽힌 복잡한 캠페인이면 시나리오 캠페인으로 넘어갑니다.

| 챕터 | 무엇을 다루나 |
| --- | --- |
| **캠페인 기획·타겟팅 변수** | 캠페인 분류, 기간, 실험군/대조군, 캡핑 등 기본 설정값 |
| **접점 채널별 연동 규격** | TV팝업·타겟배너·토스트 팝업·모바일 푸시 채널별 연동 필드 |
| **비즈니스 쿼리 유형 (NaviLog 2.0)** | 준실시간 가입자 행동 기반 타겟팅 쿼리 |
| **P1 — 간편 캠페인 등록 및 오퍼·채널 매핑** | 단발성 프로모션의 표준 등록 절차 |
| **P2 — 테스트 STB 검증 및 승인요청** | 상용 발송 전 검증·결재 절차 |
| **시나리오 캠페인 워크플로우 모델링** | 여러 세그먼트·채널·Wave를 캔버스로 설계 |
| **예외처리·장애방지** | 자주 막히는 상황과 원인 |

## 캠페인 기획·타겟팅 변수

> 적용대상 **공통** · 관련 시스템 ACS

간편 캠페인 등록 화면에서 캠페인의 뼈대를 정하는 값들입니다. 여기서 잘못 고르면 뒤 단계(타겟팅·오퍼)에서 선택지 자체가 좁아집니다.

| 항목 | 설정값 | 설명 |
| --- | --- | --- |
| **캠페인 분류** | 월정액 / PPV 매출증대 / 고객구조개선 / 공지 | 분류에 따라 선택 가능한 상품 풀이 엄격히 제한됨. **월정액** → 월정액 상품만, **PPV** → 단건 PPV VOD만 → [상품 분류 체계](PPC-P-01#h-상품-분류-체계-(PPV-/-PPM)) |
| **캠페인 기간** | 시작일 / 종료일 | **시작일**: 대상 모수를 추출해 쿠폰 시스템·채널로 발송하는 기준일. **종료일**: 구매 반응·성과 수집 마감일 |
| **기간 유형** | 일회성 / 주기성 | 일회성: 시작일에 1회 추출·실행. 주기성: 일정 간격 반복 (배치 스케줄링) |
| **공휴일 처리** | 공휴일 포함 / 공휴일 배제 | 주기성 캠페인 실행일이 공휴일이면 당일 발송할지, 다음날·전날 실행할지 선택 |
| **실험군/대조군 비율** | 슬라이더 또는 숫자 (예: 10) | 성과 검증용으로 오퍼를 보내지 않을 대조군 비율. **실험군:대조군 = 90:10 권장** |
| **최종 조정 고객 수** | 조정 안함 / 100,000명 / 200,000명 등 | 추출 모수가 예산·시스템 한계를 넘으면 설정 수만큼 **랜덤 캡핑** |

**관련 문서** — 성과 수집이 종료일 이후로 연장되는 경우는 아래 **예외처리·장애방지**, 입력 순서는 아래 **P1**을 보세요.

## 접점 채널별 연동 규격

> 적용대상 **공통** · 관련 시스템 ACS

| 채널 | 핵심 연동 필드 | 설정 규칙·주의 |
| --- | --- | --- |
| **TV 팝업 / OAP** | 팝업 ID / 편성 명칭 / 메일 기안 폼 | 상용 편성된 TV팝업 중 타겟팅할 팝업을 매핑. 하단 **메일 기안 UI**로 편성 채널 담당자에게 연동 협조 메일을 즉시 상신 |
| **타겟배너(빅배너) / 타겟메뉴(블럭)** | GNB 유형 / 콘텐츠 ID / 노출 종료일 | 단말 버전 그룹(v4.0 / v5.0)에 맞춰 배너 이미지 경로와 GNB 편성 영역(예: TV다시보기)을 매핑하고 노출 기간 제어 |
| **v5.0 토스트 팝업** | 바로가기 유형 (텍스트, 시놉바로가기, 장르홈, APP 등) | 클릭 시 랜딩 목적지 제어. **시놉바로가기**: 타겟 VOD 상세 ID. **장르홈**: 랜딩할 GNB 메뉴. **APP**: 인앱 서비스의 Service ID, Item ID, VAS ID |
| **Push Message (모바일 B tv)** | 메시지 형태 / Notice No / Content ID | 아래 작성 규칙 참고 |

### Push Message 작성 규칙

- **VOD 상세보기 이동**: Content ID 필드에 **중괄호를 포함한 코드**를 적습니다 (예: `{D28F151D-...}`). **SER_NO 필드는 반드시 빈칸**입니다.
- **Web 이동**: 메시지 길이 제한 때문에 원본 URL을 **단축 URL**로 줄여 등록합니다. 이미지 URL도 동일합니다.

> 확인 필요: 원문은 단축 URL 도구로 goo.gl을 안내하지만, goo.gl은 신규 생성이 중단된 서비스입니다. 현재 사용하는 단축 URL 도구를 확인해야 합니다.

**관련 정책** — [TV팝업 운영 기준](PPC-P-04) (버튼별 UI 버전, 피로도 제외), [배너 유형별 편성 기준](PPC-P-04). 단축 URL 미적용 시 증상은 아래 **예외처리·장애방지**에 있습니다.

## 비즈니스 쿼리 유형 (NaviLog 2.0)

> 적용대상 **공통** · 관련 시스템 ACS

준실시간 가입자 이벤트 수집 고도화(**NaviLog 2.0**)로, 타겟팅 캔버스에서 가입자 행동을 준실시간으로 포착하는 쿼리 템플릿입니다. 조회 범위는 **수행 시점 기준 최대 24시간** 이내 로그입니다.

| 쿼리명 | 포착하는 행동 | 활용 예시 |
| --- | --- | --- |
| **실시간시청_타게팅_V2** | 편성표 진입, 채널 선택, 미니편성표 노출 | STB 구동 후 전체편성표 메뉴에 진입한 가입자 |
| **VOD시청_타게팅_V2** | VOD 재생 시작, 이어보기, 연관 영상 선택 | 특정 VOD(예: 베놈2) 시놉시스 진입 후 예고편을 재생한 가입자 |
| **메뉴이동_타게팅_V2** | 홈, OCEAN, 영화, 월정액 등 메뉴 이동 | OCEAN 월정액 홈의 '새로 들어온 영화' 블록에 진입한 가입자 |
| **시놉시스_타게팅_V2** | 단편·시즌 시놉시스 진입, 줄거리·더보기 선택 | 영화 상세 시놉시스에서 구매하기 버튼을 누른 가입자 |
| **콘텐츠선호도_타게팅_V2** | 찜하기, 좋아요, 리뷰 입력 | 시놉시스 평점 창에서 리뷰·별점을 남긴 가입자 |
| **검색_타게팅_V2** *(신규)* | 통합검색 진입, 키워드 입력, 결과 선택 | 검색 결과에서 특정 VOD를 선택한 가입자 |
| **구매_타게팅_V2** | 결제창 진입, 구매 시도·완료·취소 | 결제 팝업까지 들어왔다가 결제하지 않고 취소한 가입자 |

**쓸 때 주의할 것** — 준실시간 쿼리와 일반 대용량 배치 쿼리를 한 캔버스에 섞지 마세요(아래 **예외처리·장애방지 — 쿼리 1분 초과** 참고). 테스트 단말에서 로그가 잡히지 않으면 STB 매핑부터 확인하세요. 캔버스 조작 방법은 아래 **시나리오 캠페인 워크플로우 모델링**에 있습니다.

## P1 — 간편 캠페인 등록 및 오퍼·채널 매핑

> 적용대상 **공통** · 관련 시스템 ACS

단발성 프로모션에서 **기본 기획 → 가입자 추출 → 오퍼 → 접점 채널**을 한 흐름으로 연결하는 표준 절차입니다.

**1단계 캠페인 기본 기획 → 2단계 타겟팅 조건 설계·대상 추출 → 3단계 오퍼 매핑 → 4단계 접점 채널 설정**

> 사전 조건: 사용할 쿠폰 정책이 CBS에서 **승인 완료**되어 있어야 합니다. → [CBS P1](PPC-CBS#h-P1-—-쿠폰·B캐쉬-정책-등록-및-승인요청)

| 단계 | 화면 | 작업 | 주의사항 |
| --- | --- | --- | --- |
| **1. 기본 기획** | 간편 캠페인 등록 (기본 정보) | 캠페인 분류(예: 월정액) 선택 → 기간 설정 → 대상 상품(예: JTBC 월정액) 매핑 → 저장 | 오퍼 매핑 **후에** 기본 정보의 대상 상품을 수정·삭제하면 **저장된 오퍼 정보가 강제 초기화**됩니다. 기획을 확정한 뒤 조작하세요 |
| **2. 타겟팅** | 타겟팅 설정 | 쿼리 템플릿(예: 고객프로파일_일별) 선택 → 필수값(★) 입력 → **[추출실행]**으로 모수 확인 → 대조군 비율(예: 10%) 입력 | **피로도 정책 필수**: 제외조건 탭에서 **동일 캠페인 접촉 제외**와 **TV팝업 2주 2회 제외** 체크 |
| **3. 오퍼** | 오퍼 설정 | 쿠폰/포인트 탭 → 정책 검색 → 유효기간·할인율 설정 → **[할당]** → 하단 목록에 추가됐는지 확인 | 쿠폰 적용 상품은 1단계에서 매핑한 상품 풀과 자동 동기화. **중복 발송 허용여부는 '불가' 권장** |
| **4. 채널** | 접촉 채널 설정 | 드롭다운에서 채널 선택(예: v5.0 토스트 팝업) → 랜딩 바로가기 유형 지정 → 이미지 업로드 | 모바일 푸시 본문의 모든 링크는 **단축 URL**로 변환 |

**다음 단계** — 테스트 발송으로 노출을 확인하고 승인을 요청합니다. 아래 **P2**로 이어집니다.

**관련 문서** — 위 **캠페인 기획·타겟팅 변수**, **접점 채널별 연동 규격**. 스마트알림 발송 일정과 겹치지 않게 [스마트알림 규칙](PPC-P-04)도 확인하세요.

## P2 — 테스트 STB 검증 및 승인요청

> 적용대상 **공통** · 관련 시스템 ACS

기획·타겟팅이 끝난 캠페인을 상용 발송 전에 **본인 테스트 단말로 검증**하고 **승인을 상신**하는 절차입니다.

### 1. 테스트 STB 발송 검증

1. 채널 설정 화면 하단 **[TV팝업 테스트 발송]** 영역으로 이동
2. 테스트그룹을 **전체**로 지정 → **[테스트 STB 목록 출력]** (본인 사번에 미리 연결된 단말 조회)
3. **[테스트 발송]** → 본인 테스트 단말에 팝업·토스트가 규격대로 뜨는지 **직접 눈으로 확인**

단말이 이상하면 [캠페인 관리] > **[STB 관리]**에서 본인 단말 식별자(STB_ID)와 가입 서비스관리번호가 **1:1로 매핑**되어 있는지 확인하세요.

### 2. 승인 기안 요청

1. GNB **[승인]** 탭 → 기안 요약 Comment 작성
2. 결재 라인 확인: **BTV 캠페인 관리자(김*복 매니저)** 및 **VOD**팀 팀장**
3. **[승인요청]** 상신

> **필수**: 상신 직후 사내 메일로 **류*영 매니저**에게 검토 협조 메일을 보냅니다. 본문에 **1) 캠페인명 2) 쿠폰정책번호 3) 정산방식**을 적습니다. → [담당자·결재 라인](PPC-R-02)

**승인요청 후 수정** — 승인요청 상태가 되면 캠페인 데이터가 **잠금(읽기 모드)**됩니다. 수정하려면 **승인요청취소**를 먼저 해야 수정 메뉴가 다시 열립니다.

**관련 문서** — 이전 단계는 위 **P1**. 테스트 단말에서 준실시간 로그가 안 잡힐 때는 아래 **예외처리·장애방지**를 보세요.

## 시나리오 캠페인 워크플로우 모델링

> 적용대상 **공통** · 관련 시스템 ACS

**시나리오 캠페인**은 하나의 캠페인 안에서 여러 가입자 세그먼트·여러 채널·후속 Wave(반응 여부 추적)를 캔버스에 노드로 그려 설계하는 방식입니다. P1의 단순 절차로는 부족한, 1차 반응을 보고 2차를 내보내는 캠페인에 씁니다.

### 모델링 절차

1. GNB **[시나리오 캠페인 등록]** → 캠페인 기본 기획 정보 저장
2. 좌측 컴포넌트 목록에서 노드를 끌어 우측 캔버스에 **드래그 앤 드롭**
3. 노드 테두리에 마우스를 올리면 나오는 연결 포인트를 클릭한 채 다음 노드로 드래그 → **링크 선(화살표)** 생성

### 노드 종류

| 노드 | 역할 | 설정 방법·조건 |
| --- | --- | --- |
| **Campaign Start** (초록) | 시나리오 전체 작동 스케줄·주기 정의 | 캔버스당 **1개만**. 더블클릭 → 속성 창에서 되풀이 여부, 수행 주기(예: 매일, 특정 요일), 가동 시각 입력 |
| **비즈니스 쿼리** (빨강) | 가입자 추출 조건 | 속성 창에서 마트 템플릿·변수 조건 입력 후 **[실행]**을 눌러야 가동. 검증되면 우측 상단 **초록 체크** 표시 → 위 **쿼리 유형** 참고 |
| **Join** | N개 고객군 결합 | 교집합, 차집합, 합집합-교집합, 기준유지 등. **조인 키 매핑 필수**: 좌측 기준 컬럼(예: CUST_ID)을 대상 컬럼의 CUST_ID 위로 드래그 드롭 |
| **Multi-Step** | 1차 발송 반응을 보고 2차 Wave 설계 | 속성 창에서 **반응이력사용** 체크 → 이전 캠페인 반응 유형(예: 채널미반응자, 구매미반응자) 선택 → 일정(예: 실행일 이후 1일 후) 지정 → 아래에 새 오퍼·채널 노드 연결 |

> 준실시간 쿼리와 배치 쿼리를 한 캔버스에 섞으면 안 되는 이유는 아래 **예외처리·장애방지**에 있습니다.

## 예외처리·장애방지

> 적용대상 **공통** · 관련 시스템 ACS

### 캠페인이 끝났는데 성과가 계속 수집된다 — 오퍼 유효기간 연장

반응 수집은 기본적으로 **캠페인 종료일에 마감**됩니다. 단, 할인 쿠폰·포인트의 **유효기간 만료일이 캠페인 기간보다 길면**, 시스템이 자동으로 **쿠폰 만료일까지 성과 수집을 연장**합니다. 기획안의 성과 측정 기간을 잡을 때 반영하세요.

### 푸시를 눌러도 화면이 안 열린다 — 단축 URL 미적용

모바일 B tv 푸시의 URL 필드는 단말 전송 한계 때문에 **잘림 현상**이 자주 생깁니다. 잘리면 가입자가 눌러도 랜딩되지 않습니다. 메시지 본문과 이미지 경로 모두 **단축 URL**로 바꿔 적으세요. → 위 **접점 채널별 연동 규격**

### 테스트 단말에서 준실시간 로그가 안 잡힌다 — STB 매핑 누락

NaviLog가 수집한 행동 로그의 **셋톱박스 식별자**와 **서비스 가입자 번호**가 ACS에서 매핑되지 않으면 발생합니다. [캠페인 관리] > **[STB 관리]**에서 본인 기기 ID가 가입 정보와 1:1로 연결되어 있는지 먼저 확인하세요. → 위 **P2**

### 준실시간 타겟 대상이 누락된다 — 쿼리 1분 초과

준실시간 쿼리는 수행 시점부터 **최대 24시간** 이내 로그를 조회합니다. 한 캔버스에 **일반 대용량 배치 쿼리**와 **준실시간 쿼리**를 섞으면, 배치 쿼리 대기가 길어져(**1분 초과**) 준실시간 대상 시점이 틀어지고 누락될 수 있습니다.

> **단발성 쿼리 캔버스와 실시간 이벤트 쿼리 캔버스는 분리해서 기획하세요.** → 위 **시나리오 캠페인**

### 그 밖에 자주 막히는 지점

| 증상 | 원인·조치 | 문서 |
| --- | --- | --- |
| 오퍼 설정이 사라졌다 | 오퍼 매핑 후 기본 정보의 대상 상품을 수정·삭제함 | 위 **P1 1단계** |
| 캠페인 수정이 안 된다 | 승인요청 상태(잠금) → 승인요청취소 후 수정 | 위 **P2** |

| ACS 로그인이 안 된다 | 계정 신규 등록·초기화 → 조*경 매니저 메일 요청 | [담당자](PPC-R-02) |
