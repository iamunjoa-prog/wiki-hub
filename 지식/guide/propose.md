## 이 문서는

문서가 낡지 않게 유지하는 방법입니다. 누구나 고칠 수 있고, 관리자가 확인한 뒤 반영됩니다. 마크다운을 몰라도 화면에 보이는 모양 그대로 고칠 수 있습니다.

**위키 문서 수정 방법 한 줄 요약** — 고칠 위키 문서를 열고 오른쪽 위 `✎ 고치기`(또는 장 제목 옆 `✎ 이 장 고치기`)를 눌러 그 자리에서 고친 뒤 `제출하기`를 누릅니다. 관리자가 승인(머지)하면 다음 배포에서 위키에 반영됩니다. 새 문서는 위키 문서 목록의 `+ 새 문서`에서 씁니다.

**말로 고치기** — 형식은 몰라도 됩니다. 챗봇에게 무엇을 어떻게 고칠지 말하면 형식에 맞춘 수정안을 만들어 드립니다. 확인하고 제출하면 관리자 승인을 거쳐 다음 배포 때 위키에 반영됩니다. 말하는 법은 [문서 작성 규칙](HUB-03)의 **형식은 몰라도 됩니다 — 말로 고치는 법**을 보세요.

**왜 제안·승인을 거치나** — 아무나 바로 고칠 수 있으면 문서는 빨리 낡지 않지만 **무엇이 왜 바뀌었는지**를 잃습니다. 반대로 관리자만 고칠 수 있으면 현장 지식이 반영되지 않습니다. 그래서 **실무자가 제안하고 관리자가 확인해 반영**하는 절차를 둡니다.

## 수정 제안 → 승인 절차

1. **고치기** — 문서 오른쪽 위 `✎ 고치기`를 누르면 지금 읽던 장이, 장 제목 옆 `✎ 이 장 고치기`를 누르면 그 장이 편집 칸으로 바뀝니다. 페이지는 옮겨 가지 않습니다.
2. **바뀐 곳 확인** — 고친 곳은 색으로 칠해지고, 오른쪽 편집 패널의 **바뀐 곳** 목록에 장별로 모입니다.
3. **제출** — 맨 위 편집 바나 편집 패널의 `제출하기`를 누르면 **이대로 제출할까요?** 창이 뜹니다. 고치기 전과 후를 확인하고 `제출`을 누르면 **대기 중**으로 내 요청에 올라갑니다.
4. **관리자 검토** — 관리자의 `승인 관리` 메뉴에 대기 항목으로 올라갑니다.
5. **승인 또는 반려** — 승인(=GitHub에서 PR 머지)되면 상태가 **머지됨**이 되고, **다음 배포에서** 위키에 반영되며 버전이 올라갑니다. 머지한 뒤에도 재배포하기 전까지는 화면이 그대로입니다. 반려(닫힘)되면 PR 의견에서 사유를 확인합니다. 보완해 다시 제안하면 됩니다.
6. **이력 확인** — 문서의 `⎇ 히스토리`에서 버전별 변경 내용을 봅니다.

> 진행 상태는 **내 요청 현황** 메뉴에서 확인합니다. 상태 이름은 **대기 중**(관리자 확인 전) · **머지됨**(승인됨, 다음 배포 때 반영) · **닫힘**(반려) 세 가지입니다.

## 고치는 법

편집 중에는 화면 맨 위에 **편집 바**(편집 중 · 임시 저장 시각 · `바뀐 곳 표시 끄기` · `원문 보기(고급)` · `제출하기` · `편집 끝내기`)가, 오른쪽에 **편집 패널**(바뀐 곳 · 확인할 것 · 수정 사유)이 보입니다.

| 하고 싶은 것 | 이렇게 합니다 |
| --- | --- |
| 글자 고치기 | 고칠 글자를 눌러 바로 고칩니다. 화면에 보이는 모양 그대로 고치면 되고, 마크다운 기호는 몰라도 됩니다. |
| 꾸미기·넣기 | 장 위 도구줄에서 `굵게` · `링크`(위키 문서를 골라 걸거나 https 주소 넣기) · `목록` · `번호`, `블록 ▾`(문단·작은 제목·표 (2칸)·구분선), `주의 상자 ▾`(확인 필요·주의·참고)를 씁니다. |
| 표 고치기 | 칸을 눌러 바로 고칩니다. `Enter`를 누르면 아래 칸으로 갑니다. 표 위 줄의 `행 추가 ↑`·`행 추가 ↓`·`열 추가 ←`·`열 추가 →`·`행 지우기`·`열 지우기`로 칸을 늘리고 줄입니다. |
| 지우기·되살리기 | 블록 옆 `지우기`를 누르면 지운 자리에 「지운 문단 · …」처럼 한 줄이 남고, `되살리기`로 되돌립니다. 지운 표 행도 같습니다. |
| 방금 한 것 되돌리기 | 장 도구줄의 `되돌리기`(한 번씩), `이 장 원래대로`(편집을 시작할 때로)를 씁니다. |
| AI에게 부탁 | 장 도구줄의 `AI에게 부탁`에 할 일을 적고 `부탁하기`를 누릅니다. 그 장만 보내서 보통 20초~1분 걸립니다. 결과는 바로 들어가지 않고 칠한 제안으로 먼저 보이니 `받기` 또는 `버리기`를 고릅니다. AI가 장 밖까지 바꿔 오면 받지 않습니다. 편집을 열지 않고 챗봇 대화로 "○○를 △△로 고쳐줘"라고 말해도 수정안을 받을 수 있습니다. |
| 기호째 고치기 | 편집 바의 `원문 보기(고급)`를 누르면 장 원문과 옆 미리보기가 보입니다. `보기 모양으로`를 누르면 돌아옵니다. 회색 상자로 「이 부분은 원문 보기에서 고칠 수 있어요」라고 뜬 곳은 여기서 고칩니다. |

- **가린 이름은 잠겨 있습니다** — `구*화`처럼 가려 둔 이름은 잠긴 칩으로 보입니다. 글자를 채울 수 없고 칩째로만 지울 수 있습니다. 원문 보기에서 가린 글자를 채우면 제출이 막힙니다. 가리는 규칙은 [문서 작성 규칙](HUB-03)의 **사내 정보 주의**를 보세요.
- **확인할 것** — 고치는 동안 편집 패널이 공개 규칙(실명·금액·제휴사명 등)과 끊긴 링크를 검사합니다. ⛔ 줄은 고쳐야 제출할 수 있고, ⚠ 줄은 확인만 하면 제출할 수 있습니다. 줄을 누르면 그 장으로 갑니다. 소제목을 바꿔 다른 문서의 링크가 끊기면 여기에 뜹니다.
- **수정 사유** — 편집 패널의 **수정 사유**에 무엇을 왜 바꿨는지 한 줄 적습니다. 승인하는 사람이 판단하는 근거가 됩니다. 비워 두면 바뀐 곳을 바탕으로 사유가 채워집니다.
- **AI 엔진이 연결되지 않았으면** `AI에게 부탁`을 쓸 수 없습니다. 직접 고치거나 [챗봇 답변 엔진 안내](HUB-04)를 보고 연결합니다.

## 제출 전 확인 창

`제출하기`를 누르면 **이대로 제출할까요?** 창이 뜹니다. 장마다 **원본 v번호**와 **내 수정**을 보이는 글 그대로 나란히 보여 줍니다. `좌우로 보기`·`한 줄로 보기`로 보는 모양을 바꾸고, 마크다운 줄까지 보려면 `원문 비교(고급)`를 누릅니다. 의도한 부분만 바뀌었는지 보고 `제출`을 누릅니다. 더 고칠 것이 있으면 `더 고치기`로 돌아갑니다.

제출하면 「수정 제안을 올렸습니다 · 대기 중」과 PR 번호가 뜹니다. 지금 보이는 문서는 승인·배포 전까지 그대로입니다.

## 임시 저장

- 고치는 내용은 **이 PC의 이 브라우저**에 저절로 임시 저장됩니다. 편집 바에 「임시 저장 시:분」이 보입니다. 다른 PC·다른 브라우저에서는 보이지 않고, 제출하기 전에는 아무에게도 보이지 않습니다.
- `편집 끝내기`를 누르거나 화면을 떠나도 지워지지 않습니다. 그 문서를 다시 열면 문서 위에 「임시 저장한 수정이 있습니다」 띠가 뜨고, `이어서 고치기` 또는 `버리기`를 고릅니다.
- 고친 것을 모두 지우려면 편집 패널의 `고친 것 모두 버리기`를 누릅니다. 되돌릴 수 없어서 한 번 더 묻습니다.

## 다른 분이 먼저 고쳤을 때

- **편집을 시작할 때** 같은 문서에 승인을 기다리는 제안이 있으면 알려 줍니다. `그래도 고치기`로 계속 고칠 수 있지만, 나중에 승인되는 쪽은 다시 올려야 할 수 있습니다.
- **제출할 때 문서가 그사이 바뀌었으면**(다른 제안이 먼저 승인됨) 제출하지 않고 알려 줍니다. 내 수정은 그대로 있습니다.
  - 내가 고친 장이 그대로면 최신 문서 위에 내 수정을 다시 얹어 둡니다. `다시 제출`만 누르면 됩니다.
  - 내가 고친 장도 바뀌었으면 **다른 분이 고친 최신본**과 **내 수정**을 나란히 보여 줍니다. 장마다 `최신본으로 두기` 또는 `내 것으로 덮기`를 고르거나, `최신본에서 다시 고치기`로 다시 엽니다.
- 임시 저장해 둔 사이 문서가 바뀌었을 때도 다시 열면 같은 방식으로 알려 줍니다. 내 장도 바뀌었으면 `나란히 보며 합치기`로 합칩니다.

## Git 워크플로우와의 대응

지식 문서를 Git + 마크다운으로 관리하기 때문에, 이 절차는 Git 동작에 그대로 대응됩니다. 승인 절차를 따로 개발한 것이 아니라 **Git이 이미 하는 일을 화면으로 보여주는 것**입니다.

| 허브 화면 | Git |
| --- | --- |
| 수정 제안 제출 (대기 중) | 브랜치 생성 + 커밋 + Pull Request 열기 |
| 제출 확인 창의 바뀐 곳 | Pull Request diff |
| 관리자 승인 (머지됨) | PR 머지 |
| 반려 (닫힘) | 머지하지 않고 PR 닫기 · 사유는 PR 의견 |
| 위키 반영 | main 머지 뒤 다음 배포 |
| 수정 이력 | `git log` · `git blame` |

## 편집 경로 두 가지

### ① 웹앱 UI — 일반 담당자

문서 화면에서 고치고 제출하면 뒤에서 브랜치·커밋·PR이 자동으로 만들어집니다. Git을 몰라도 됩니다. 문서 한두 건을 고칠 때 씁니다.

### ② Claude Code CLI — 파워 유저

저장소를 로컬에 두고 자연어로 문서를 수정하거나 PR을 만듭니다. 단건 수정보다 **일괄 작업**에서 가치가 큽니다.

- "모든 PPM 문서의 UI 버전 표기를 5.4.1 기준으로 갱신해줘"
- "용어 사전에 없는 약어를 본문에서 찾아 항목으로 추가해줘"

## 시트를 정식 문서로 승격하기

개인이 관리하던 편성·마케팅 시트에 쌓인 기준도 지식 자산입니다.

1. **편성/스케줄** 첫 화면의 `+ 등록`으로 시트를 등록합니다.
2. 시트 상세에서 `↑ 정식 지식 문서로 승격 요청`을 누릅니다.
3. 관리자가 카테고리를 지정해 승인합니다. 지금은 승격 표시만 되고 **위키 문서는 아직 만들어지지 않습니다** (저장소 반영 준비 중).

담당자가 바뀌어도 노하우가 남게 하는 것이 목적입니다.
