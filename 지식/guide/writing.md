## 이 문서는

문서를 새로 넣거나 옮길 때의 형식 규약입니다. 형식을 못 맞춰도 본문만 주면 정리해 드립니다.

## 파일 하나 = 문서 하나

지식 문서는 저장소의 `지식/` 폴더에 마크다운 파일로 둡니다. **폴더가 곧 1단 메뉴**입니다.

| 폴더 | 1단 메뉴 | 문서 코드 접두 |
| --- | --- | --- |
| `지식/programming/` | 편성 | 아직 미확정 (문서 없음) |
| `지식/promotion/` | 프로모션 | `PPC-P-*` · `PPC-R-*` · `PPC-ACS`/`PPC-CBS`/`PPC-SWG` · `MKI-*` |
| `지식/guide/` | 이용 안내 | `HUB-*` |

> 예전에는 `지식/insight/`(마케팅 인사이트)와 `지식/system/`(시스템 매뉴얼)이 따로 있었으나, 지금은 둘 다 `지식/promotion/` 아래 서브메뉴로 합쳐졌습니다. **폴더는 1단 메뉴만 가른다**는 원칙은 유지하고, 2단 메뉴(서브메뉴)는 프론트매터의 `subcategory` 값으로 정합니다.

파일명은 영문 소문자 + 하이픈으로 짓습니다. (`ppm.md`, `ui-versions.md`)

## 프론트매터

파일 맨 위에 `---`로 감싼 메타 정보를 둡니다.

```yaml
---
title: PPM(월정액) 프로모션 정책
code: PPC-P-02
category: promotion
subcategory: policy
version: 1
updatedBy: 홍*동
updatedAt: 2026-09-14
ownerId: ppc-team
scope: PPM
systems: [CBS, ACS]
parent: null
order: 20
status: 정리완료
source: "원문 위치"
---
```

| 항목 | 설명 |
| --- | --- |
| `title` | 사이드바·문서 상단에 보이는 제목 |
| `code` | 문서 식별자. 챗봇이 근거를 표시할 때, 문서끼리 링크할 때 쓴다 |
| `category` | `programming` / `promotion` / `guide` — 어느 1단 메뉴에 들어갈지 |
| `subcategory` | 2단 메뉴. **프로모션**은 `start`(시작하기) · `policy`(정책) · `process`(업무 프로세스) · `system`(시스템 매뉴얼) · `spec`(규격·제약) · `reference`(참조) 중 하나. **편성**은 `movie-series`·`tv`·`animation`·`kids`·`free` 중 하나. 서브메뉴가 없는 카테고리(이용 안내)는 비워 둔다 |
| `scope` | `PPM 전용` / `PPV 전용` / `공통` — 챗봇이 상품 유형으로 근거를 거를 때 쓴다 |
| `systems` | 관련 시스템 (`[CBS, ACS]`) |
| `order` | 서브메뉴 안에서의 정렬 순서 (작을수록 위) |
| `status` | 아래 상태 표기 참고 |
| `source` | 원문이 어디에 있었는지 |

## 상태 표기

| 표기 | 의미 |
| --- | --- |
| **정리완료** | 원문 내용을 옮기고 구조화함 |
| **초안** | 원문에 일부만 있어 보완이 필요함. 본문에 `확인 필요`로 표시 |
| **빈 페이지** | 항목만 있고 본문이 없어 자리만 만들어 둠 |

보완이 필요한 부분은 숨기지 말고 본문에 *(확인 필요: ...)* 로 남깁니다. 무엇이 비었는지 보이는 편이 낫습니다.

## 문서 톤앤매너

- 첫 H2는 **"이 문서는"** — 이 문서가 무엇을 다루는지, 누가 왜 읽는지 한두 문장으로 엽니다.
- **WHY를 먼저 설명합니다.** "무엇을 해라"만 있으면 예외 상황에서 응용을 못 합니다. "왜 이렇게 정해졌나"를 짧게 붙이면, 표에 없는 상황도 스스로 판단할 수 있습니다.
- 여러 챕터가 합쳐진 긴 문서는 본문 앞에 **"이 문서 안의 챕터"** 표로 지도를 먼저 보여줍니다.
- 표·체크리스트로 이미 스캔하기 좋은 내용(용어 사전, FAQ, 규격표)은 굳이 문장으로 풀어쓰지 않습니다. 표는 그대로 두고, 여는 문단과 맺는 문단만 다듬습니다.
- 문서 끝에는 **"다음에 볼 문서"** 표를 둡니다. 읽고 나서 어디로 가야 할지 알려줍니다.
- 해요체(``~합니다``)로 씁니다. 원문(Confluence 등)이 개조식이어도 옮길 때 풀어씁니다.

## 문서끼리 링크하기

링크 주소에 **문서 코드**를 적습니다. 파일 경로가 아닙니다.

```markdown
[담당자·결재 라인](PPC-R-02)
```

**다른 문서의 특정 소제목**을 가리키려면 문서 코드 뒤에 `#h-소제목`을 붙입니다. `h-` 뒤에는 대상 문서의 소제목(H2/H3) 텍스트를 그대로 넣되, 공백만 하이픈(`-`)으로 바꿉니다. 문장부호는 그대로 둡니다.

```markdown
[다크패턴 대응](PPC-P-02#h-다크패턴-대응-및-정가-전환동의)
```

이렇게 걸면 클릭했을 때 그 문서 맨 위가 아니라 **그 소제목이 시작하는 위치로 바로 스크롤**됩니다. 대상 소제목의 정확한 글자를 모르겠으면 그 문서를 열어 확인하세요 — 철자가 하나라도 다르면 그냥 문서 맨 위로 이동합니다(에러는 아닙니다).

같은 문서 안의 다른 섹션을 가리킬 때는 링크 대신 **굵은 글씨**로 섹션 이름을 적습니다.

## 본문 작성

- 표, 목록, 인용(`>`), 코드블록 모두 그대로 렌더링됩니다.
- 소제목은 `##`과 `###`만 씁니다. 이 두 단계가 문서 우측 목차에 잡힙니다.
- 문서가 길어도 괜찮습니다. 관련 내용이 한 페이지에 모여 있는 편이 여러 페이지로 쪼개진 것보다 읽기 쉽습니다.
- 숫자 범위는 물결표(`1~3개`)를 그대로 씁니다. 취소선으로 잘못 읽히지 않도록 렌더러에서 처리해 둡니다.

## 컨플루언스에서 옮기는 법

1. 문서 → `...` → **Export** → Markdown으로 내보내기
2. 내보낸 파일을 해당 폴더에 넣기 — 마크다운 정리는 이쪽에서 처리합니다
3. 마크다운 내보내기가 막혀 있으면 페이지 본문을 복사해 `.md`로 저장해도 됩니다

## 사내 정보 주의

**저장소에 넣기 전에 외부 반출이 가능한 범위인지 확인합니다.**

아래 항목은 그대로 넣지 않습니다.

- 임직원 **실명**·연락처·이메일 → `홍*동`처럼 가립니다
- **부서명** → `미디어**팀`처럼 가립니다
- 사내 시스템 **URL**·조직 코드 → `(사내 Confluence 원문 · URL 생략)`처럼 대체합니다
- 제휴사명이 드러나는 **실제 캠페인명**

> 판단이 애매하면 가리는 쪽을 택합니다. 한번 공개된 내용은 되돌리기 어렵습니다.
> 이미 가려진 표기(`구*화`, `미디어**팀장`처럼 일부만 보이는 이름)를 마주치면, **그럴듯한 이름으로 채워 넣지 않습니다.** 가려진 그대로 옮깁니다 — 추측해서 채우면 사실이 아닌 내용을 문서에 남기게 됩니다.
