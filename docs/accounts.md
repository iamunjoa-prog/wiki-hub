# 담당자 계정 설정

사내 메일 계정은 클라우드 PC에서만 쓸 수 있습니다. 그래서 일반 PC에서 쓰는 허브는 **허브 전용 계정**을 따로 둡니다.

- **계정 발급**: 관리자가 "계정 관리" 화면에서 아이디·이름·팀·권한을 넣으면 임시 비밀번호가 나옵니다.
- **여러 명 발급**: "여러 명 한 번에 발급"에 엑셀 명단(아이디 · 이름 · 팀 · 권한 열)을 붙여넣으면 한 번에 만들어집니다. 결과의 임시 비밀번호는 엑셀용으로 복사하거나 CSV로 내려받을 수 있습니다.
- **첫 로그인**: 담당자는 아이디와 임시 비밀번호로 로그인한 뒤, 바로 새 비밀번호로 바꿔야 허브가 열립니다.
- **비밀번호 분실**: 관리자가 "비밀번호 초기화"를 누르면 새 임시 비밀번호가 나옵니다.
- **퇴사·이동**: "사용 중지"를 누르면 그 계정은 바로 로그아웃되고 다시 로그인할 수 없습니다.
- **권한**: 실무자/관리자는 계정 관리에서 바꿉니다. 관리자만 "승인 관리"와 "계정 관리"에 들어갑니다.
- **작성자 기록**: "+ 새 문서" PR 같은 작성자 기록에는 로그인한 계정의 이름이 남습니다.

비밀번호는 원문을 저장하지 않고 해시로만 저장합니다. 같은 아이디로 5번 틀리면 10분 동안 로그인이 막힙니다.

## 처음 한 번 하는 설정 (Vercel)

### 1. 계정 저장소 연결

Vercel 프로젝트 → **Storage** → **Create Database** (또는 Marketplace) → **Upstash for Redis** → 무료 플랜으로 만들고 이 프로젝트에 연결합니다.
연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 환경변수에 자동으로 들어갑니다.

### 2. 환경변수 추가

Vercel 프로젝트 → Settings → **Environment Variables**에 아래 세 값을 넣습니다.

| 이름 | 값 |
|---|---|
| `HUB_AUTH_SECRET` | 아무도 모르는 32자 이상 임의 문자열. 로그인 세션 서명용이며, 바꾸면 모두 로그아웃됩니다 |
| `HUB_ADMIN_ID` | 첫 관리자 아이디 (예: `admin`) |
| `HUB_ADMIN_PASSWORD` | 첫 관리자 임시 비밀번호 |

### 3. 다시 배포

Deployments → 최신 배포 → **Redeploy**.

### 4. 첫 관리자 로그인

`HUB_ADMIN_ID` / `HUB_ADMIN_PASSWORD`로 로그인하면 관리자 계정("허브 관리자")이 만들어집니다. 곧바로 비밀번호를 바꾸라는 화면이 나옵니다.
이 방법은 계정이 하나도 없을 때만 동작하므로, 첫 관리자를 만든 뒤에는 `HUB_ADMIN_PASSWORD`를 지워도 됩니다.

그다음 계정 관리에서 내 실명 계정을 **관리자** 권한으로 발급해 쓰세요. 실명 계정으로 로그인한 뒤에는 첫 관리자 계정을 "사용 중지"해도 됩니다.

## 알아 둘 점

- `HUB_AUTH_SECRET`과 계정 저장소 중 하나라도 없으면 로그인 없이 데모 계정(김OO)으로 동작합니다.
- 로컬 허브(`start-hub.bat`)는 내 PC에서만 열리므로 로그인 없이 데모 계정으로 동작합니다.

## 요청·승인 기록

계정 기능이 켜진 배포에서는 요청과 승인 기록이 계정과 같은 저장소(Upstash Redis)에 쌓입니다. 담당자 모두가 같은 기록을 보고, 새로고침해도 사라지지 않습니다.

- **저장되는 것**: 문서 수정 제안, 편성표 등록·승격 요청, 시스템 등록·접속 주소 요청, 그리고 각각의 승인·반려 결과
- **요청자**: 화면이 보낸 이름이 아니라 로그인한 계정 이름으로 남습니다.
- **승인 권한**: 서버가 관리자인지 확인합니다.
- **git 반영**: 승인한 문서 수정과 편성표 승격 문서는 `지식/` 폴더에 바로 커밋됩니다(main). 커밋되면 Vercel이 다시 배포해, git과 위키 화면이 같아집니다.
  - Vercel에 `GITHUB_TOKEN`이 있어야 합니다. 권한은 이 저장소로 제한하고 Contents: Read/Write, Pull requests: Read/Write를 줍니다.
  - 토큰이 없으면 승인은 되지만 git에는 반영되지 않고 허브 화면에만 보입니다. 승인할 때 그 사실이 함께 표시됩니다.
  - 커밋이 실패하면(main 보호 규칙 등) 승인도 하지 않고 이유를 보여 줍니다.
- 로컬 허브(`start-hub.bat`)는 이 저장소를 쓰지 않습니다. 시스템 목록은 팀 공유 파일, 나머지는 메모리에서 동작합니다.
