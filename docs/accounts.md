# 담당자 계정 설정

사내 메일 계정은 클라우드 PC에서만 쓸 수 있습니다. 그래서 일반 PC에서 쓰는 허브는 **허브 전용 계정**을 따로 둡니다.

- **계정 발급**: 관리자가 "계정 관리" 화면에서 아이디·이름·팀·권한을 넣으면 임시 비밀번호가 나옵니다.
- **여러 명 발급**: "여러 명 한 번에 발급"에 엑셀 명단(아이디 · 이름 · 팀 · 권한 열)을 붙여넣으면 한 번에 만들어집니다. 결과의 임시 비밀번호는 엑셀용으로 복사하거나 CSV로 내려받을 수 있습니다.
- **첫 로그인**: 담당자는 아이디와 임시 비밀번호로 로그인한 뒤, 바로 새 비밀번호로 바꿔야 허브가 열립니다.
- **비밀번호 분실**: 관리자가 "비밀번호 초기화"를 누르면 새 임시 비밀번호가 나옵니다.
- **퇴사·이동**: "사용 중지"를 누르면 그 계정은 바로 로그아웃되고 다시 로그인할 수 없습니다.
- **권한**: 실무자/관리자는 계정 관리에서 바꿉니다. 관리자만 "승인 관리"와 "계정 관리"에 들어갑니다.
- **작성자 기록**: "+ 새 문서" PR 같은 작성자 기록에는 로그인한 계정의 이름이 남습니다.

비밀번호는 원문을 저장하지 않고 해시로만 저장합니다. 같은 아이디로 5번 틀리면 10분 동안 로그인이 막힙니다.

## 처음 한 번 하는 설정 (Vercel)

### 1. 계정 저장소 연결

Vercel 프로젝트 → **Storage** → **Create Database** (또는 Marketplace) → **Upstash for Redis** → 무료 플랜으로 만들고 이 프로젝트에 연결합니다.
연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`이 환경변수에 자동으로 들어갑니다.

### 2. 환경변수 추가

Vercel 프로젝트 → Settings → **Environment Variables**에 아래 세 값을 넣습니다.

| 이름 | 값 |
|---|---|
| `HUB_AUTH_SECRET` | 아무도 모르는 32자 이상 임의 문자열. 로그인 세션 서명용이며, 바꾸면 모두 로그아웃됩니다 |
| `HUB_ADMIN_ID` | 첫 관리자 아이디 (예: `admin`) |
| `HUB_ADMIN_PASSWORD` | 첫 관리자 임시 비밀번호 |

### 3. 다시 배포

Deployments → 최신 배포 → **Redeploy**.

### 4. 첫 관리자 로그인

`HUB_ADMIN_ID` / `HUB_ADMIN_PASSWORD`로 로그인하면 관리자 계정("허브 관리자")이 만들어집니다. 곧바로 비밀번호를 바꾸라는 화면이 나옵니다.
이 방법은 계정이 하나도 없을 때만 동작하므로, 첫 관리자를 만든 뒤에는 `HUB_ADMIN_PASSWORD`를 지워도 됩니다.

그다음 계정 관리에서 내 실명 계정을 **관리자** 권한으로 발급해 쓰세요. 실명 계정으로 로그인한 뒤에는 첫 관리자 계정을 "사용 중지"해도 됩니다.

## 알아 둘 점

- `HUB_AUTH_SECRET`과 계정 저장소 중 하나라도 없으면 로컬과 Preview에서는 로그인 없이 데모 계정(김OO)으로 동작합니다. 운영(Production) 배포에서는 보안을 위해 챗봇·AI 수정·새 문서·수정 제안·내려받기가 "허브 점검 중"으로 닫히고, 원인은 Vercel 함수 로그의 `[guard]` 줄에 남습니다.
- 로컬 허브(내려받은 ZIP의 `start-hub-windows` / Mac은 `start-hub-mac.command`)는 내 PC에서만 열리므로 로그인 없이 데모 계정으로 동작합니다.
- 수정 제안·승인·시스템 요청 기록은 아직 브라우저 메모리에만 있습니다. 누가 요청했는지는 이제 구분되지만, 이 기록을 담당자끼리 함께 보려면 같은 저장소로 옮기는 작업이 이어서 필요합니다.

## 챗봇 대화 기록 보관

챗봇이 답을 잘 못한 질문을 찾아 위키와 대화 규약을 고치려고, 배포 허브(웹 주소)의 챗봇 대화를 계정 저장소(위 1절의 Upstash Redis)에 함께 남깁니다. 설계 기준은 `docs/plan/2026-11-20-chat-history-log.md` 입니다.

### 무엇을 저장하나

- 질문 1번에 엔진이 답을 시도할 때마다 기록 1건이 남습니다. 엔진을 넘겨 가며 다시 시도했으면 같은 질문 아래 여러 건이 묶입니다.
- 남는 것: 질문 원문, 답 앞부분(1,500자까지), 근거로 든 위키 문서, 쓴 엔진, 성공·실패·취소, 걸린 시간, 물은 계정의 **아이디**.
- 리포트는 제목·3줄 요약·근거 문서·외부 출처·빈칸 목록만 남고 **본문은 남지 않습니다.**
- 남기지 않는 것: 이름·팀(볼 때 계정 목록에서 붙입니다), 오류 원문 메시지, 앞 대화 전체, 로그인하지 않은 대화, 계정 기능이 꺼진 데모 배포의 대화.
- 질문에 쓴 말은 가리지 않고 그대로 남습니다. 개인 연락처 같은 내용은 챗봇에 넣지 마세요.

### 얼마나 두나

- **90일** 뒤 저절로 지워집니다. 보관 일수는 Vercel 환경변수 `HUB_CHATLOG_DAYS`(기본 90)로 바꿀 수 있고, 바꿔도 이미 저장된 기록의 만료일은 그대로입니다.
- **하루 500건**까지 내용을 남깁니다(`HUB_CHATLOG_DAILY_CAP`, 기본 500). 넘은 뒤의 질문은 내용 없이 건수만 셉니다. 같은 저장소를 쓰는 로그인 기능이 무료 한도에 걸리지 않게 하려는 장치이며, 챗봇 답에는 영향이 없습니다.

### 누가 보나

- **관리자**: 관리자 메뉴 "대화 기록"에서 모든 기록을 봅니다.
- **본인**: "내 대화 기록"에서 자기 기록만 봅니다. 다른 사람의 기록은 보이지 않습니다.
- 내보내기(CSV·엑셀)·전체 복사·공유 링크는 없습니다. 기록은 GitHub 에 올라가지 않습니다.
- 기록에서 찾은 문제를 위키·문서·PR 로 옮길 때는 질문 원문을 붙이지 않고 경향으로만 씁니다(공개 저장소).

### 지우고 싶으면

- 실무자가 직접 지우는 버튼은 없습니다. 잘못 넣은 내용이 있으면 **관리자에게 말해** 주세요. 관리자는 "대화 기록"에서 질문 하나씩 지울 수 있습니다(엔진을 넘겨 다시 시도한 기록까지 함께 지워집니다).

### 실무자 PC에는 Redis 를 넣지 않습니다

- 로컬 허브(내려받은 ZIP으로 켜는 내 PC용 허브)에서 나눈 대화는 저장되지 않습니다. 실무자 PC에는 저장소 설정이 없기 때문입니다.
- `KV_REST_API_URL`·`KV_REST_API_TOKEN` 은 **Vercel 환경변수에만** 둡니다. 실무자 PC의 `.env.local`·설치 스크립트·허브 ZIP·메신저·메일로 나눠 주지 않습니다. 토큰 하나로 모든 계정과 대화 기록을 읽고 지울 수 있습니다.
- 예외는 관리자 PC 하나입니다. 관리자 PC의 `.env.local` 에 넣으면 그 PC의 대화만 `local:<PC 이름>` 아이디로 남습니다.
- 사용량 점검(한 달에 한 번)과 무료 한도를 넘었을 때 생기는 일은 `docs/ops/chat-history-ops.md` 에 있습니다.
