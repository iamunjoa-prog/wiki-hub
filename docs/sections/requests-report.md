| # | 결정 |
| --- | --- |
| D1 | 리포트의 기본 용도는 **개인 보고 문서**(.md 저장·복사)다. 사용자가 리포트 직후 "위키에 반영해 줘"라고 하거나 카드의 반영 버튼을 누를 때만 "+ 새 문서" 화면을 리포트 본문으로 미리 채워 연다. 제출 뒤는 기존과 같다: PR 열림 → 관리자 승인(머지) → 다음 배포 때 반영 |

| D4 (Q5) | 위키 반영본은 **수치 대신 경향**으로 쓴다. `[외부]` 출처는 반영본에도 남긴다 |

## 1. 지금 실제로 일어나는 일 (문구의 근거)

| 순간 | 실제 동작 | 근거 |
| --- | --- | --- |
| 리포트가 대화에 뜰 때 | 아무것도 저장되지 않는다. 리포트는 이 브라우저의 대화 기록에만 있다. `.md로 저장` 도 브라우저 다운로드일 뿐이다 | 기획안 "화면 — 리포트 카드" |
| "+ 새 문서" 화면 열기 | `/wiki/new`. 지금은 카테고리·서브메뉴를 주소(`?category=&sub=`)로만 받는다. **본문·제목을 넘겨받는 길이 없다** | `src/pages/NewDoc.tsx` |
| 새 문서 화면에서 [PR로 제출] | `requestNewDoc` → `/api/createDoc` → `parseCreateDocInput` → `createDocPR`: 코드 자동 부여 → 서버가 **프론트매터를 직접 붙인다**(`buildMarkdown`) → 브랜치 `docs/{코드}-…` → 파일 1개 커밋 → PR 열림 | `src/lib/createDoc.ts`, `server/github.ts:199-236` |
| PR 제목·커밋 메시지 | 제목이 그대로 들어간다: `새 문서: {제목} ({코드})`, `docs: {코드} {제목} 추가` | `server/github.ts:222`, `:226` |
| PR 이 열린 순간 | **공개 저장소에 바로 올라간다.** 반려(닫힘)돼도 브랜치·PR diff 는 남는다 | 공개 저장소 |
| 공개 규칙 검사 | 새 문서 경로에는 **아무 검사도 없다.** `maskLeaks` 는 수정 제안 화면만 쓰고, 금액·제휴사 이름 검사는 어디에도 없다 | `src/lib/docEdit.ts:52`, `NewDoc.tsx` |
| 입력 오류 응답 | 로컬·배포 모두 `createDoc` 의 입력 오류를 **502** 로 돌려준다(400 아님) | `server/cliBridge.ts:742`, `api/createDoc.ts:33` |
| 로컬 허브의 새 문서 제출 | 로그인·하루 건수 제한이 없다. 출처·크기만 본다 | `server/cliBridge.ts:387` `readGuardedBody` |
| 배포본의 새 문서 제출 | 로그인·호출 횟수(`RATE_PR`)·크기를 본다. 작성자는 로그인 계정 이름으로 바꿔 남긴다 | `api/createDoc.ts:18-28` |
| 완료 화면 | `「{코드} 문서로 PR을 만들었습니다. 팀장이 확인하고 머지하면 다음 배포에서 위키에 반영됩니다.」` — 수정 제안 화면은 "관리자"라고 쓴다(11-13 R6) | `NewDoc.tsx:69` |
| "위키에 반영해 줘" 입력 | `detectKnowledgeEdit` 가 "위키"+"반영"을 수정 요청(`fix`)으로 잡아 수정 제안 화면 안내로 빠진다 | `src/lib/assistant.ts:282-292` |

그래서 반영 흐름의 어떤 문구도 "반영했습니다"·"올렸습니다"를 **새 문서 화면으로 넘어가는 순간에** 쓰지 않는다. 새 문서 화면을 여는 것은 아직 아무 데도 올리지 않은 상태다. "제안을 올렸습니다"는 PR 이 열린 뒤에만 쓴다.

## 2. 상태 이름 — 한 가지로 쓴다

11-13 문구 문서 2절의 상태 이름에 리포트 쪽 두 단계(개인 문서, 반영 준비)만 앞에 붙인다. 내 요청 태그 이름은 바꾸지 않는다.

| 단계 | 저장소에서 | 내 요청 태그 | 카드·안내에서 부르는 말 |
| --- | --- | --- | --- |
| 개인 문서 | 없음 (브라우저 대화 기록·내려받은 파일) | 안 뜸 | 리포트 (개인 보고 문서) |
| 공개 검사 | 없음 | 안 뜸 | 공개해도 되는지 검사하는 중 |
| 반영 준비 | 없음 (새 문서 화면에 채워진 상태) | 안 뜸 | 새 문서 화면에서 확인 중 · 아직 제출 전 |
| 제출 | PR 열림 | `대기 중` | 제안을 올렸습니다 · 대기 중 |
| 머지 | main 에 들어감 | `머지됨` | 승인(머지)됨 · 다음 배포 때 위키에 반영 |
| 다음 배포 반영 | 배포됨 | (`머지됨` 그대로) | 위키에 반영됨 |
| 반려 | PR 닫힘(머지 없이) | `닫힘` | 반려(닫힘) |

규칙
- "반영"이라는 말은 **"위키에 반영 요청"(버튼·사용자 발화)** 과 **"다음 배포 때 위키에 반영"(머지 뒤)** 에만 쓴다. 검사·새 문서 화면 단계에서 "반영 중"·"반영했습니다"를 쓰지 않는다.
- 대화 본문에서 리포트의 진행 상태를 말할 때도 이 이름을 쓴다 (chatbot-planner 와 맞출 것, 12절).

## 4. 흐름 경로

### 4-1. 지금 (리포트 기능이 들어가도 반영 흐름이 없을 때)

```
리포트 카드 [복사] → 위키 목록 → [+ 새 문서] → 카테고리·서브메뉴·제목 입력
→ 본문 붙여넣기 → (엔진 이름·검색어·프론트매터를 손으로 지움) → [PR로 제출]
→ /api/createDoc → createDocPR → PR 열림          ← 공개 검사 없음
```

### 4-2. 바꾼 뒤

```
[리포트 카드]
  │ (가) [위키에 반영 요청] 누름
  │ (나) 리포트 직후 "위키에 반영해 줘" 입력 (5절 판별 — /api/ask 를 부르지 않음)
  ▼
반영본 만들기 (6절, 브라우저 안에서 — 서버 호출 없음)
  ▼
공개 검사  /api/publicCheck {title, body, via:'report'}  → publicLeaks (7절)
  │ 차단 0 ─────────────────────────────▶ 새 문서 화면 열기 (/wiki/new, 미리 채움)
  │ 차단 ≥1 ─▶ 카드 안 [막힘] 상자 (8-2)            │ 경고는 새 문서 화면 노란 상자로
  │           [새 문서 화면에서 고치기] ─────────────▶│ (제출 버튼은 차단이 풀릴 때까지 꺼짐)
  │ 목록 없음 ─▶ 카드 안 [멈춤] 상자 (8-2) — 진행 안 함
  ▼
새 문서 화면 [다시 검사] / [PR로 제출]
  → requestNewDoc → /api/createDoc {…, via:'report', reason}
  → parseCreateDocInput → publicLeaks(서버, 한 번 더) → 차단이면 400 public-leak
  → createDocPR → PR 열림 → 완료 화면 → refreshProposals → [내 요청에서 보기]
```

- 새 문서 화면으로 본문을 넘기는 길: `navigate('/wiki/new', { state })` 와 함께 **sessionStorage**(키 예: `wiki-hub:newdoc-prefill`)에 한 번 더 둔다. 새로고침해도 남게 하되, 제출 성공·[취소] 때 지운다. localStorage 는 쓰지 않는다(공용 PC에 남는다). 주소창(쿼리)에는 본문을 싣지 않는다.
- 미리 채운 값에는 `fromMessageId`(리포트 메시지 id)를 같이 둔다. 제출이 성공하면 그 리포트 카드에 결과 한 줄을 남긴다(8-1 마지막 행).
- 11-13 대화 초안 카드가 나중에 들어와도 같은 미리 채우기 통로(state + sessionStorage, 필드 이름 동일)를 쓴다 — 합칠 자리. 초안 카드의 [편집 화면에서 열기](11-13 6절)와 필드 구성이 같다: 카테고리·서브메뉴·제목·적용 상품·본문·사유·진입(`via`).

## 5. "위키에 반영해 줘" 발화 처리 (D2)

판별은 **화면이 먼저** 한다(`src/lib/assistant.ts`). 대화 기록은 화면에 있고, 반영 요청은 엔진이 할 일이 없기 때문이다. 판별되면 `/api/ask` 를 부르지 않는다 — 기다림 0.

### 5-1. 반영 요청으로 받는 조건 (모두 만족)

| # | 조건 |
| --- | --- |
| 1 | 대화의 **가장 최근 어시스턴트 메시지가 리포트**(`mode:'report'`)다. `report-unavailable` 안내는 리포트가 아니다 |
| 2 | 발화에 반영 동사가 있다: `반영` · `올려` · `올리` · `등록` · `넣어` · `추가해` · `문서로 만들` (대상 명사 `위키`·`문서`·`허브` 는 없어도 된다 — "이거 반영해 줘"도 받는다) |
| 3 | 부정이 아니다: `하지 마` · `안 해` · `말고` · `안 해도` · `취소` 가 없다 |

1을 만족하지 않으면(리포트 뒤에 다른 질문을 한 번이라도 했으면) 지금처럼 `detectKnowledgeEdit` 로 간다. 이때도 리포트 카드의 [위키에 반영 요청] 버튼은 그대로 쓸 수 있다.

### 5-2. 받은 뒤 어떻게 답하나

| 발화 모양 | 예 | 처리 | 대화 본문 (그대로) |
| --- | --- | --- | --- |
| 바로 해 달라 | "위키에 반영해 줘", "이거 올려 줘" | 버튼과 같은 흐름 시작 | 「방금 리포트 「{리포트 제목}」을 위키 새 문서로 올릴 준비를 합니다. 먼저 공개해도 되는 내용인지 검사합니다.」 |
| 방법을 묻는다 | "위키에 반영하려면 어떻게 해?" | 시작하지 않음 | 「리포트 카드의 [위키에 반영 요청]을 누르면 새 문서 화면이 리포트 내용으로 채워져 열립니다. 제출하면 관리자가 승인(머지)한 뒤 다음 배포 때 위키에 보입니다.」 |
| 고칠 점이 함께 있다 | "금액 빼고 위키에 반영해 줘", "3번은 지우고 올려 줘" | 흐름 시작 + 한 줄 덧붙임 | 위 "바로 해 달라" 문장 + 「말씀하신 고칠 점은 새 문서 화면에서 직접 고쳐 주세요. 리포트 내용을 자동으로 바꾸지는 않습니다.」 |
| 기존 문서를 짚는다 | "PPV 정책 문서에 반영해 줘" | 흐름 시작 + 한 줄 덧붙임 | 위 "바로 해 달라" 문장 + 「리포트는 새 문서로만 올라갑니다. 기존 문서를 고치려면 그 문서의 [✎ 수정 제안]을 써 주세요.」 |

- "고칠 점이 함께 있다"·"기존 문서를 짚는다"를 나누는 정확한 신호(바꿔·빼고·지우고 / 문서 코드·문서 제목 일치)는 dev-front 가 정하고 판별 예시 표로 보고한다.
- 리포트를 **고쳐서 다시 만들어 달라**는 요청(반영 동사 없이 "금액 빼고 다시 정리해줘")은 반영 요청이 아니다. 리포트 재요청 규약은 chatbot-planner 소관이다.

### 5-3. 회귀 확인

- 리포트가 없는 대화에서 "판촉 쿠폰 결재선 문서 고쳐줘", "위키에 반영해 줘"는 지금과 똑같이 수정 제안 안내로 간다.
- 리포트 직후라도 "결재선이 뭐야?"는 반영 요청이 아니다(반영 동사 없음).

## 6. 반영본 만들기 (개인 리포트 → 위키 문서 본문)

브라우저 안에서 규칙대로 바꾼다(엔진을 다시 부르지 않는다 — 기다림 0). 바꾼 결과를 사용자가 새 문서 화면에서 보고 고친다.

### 6-1. 무엇을 빼고 무엇을 남기나

| 리포트의 부분 | 반영본 | 이유 |
| --- | --- | --- |
| `.md로 저장` 의 YAML 프론트매터 | **뺀다.** 리포트 `markdown` 을 쓰고, 본문 맨 앞의 `---` 블록이 있으면 지운다 | 서버 `buildMarkdown` 이 프론트매터를 붙인다. 두 겹이 된다 |
| 맨 위 `# 제목` (H1) | 본문에서 빼고 **제목 칸**으로 옮긴다(80자 넘으면 80자에서 자름) | 문서 제목은 프론트매터 `title` 이다. 소제목은 `##`·`###` 만 쓴다(`지식/guide/writing.md`) |
| 머리 인용줄 `> 작성일 · 엔진 · 근거 범위` | 빼고 아래 "이 문서는" 문단으로 바꾼다. **엔진 이름은 넣지 않는다** | 11-13 8-3 (엔진 이름은 PR·문서에 안 남김) |
| `####` 이하 소제목 | 굵은 줄(`**…**`)로 바꾼다 | 우측 목차는 `##`·`###` 만 잡는다 |
| 결론 문장 끝의 `[위키]`·`[외부]`·`[추정]` | **그대로 남긴다** | 읽는 사람이 무엇이 정책이고 무엇이 판단인지 구분해야 한다 |
| 외부 출처 절 (제목·URL·확인일) | **남긴다** (D4) | `[외부]` 문장의 근거다 |
| 사용한 검색어 목록 | **뺀다** | 기획안 반영 흐름 3. 개인 리포트의 작업 기록이다 |
| 위키 근거(`sourcePaths`) | 본문 끝 `## 참고 문서` 표로 바꾼다: `| 문서 | 코드 |` · 링크는 문서 코드로 `[{제목}]({코드})` | 위키 링크는 경로가 아니라 문서 코드로 건다(`writing.md`) |
| 빈칸(`gaps`) · 한계 | **남긴다.** 절 이름은 `## 아직 채우지 못한 것` | 무엇이 비었는지 보이는 편이 낫다(`writing.md` 상태 표기) |
| 수치 (비율·건수·배수 등) | 자동으로 바꾸지 않는다. 검사 경고(7-2 W6)로 짚고 사용자가 경향으로 고친다 (D4) | 규칙으로 경향 문장을 지어내면 뜻이 바뀐다 |
| 금액 | 자동으로 바꾸지 않는다. 검사 **차단**(7-1 B1) | D3 |

### 6-2. 본문 맨 앞에 붙이는 문단 (그대로, 값만 채움)

```
## 이 문서는

{작성일}에 챗봇 리포트로 정리한 {유형 이름}입니다. 문장 끝 표시는 근거를 뜻합니다 — [위키] 위키 문서에 적힌 내용, [외부] 공개된 외부 자료, [추정] 위 둘을 바탕으로 한 판단입니다. [추정] 문장은 정해진 정책이 아닙니다.
```

| `reportType` | `{유형 이름}` |
| --- | --- |
| `compare` | 비교 자료 |
| `audit` | 점검 결과 |
| `insight` | 판단 자료 |
| `brief` | 업무 정리 |

리포트에 이미 `## 이 문서는` 절이 있으면 붙이지 않는다.

### 6-3. 새 문서 화면에 채우는 값

| 칸 | 채우는 값 | 사용자가 바꿀 수 있나 |
| --- | --- | --- |
| 카테고리 | `프로모션` | 된다 |
| 서브메뉴 | `compare`·`insight` → `마케팅 인사이트`, `audit`·`brief` → `운영 참고자료` | 된다. 칸 아래 회색: 「리포트 종류로 고른 추천 위치입니다. 맞는지 확인해 주세요.」 |
| 적용 상품 | 리포트 머리의 대상 상품이 `[PPV]` 면 `PPV(단건)`, `[PPM]` 이면 `PPM(월정액)`, 그 밖 `공통` | 된다 |
| 제목 | 리포트 제목 | 된다 |
| 본문 | 6-1·6-2 로 만든 반영본 | 된다 |
| 등록 사유 | 아래 기본값 | 된다. 비면 제출 꺼짐 (11-13 R4 의 칸이 생긴 뒤) |
| 진입(`via`) | `report` — 화면에 안 보임, PR 본문에 실림 | 안 됨 |

**등록 사유 기본값** (그대로, 값만 채움)

```
챗봇 리포트 「{리포트 제목}」을 위키 문서로 올립니다.
근거: 위키 문서 {n}건 · 외부 공개 자료 {n}건 · 판단([추정]) 문장 {n}개
```

- 등록 사유 칸이 아직 없으면(11-13 R4 미반영) 이 값은 보내지 않는다. 그래도 진입(`via:'report'`)은 보낸다.

## 7. 공개 규칙 검사 — 차단·경고 기준 (D3)

검사 함수는 하나(`publicLeaks`, 서버·화면 공용 규칙)이고 **새 문서로 들어가는 모든 길**(리포트 반영, 새 문서 화면 직접 작성, 11-13 대화 초안 카드의 새 문서)이 같은 기준을 쓴다. 검사 대상은 **제목·본문·등록 사유** 셋이다(제목은 PR 제목·커밋 메시지에, 사유는 PR 본문에 실린다).

### 7-1. 차단 (빨강 — 제출 못 함)

| # | 무엇 | 판정 | 적용 |
| --- | --- | --- | --- |
| B1 | 금액 표기 | 숫자(쉼표 포함) + `원`·`만 원`·`천 원`·`억`·`천만`·`백만`·`조`, 한글 수사(`십`·`백`·`천`·`만`·`억` 등) + `원`, 통화 기호·단위 + 숫자(`₩`·`$`·`KRW`·`USD`·`달러`). 띄어쓰기 차이는 무시 | 새 문서 전체 |
| B2 | 비공개 이름 목록 일치 | 공유 드라이브 목록 파일(`HUB_PRIVATE_TERMS_FILE`)의 항목과 일치. 대소문자·띄어쓰기 무시, 더 긴 낱말 안에 들어 있어도 일치로 본다. 가린 표기(`홍*동`)는 일치가 아니다 | 새 문서 전체 |
| B3 | 별표 2개로 가린 표기 | 기존 `maskLeaks` 의 별표 2개 규칙 (`미디어**팀` 꼴) | 새 문서 전체 |

- 차단은 화면과 서버가 **둘 다** 한다. 서버 검사는 `createDocPR` 이 GitHub 을 부르기 **전에** 돈다 — 막힌 제출은 브랜치도 만들지 않는다.
- 목록은 서버만 읽는다. 화면에 목록을 내려보내지 않는다. 화면은 `/api/publicCheck` 응답으로 걸린 위치·표기만 받는다(사용자가 쓴 글자이므로 보여 줘도 된다).
- 서버 로그에는 **걸린 표기를 남기지 않는다.** 종류별 건수만 남긴다(예: `publicCheck block amount=2 name=1`).

### 7-2. 경고 (노랑 — 제출은 됨)

| # | 무엇 | 판정 | 적용 |
| --- | --- | --- | --- |
| W1 | 회사 표기로 보임 | `주식회사`·`(주)`·`㈜`·`Inc`·`Corp`·`Co., Ltd` 등, 또는 `○○사` 꼴. 목록(B2)에 이미 걸린 것은 빼고 | 새 문서 전체 |
| W2 | 인터넷 주소 | `http(s)://…`. 단 리포트 반영본의 **외부 출처 절 URL은 경고하지 않는다**(공개 자료라서 남기기로 한 것, D4) | 새 문서 전체 |
| W3 | 이메일 | 이메일 꼴 | 새 문서 전체 |
| W4 | 전화번호 | 전화번호 꼴 | 새 문서 전체 |
| W5 | (보완 필요) | `(보완 필요)` 개수 | 새 문서 전체 |
| W6 | 수치 | 숫자 + `%`·`퍼센트`·`배`·`건`·`명`·`회`·`p`(포인트). 날짜·문서 코드·`1~3개` 같은 범위 표기는 뺀다 | **리포트 반영(`via:'report'`)만**. 새 문서 화면 직접 작성에는 걸지 않는다(규격 문서의 픽셀·글자 수 같은 정당한 수치가 많다) |

### 7-3. 목록 파일을 못 읽을 때

| 경로 | 처리 |
| --- | --- |
| 리포트 반영 | **멈춘다.** 새 문서 화면으로 넘어가지 않는다(8-2 "멈춤"). 확정 조건 3("마스킹 검사를 반드시 거친다")을 이름 검사 없이 지나가지 않기 위해서다 |
| 새 문서 화면 직접 작성 | B1·B3 와 경고만 검사하고 제출은 된다. 검사 상자에 회색 한 줄을 붙인다(8-4). 지금 있는 제출 흐름을 목록 파일 준비 전에 끊지 않기 위해서다 |
| 배포본 `/api/createDoc` | 공유 드라이브를 읽을 수 없다. 목록을 어떻게 줄지 정해야 한다(13절 R-B). 정해지기 전에는 위 "직접 작성"과 같다 |

### 7-4. 검사 응답 모양 (dev-server 계약 초안)

```
POST /api/publicCheck  { title, body, reason?, via? }
→ 200 { blocks: Hit[], warnings: Hit[], namesChecked: boolean }

POST /api/createDoc  (차단이 있으면)
→ 400 { error: '공개 저장소에 올릴 수 없는 표현이 있습니다', code: 'public-leak', blocks: Hit[] }

Hit = { kind: 'amount'|'name'|'doubleStar'|'company'|'url'|'email'|'phone'|'todo'|'figure',
        where: 'title'|'body'|'reason', line: number|null, text: string }
```

`text` 는 사용자가 보낸 글자 중 걸린 부분만이다. 목록의 다른 항목은 응답에 절대 싣지 않는다.

## 8. 화면 문구

### 8-1. 리포트 카드 — 반영 단계

| 상태 | 카드에 보이는 것 (그대로) | 버튼 |
| --- | --- | --- |
| 개인 문서 (기본) | 버튼 옆 회색: 「이 리포트는 내 대화에만 있습니다. 위키에 올리려면 [위키에 반영 요청]을 눌러 주세요.」 | `.md로 저장` · `복사` · `위키에 반영 요청` |
| 공개 검사 중 | 「공개해도 되는 내용인지 검사하는 중입니다. 몇 초 걸립니다.」 | 모두 꺼짐 |
| 통과 → 넘김 | 카드 아래 회색 한 줄: 「새 문서 화면으로 넘겼습니다 · 아직 제출 전입니다.」 | `새 문서 화면 다시 열기` |
| 막힘 | 8-2 빨강 상자 | `새 문서 화면에서 고치기` · `닫기` |
| 멈춤 (목록 없음) | 8-2 회색 상자 | `닫기` |
| 검사 실패 (네트워크·서버) | 「검사를 하지 못했습니다. 잠시 뒤 [위키에 반영 요청]을 다시 눌러 주세요. 계속되면 관리자에게 알려 주세요.」 | `위키에 반영 요청` |
| 제출 뒤 (새 문서 화면에서 성공) | 카드 아래 회색 한 줄: 「제안을 올렸습니다 · 대기 중 · {코드}」 | `내 요청에서 보기` |

- `위키에 반영 요청` 버튼 보조 설명(title): 「새 문서 화면을 이 리포트 내용으로 채워 엽니다. 제출하기 전에는 아무 데도 올라가지 않습니다.」
- 리포트 카드의 기존 경고(기획안 "공개되면 안 되는 표현이 있을 수 있습니다 — 위키 반영 전에 고쳐야 합니다")는 그대로 둔다. 리포트 자체는 개인 문서라 막지 않는다.

### 8-2. 카드 안 검사 결과 상자

**빨강 — 막힘**

| 칸 | 문구 |
| --- | --- |
| 제목 | `위키에 올릴 수 없는 표현이 있습니다` |
| 설명 | `위키는 누구나 볼 수 있는 공개 저장소에 올라갑니다. 아래 줄을 고쳐야 제출할 수 있습니다.` |
| 항목 | 8-5 의 차단 항목 문구 |
| 끝줄 | `[새 문서 화면에서 고치기]를 누르면 리포트 내용이 채워진 화면이 열립니다. 고친 뒤 [다시 검사]를 눌러 주세요.` |

**회색 — 멈춤 (목록 없음)**

| 칸 | 문구 |
| --- | --- |
| 제목 | `지금은 위키 반영을 할 수 없습니다` |
| 본문 | `공개하면 안 되는 이름을 확인하는 목록이 이 허브에 연결되어 있지 않습니다. 리포트는 [.md로 저장]이나 [복사]로 쓰실 수 있습니다. 위키 반영이 필요하면 관리자에게 알려 주세요.` |

### 8-3. 새 문서 화면 — 미리 채워 열렸을 때

| 위치 | 문구 |
| --- | --- |
| 화면 맨 위 (회색 한 줄) | `챗봇 리포트 「{리포트 제목}」 내용을 채웠습니다. 위치·제목을 확인하고, 고친 뒤 제출해 주세요.` |
| 본문 칸 위 (회색 한 줄) | `[위키]·[외부]·[추정] 표시는 지우지 말아 주세요. 읽는 사람이 무엇이 정해진 내용이고 무엇이 판단인지 구분하는 표시입니다.` |
| 서브메뉴 칸 아래 | 6-3 의 추천 위치 문구 |
| 제출 버튼 옆 (기존 hint 대신) | `제출하면 공개 저장소(GitHub)에 바로 올라갑니다. 반려돼도 기록은 지워지지 않습니다. 관리자가 승인(머지)하면 다음 배포 때 위키에 보입니다.` |
| 검사 버튼 | `다시 검사` — 누르면 `/api/publicCheck` 를 다시 부른다. 차단이 0 이 되면 제출 버튼이 켜진다 |

- 미리 채워 열린 화면에서 본문을 고치면 검사 결과 상자는 「고친 내용은 아직 검사하지 않았습니다. [다시 검사]를 눌러 주세요.」로 바뀌고, 차단이 있던 경우 제출 버튼은 [다시 검사] 전까지 꺼진 채로 둔다.
- 새 문서 화면을 직접 연 경우(미리 채움 없음)에는 위 맨 위·본문 칸 위 문구를 보이지 않는다. 검사·차단은 같다(D3).

### 8-4. 새 문서 화면 — 검사 상자

빨강 상자 제목: `제출할 수 없습니다 — 공개 저장소에 올릴 수 없는 표현이 있습니다`
노랑 상자 제목: `제출은 할 수 있지만 확인해 주세요` (11-13 5-3 과 같은 문장)
목록을 못 읽었을 때 상자 끝 회색 한 줄 (직접 작성만): `이 허브에서는 제휴사 이름을 자동으로 확인하지 못했습니다. 제휴사 이름이 들어가 있지 않은지 직접 확인해 주세요.`

### 8-5. 항목 문구

위치는 본문이면 `{n}번째 줄`, 제목이면 `제목`, 사유면 `등록 사유` 로 쓴다.

| # | 문구 (그대로) |
| --- | --- |
| B1 금액 | `{위치} 「{표기}」 — 금액입니다. 금액은 공개 저장소에 올릴 수 없습니다. "늘어나는 추세", "할인 폭이 큰 편"처럼 경향으로 바꿔 주세요.` |
| B2 비공개 이름 | `{위치} 「{표기}」 — 공개하면 안 되는 이름 목록에 있는 이름입니다. "제휴사"처럼 일반 표현으로 바꿔 주세요.` |
