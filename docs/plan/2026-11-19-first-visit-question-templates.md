## 2. 확인 방법

- **규칙 기반**: esbuild 로 `src/lib/assistant.ts` 와 `server/knowledge.ts` 의 `detectReportIntent` 를 묶어 node 에서 불렀다. `src/data/knowledgeDocs.ts` 의 `import.meta.glob(...)` 은 esbuild 플러그인으로 `지식/` 실제 파일 내용을 넣어 바꿨다(지시서 9절과 같은 방법). `askAssistant(q, [], …)` 로 규칙 기반 경로 전체(`answer` → `withNextStep` → `withRefine`)를 탔다.
- **AI 엔진 경로**: `fetch` 를 모의 응답(`{ mode: 'qa', text, sourcePaths: [] }`)으로 바꾸고 `askAssistant(q, ['gemini'], …)` 를 불렀다. 그래서 **화면 쪽이 엔진 답에 붙이는 것**(`requestEngine` 의 `intentPromptFor`, `withNextStep`, `withRefine`)은 실제 코드로 확인했다. 서버 쪽 리포트 판정은 `detectReportIntent` 를 직접 불러 `mode` 를 봤다.
- **확인하지 못한 것**: 실제 엔진(Claude·Codex·Gemini)이 쓰는 답 본문. 이 환경에 키·로그인이 없다. 표의 "엔진 답 유형"은 대화 규약상 그 발화가 어느 유형으로 가는지를 적은 것이다.
- 칩을 고른 뒤 동작(`resolveIntent`)은 `src/store/AppStore.tsx:528-652` 를 따라가 확인했다.

## 4. ② 템플릿 확정안

공통 규칙

- 값 글자 = 보내는 글자(wiki-ux 조건 4). 빈칸 뒤에는 받침에 따라 바뀌는 조사를 두지 않는다. 세 틀 모두 빈칸 뒤가 고정 명사(`프로모션`, `방식으로`, `기준`)다.
- 두 번째 빈칸은 모두 `dependsOn: 상품` 이다. 상품을 바꾸면 비운다(wiki-ux 2.3).
- 값은 모두 `지식/promotion/` 문서에 있는 이름에서 가져왔다. 금액·할인율·제휴사 이름은 값에 넣지 않았다(문서의 금액은 과거 사례이고, 공개 저장소 규칙).
- 값 글자 수: `지상파·종편·CP 월정액` 13자, `30일 이하 월 전환동의` 13자로 wiki-ux 권장(12자)을 1자 넘는다. 앞의 것은 기존 칩 글자(`PPM_DETAILS` label)와 같아야 해서 줄이지 않는다. 뒤의 것은 줄이면 규칙 기반 근거가 흐려진다(4-3 시험 참고). wiki-ux 확인 필요.

### 4-2. `placement` — 노출 구좌

**문장**: `[상품] [혜택] 프로모션 노출 구좌 잡아 줘`

**진행 확인 칩은 뜨지 않는 것이 맞다.** 결과물 요청(`detectDeliverable` → `placement`)이라 칩 없이 바로 답한다. 규칙 기반은 `deliverableReply` 가 플레이북에서 혜택에 맞는 조합 하나를 골라 편성 영역·필수 배너 줄을 보여 준다. 처음 쓴 문장(`… 하면 노출 구좌는 어디가 좋아?`)은 판단 요청으로 가서 규칙 기반 답이 문서 소개 문장만 뽑았다 — `잡아 줘` 로 바꿔 결과물 요청으로 보냈다.

`추천해 줘`·`골라 줘` 는 쓰지 않는다. 서버 `JUDGMENT` 정규식에 걸려 리포트 칩(`reportHint: 'offer'`)이 붙는다. `잡아 줘` 는 `MAKE_CUES` 에는 걸리고 `JUDGMENT` 에는 안 걸린다.

### 4-3. `policy` — 정책 확인

**문장**: `[상품] 프로모션에서 [정책 항목] 기준 알려줘`

**진행 확인 칩·세부 상품 칩 모두 뜨지 않는 것이 맞다.** 사실 질문이다. `기준` 이 `ASKS_RULE` 에 걸려 결과물 요청에서도 빠진다. PPM 정책은 세부 상품과 상관없이 같으므로 상품 칸은 **PPM/PPV 두 값**(기존 상품 칩 글자 그대로)이다.

`B tv+`·`지상파·종편·CP 월정액` 을 상품 값으로 넣지 않은 이유: `지상파·종편·CP 월정액 프로모션에서 약정 쿠폰 기준 알려줘` 를 보내면 `지상파`·`종편`·`CP` 글자 때문에 규칙 기반 검색이 실적 벤치마크(MKI-04)의 반응률 줄을 2순위 근거로 끌고 온다(실측). 정책 질문에 관계없는 실적 수치가 붙는다.

| 정책 항목 (`월정액(PPM)`) | `전환동의` | `promotion/ppm.md` "다크패턴 대응 및 정가 전환동의" |

### 4-4. 넣지 않은 틀 — `system` (시스템 사용법)

| 이유 | 실측 |
| --- | --- |
| `방법`·`어떻게 해` 가 들어가면 `wantsAdvice` 가 `쿠폰`·`캠페인` 과 함께 참이 되어 매뉴얼 답 끝에 마케팅 인사이트 안내 줄이 붙는다 | `CBS에서 쿠폰 정책 등록 하는 방법 알려줘`, `ACS에서 간편 캠페인 등록 어떻게 해?` |

| 매뉴얼 질문은 규약상 숙련도를 한 번 되묻는다(96행). 작업을 특정하면 안 묻지만, `Swing 접점공지 등록` 처럼 매뉴얼 전체에 가까운 작업은 되물을 수 있다 | 엔진 실측 못 함 |

### 4-5. 상수 모양 (dev-front 참고)

wiki-ux 2.7 제안 구조를 따른다. 값 목록은 앞 빈칸 값별로 둔다.

```ts
// 예시 — 이름·구조는 dev-front 재량. 문장 조각과 값 글자는 이 문서 4-1~4-3과 글자 단위로 같아야 한다
{ id: 'plan', label: '프로모션 기획',
  parts: [{ slot: 'product' }, ' 프로모션을 ', { slot: 'benefit' }, ' 방식으로 기획하려고 해'],
  slots: {
    product: { label: '상품', values: ['B tv+', '지상파·종편·CP 월정액', '영화 PPV', '영화 외 PPV'] },
    benefit: { label: '혜택', dependsOn: 'product', valuesBy: { 'B tv+': PPM_BENEFITS, … } },
  } }
```

`placement` 문장 조각: `[product] [benefit] 프로모션 노출 구좌 잡아 줘` (빈칸 사이 공백 하나). `policy` 문장 조각: `[product] 프로모션에서 [item] 기준 알려줘`.

## 6. ④ "이어서 물어볼 만한 것" 버튼 — 2차 설계 메모

| 항목 | 메모 |
| --- | --- |
| 생성 주체 | **1안 화면 규칙(서버 무변경)을 권한다.** 답의 근거 문서(`sources`) 끝 "다음에 볼 문서" 표의 행과, ② 틀 사이의 이동(예: `placement` 답 다음 → 같은 상품·혜택의 `policy` 질문)으로 만든다. 2안 엔진 생성은 `REPLY_SCHEMA` 에 칸을 더하는 일이라 `server/knowledge.ts` 공유 규칙에 따라 `server/`·`api/` 를 함께 바꿔야 하고, 엔진이 문서 밖 질문을 만들 위험이 생긴다 |
| 상품 혼동 방지 (가장 중요) | 버튼을 누르면 그 글이 **사용자 발화**로 들어가고, `readSlots` 는 마지막 상품 발화를 따른다. 그래서 버튼 문장에 **사용자가 말하지 않은 상품을 넣으면 상품이 바뀌어 버린다.** 규칙: 사용자가 정한 상품 글자를 그대로 넣거나 상품 글자를 아예 넣지 않는다. 반대 상품 문서로 가는 행(`ppm.md` "PPV 정책이 궁금하다" 등)은 버리고, 상품을 모르는 대화에서는 상품 글자가 없는 버튼만 만든다 |
| 의도 감지 검증 | 버튼 문장도 ② 와 같은 harness 로 미리 돌려 진행 확인 칩·리포트 칩이 뜨지 않는 문장만 쓴다(`프로모션`+`하려/기획/진행` 조합, `추천`·`골라 줘` 금지) |
| 기존 칩과의 관계 | `reply.intent` 가 있으면(진행 확인·상품·세부·다음 단계) 버튼을 숨긴다 — 조건을 정하는 칩이 먼저다. `report`·`reportFailed`·`cancelled` 에도 숨긴다. `withNextStep` 의 카피·구좌 추천과 같은 내용은 만들지 않는다 |
| 개수·모양 | 2개까지, `· ` 목록이 아니라 답 아래 버튼 줄. 답 본문 5줄 규칙과 별개로 화면이 붙인다 |
| 규약 쪽 | 규약 46행 "다음 질문을 받는 한 줄" 예외와 겹칠 수 있다. 버튼을 붙이는 답에서는 그 한 줄이 중복되므로 2차 착수 때 규약에서 그 예외를 정리할지 chatbot-planner 가 다시 본다 |
| 먼저 정할 것 | "다음에 볼 문서" 행을 질문 문장으로 바꾸는 규칙(행 → 문장 표를 상수로 둘지), 대화당 버튼 노출 횟수 |
