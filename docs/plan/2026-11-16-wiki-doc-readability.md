# 위키 문서를 사람도 AI도 읽기 편하게 — 문서 작성 규약과 일괄 정리

작성: plan-pm · 2026-11-16 · 기준 커밋 `36e050e` (main, PR #72·#73 반영 뒤) · 코드 변경 없음

상위 지시: "위키 문서들은 사람이 읽기도 편해야 하고, AI가 읽기도 편해야 한다."

## 문제

이 지시가 겨누는 사용자는 둘이다. 같은 문서를 읽고, 막히는 곳이 서로 다르다.

| 누가 | 어떤 상황에서 | 무엇을 못 하고 있나 |
| --- | --- | --- |
| 편성·마케팅 실무자 (위키 화면) | 정책·규격 문서를 열어 답을 찾을 때 | 문서마다 같은 말을 다르게 쓴다. 할인쿠폰과 할인 쿠폰, 2단배너와 2단 배너, TV팝업과 TV 팝업이 섞여 있다. `·`, `—`, `→`, 중첩 괄호가 한 문장에 겹쳐 개조식 메모처럼 읽힌다. 비어 있는 항목을 표시하는 방식도 다섯 가지라 "이건 아직 없는 내용"이라는 신호를 한눈에 알아보기 어렵다 |
| 실무자 (위키 검색 Ctrl+K) | 용어로 문서를 찾을 때 | 검색이 띄어쓰기 단위로 단어를 자른다(`src/lib/retrieval.ts` `rawTerms`). "할인쿠폰"으로 찾으면 "할인 쿠폰"만 쓴 문서는 "할인" 조각으로만 걸려 점수가 낮다 |
| 챗봇 (Claude CLI 경로) | 작업 폴더를 Grep·Read로 뒤져 근거를 찾을 때 (`server/cliBridge.ts:209,272`) | Grep은 글자 그대로 찾는다. 표기가 하나가 아니면 같은 개념이 적힌 문서를 놓친다 |
| 챗봇 (Codex·Gemini 경로) | 문서 40개를 통째로 받아 읽을 때 (`server/knowledge.ts` `buildDocsBlock`) | 답이 표에만 있는 문서가 많다. 표를 문장으로 옮기다 "플레이북상 '…' 패턴" 같은 어색한 인용이 나왔다(#73에서 프롬프트로 막음). 빈칸 표시가 다섯 가지인데 프롬프트는 그중 두 가지만 안다 |
| 챗봇 (엔진 없는 기본 답변) | `retrieval.ts`가 소제목·문단·줄 단위로 잘라 근거 문장을 뽑을 때 | 표 줄을 펼 때 머리글을 버린다(`flattenTableRow`, `parseSections`가 구분선 위 머리글 줄을 뺀다). 열이 여러 개인 표는 "5.3.5 — 약정상품 쿠폰 적용 — PPM — …"처럼 각 값이 무슨 칸인지 모른 채 인용된다 |

한 줄 요약: 문서 형식에 기준이 없어서, 사람은 훑어 읽기 어렵고 AI는 찾기와 인용이 어렵다. 해결책은 화면이 아니라 **문서 본문의 작성 규약과 그 규약대로의 일괄 정리**다. 화면 쪽 가독성은 이미 PR #69 등으로 반영돼 있다(아래 "현재 상태 › 화면 쪽" 참고).

`server/assistant-prompt.md:60`은 `**아직 못 채운 것** —`과 `(보완 필요)`를 인용 금지로 적었다. `(보완 필요)`는 지금 문서에 한 번도 없고, `확인 필요`·`미확정`은 프롬프트가 모른다.

### 상품 유형 표시

- 문서 단위: 프론트매터 `scope` 하나뿐. 검색은 반대 상품 전용 문서를 근거에서 뺀다(`retrieval.ts` `inScope`).
- 문서 안: 공통 문서 35개 중 상품이 섞인 문서가 많은데(playbook, schemes, targeting, benchmarks, products, channel, overview 등), 줄 단위 표시는 `[PPM]` 10회·`[PPV]` 1회(5개 문서)뿐이다. `playbook.md`는 "PPV — 단건 구매"처럼 H2로 나눈다. B tv+는 표시 방식이 없다.
- 프롬프트는 "사용자 상품에 해당하는 줄만 인용"하라고 하지만(`assistant-prompt.md`), 문서가 그 줄을 표시하지 않으면 모델이 문맥으로 짐작해야 한다.

### 화면 쪽 — 이미 된 것 (이번 범위와 겹치지 않게)

`docs/ux/2026-11-13-wiki-readability-review.md`의 항목 대부분이 반영돼 있다. 본문 폭 820px(`styles.css:54,615`), 한글 줄바꿈 keep-all(`:663`), 경로 줄(`.crumb`), 한중일 굵게 플러그인(`WikiDoc.tsx:241`), 좁은 폭 접는 목차(`WikiDoc.tsx:277`), 적용대상 태그(`WikiDoc.tsx:30`), 처음이라면 줄(`WikiIndex.tsx:80`), 사이드바 순서 정렬(`docRank`). 이번 작업은 **문서 본문**과 그것을 읽는 **검색·프롬프트**만 다루고 `styles.css`·화면 배치는 건드리지 않는다.

## 이번 범위 / 범위 밖

### 이번 범위

1. **1단계 규약 정리** — 작성 규칙(HUB-03)을 이 문서의 규약 초안으로 고쳐 쓴다. 용어 표준표를 정한다. 규약을 기계로 검사하는 `npm run check:docs`를 만든다. 정리 전에 질문 세트로 기준선을 잰다.
2. **2단계 기존 문서 일괄 정리** — 40개 문서를 규약대로 고친다. 세 묶음으로 나눠 PR을 낸다(용어·빈칸 → 첫머리·표 → 상품 표시).
3. **2단계와 나란히, 읽는 쪽 맞추기** — 프롬프트의 근거 규칙을 새 규약에 맞춘다. 기본 답변 검색이 표 머리글을 살리고 빈칸 절을 근거에서 빼게 한다. AI 수정 프롬프트가 규약을 따르게 한다.
4. **3단계 검증** — 같은 질문 세트로 정리 전후를 비교한다.

## 문서 작성 규약 초안

`지식/guide/writing.md`(HUB-03)를 고칠 때의 원안이다. 확정은 열린 질문을 정한 뒤에 한다.

### R1. 용어 표기

- 용어 사전(`promotion/glossary.md`, PPC-R-03)에 **표준 표기** 열을 두고 이것을 기준으로 한다.
- 정하는 원칙(제안): 시스템 화면에 적힌 표기가 있으면 그것을 따른다. 없으면 같은 무리끼리 맞춘다. 배너 종류는 붙여 쓴다(빅배너, 띠배너, 롱배너, 2단배너). 쿠폰 종류도 붙여 쓴다(할인쿠폰).
- 1차 표준표 초안: 할인쿠폰, 2단배너, TV팝업, B tv, 전환동의, 자동 해지, 정가 전환, 판촉용 쿠폰, 선발급, 타겟, 푸시. 할인쿠폰·2단배너는 Q1에서 정한다.
- 상품명은 문서마다 처음 나올 때 한 번 "월정액(PPM)", "단건 구매(PPV)"로 쓰고, 그 뒤로는 한쪽으로 통일한다.
- 약어는 처음 나올 때 한 번 풀어 쓴다. 풀어쓴 이름은 용어 사전과 같아야 한다.

### R2. 문서 첫머리

1. 첫 줄은 지금 형식 그대로 `> 적용대상 **PPM|PPV|공통** · 관련 시스템 …`. 화면이 이 줄을 태그로 바꾸므로 형식을 바꾸지 않는다. 지금 없는 6개 문서에도 넣는다.
2. 첫 H2는 `## 이 문서는`. **첫 문장이 요약 줄**이다. "이 문서는 ~할 때 봅니다. 핵심은 ~입니다." 형태로, 80자 안쪽, 이 문서가 답하는 질문과 핵심 답을 담는다. 검색이 이 문장을 뽑아도, 사람이 목록에서 이 문장만 봐도 문서를 고를 수 있어야 한다.
3. 프론트매터 `summary` 필드를 따로 둘지는 Q3에서 정한다.

### R3. 문단

- 한 문단에 한 주제. 문단은 600자 안쪽, 한 문장 줄은 200자 안쪽.
- 문장 안 나열은 쉼표로 잇는다. `·`는 표 칸, 소제목, 짧은 명사 묶음(예: "ACS·CBS")에만 쓴다.
- `—`는 문장 안에 쓰지 않는다. 덧붙이는 말은 쉼표나 새 문장으로 쓴다.
- `→`는 "다음에 볼 문서" 표와 유저플로우 칸에만 쓴다. 절차는 번호 목록으로 쓴다.
- 괄호는 한 문장에 하나까지. 괄호 안에 괄호를 넣지 않는다.
- "위 표", "아래와 같이", "앞서 말한" 같은 지시어를 쓰지 않고 대상 이름을 직접 쓴다. 문서는 조각으로 잘려 인용된다.
- 굵게는 한 문장에 한 구절까지.

### R4. 표

- 표는 **같은 속성을 가진 항목 셋 이상을 나란히 비교할 때** 쓴다. 이유·예외·판단 근거처럼 설명이 필요한 내용은 문장으로 쓴다.
- 표 바로 위에 **이 표가 무엇을 비교하는지** 한 문장을 둔다. 예: "기능마다 필요한 최소 UI 버전입니다."
- 첫 열은 행 이름이다. 그 행만 떼어 읽어도 무엇에 대한 줄인지 알 수 있어야 한다.
- 값 칸에 O·X·✓·— 같은 기호만 쓰지 않는다. "지원", "미지원", "없음"처럼 말로 쓴다.
- 한 칸에 문장 둘 이상을 넣지 않는다. 넘치면 표 아래 문단으로 뺀다.
- 열은 5개까지. 넘으면 표를 나눈다.
- 2열 "항목 / 값" 표(플레이북 조합표 형식)는 사람과 AI 모두에게 좋아서 권장 형식으로 둔다.

### R5. 소제목

- `##`·`###`만 쓴다. `####`는 `###`으로 올리거나 굵은 줄로 바꾼다.
- 소제목에는 실무자가 질문에 실제로 쓰는 단어를 넣는다. 검색이 소제목에 걸린 질문은 그 절을 통째로 근거로 쓴다(`retrieval.ts` `findSection`).
- 새로 다는 소제목에는 `·`, `—`, `/`, `→`, 괄호를 쓰지 않는다. 기존 소제목은 Q6에서 정한다.
- 한 소제목 조각은 30줄 안쪽.

### R6. 상품 유형 표시

- 문서 단위는 프론트매터 `scope`: `PPM`, `PPV`, `공통` 중 하나. 작성 규칙의 `PPM 전용` 표기는 고친다.
- 공통 문서 안에서 한 상품에만 해당하는 소제목·줄·표 행은 앞에 `[PPM]`, `[PPV]`를 단다. 지금 `channel.md` 등에서 쓰는 형식을 표준으로 넓힌다.
- 상품별로 절을 나눌 수 있으면 소제목에 상품명을 넣는 쪽을 먼저 쓴다(예: `## PPV 단건 구매`).
- B tv+ 표시는 Q4에서 정한다.

### R7. 빈칸 표시 — 두 가지로 줄인다

| 무엇 | 형식 | 위치 |
| --- | --- | --- |
| 이 문서에 아직 없는 항목 | 문서 끝 `## 아직 없는 내용` 절 하나에 목록으로 | "다음에 볼 문서" 바로 앞 |
| 원문이 엇갈리거나 확인되지 않은 값 | 문장 안 `(확인 필요: 사유)`. 표 칸에는 `확인 필요`만 | 그 값이 있는 자리 |

- 기울임, 인용 상자, `**아직 못 채운 것** —`, `미확정`, `(보완 필요)`는 쓰지 않는다.
- 절로 모으면 사람은 목차에서 "아직 없는 것"을 바로 보고, 검색과 프롬프트는 절 이름 하나로 근거에서 뺄 수 있다.
- `status`는 본문에 `확인 필요`가 있으면 `초안`이다(Q5).

### R8. 문서 끝

- `## 다음에 볼 문서` 표를 모든 문서에 둔다. 표 형식은 지금처럼 `상황 | 이동`.

| 부딪히는 곳 | 사람 쪽 | AI 쪽 | 제안 |

