## 2. 결함 1 — 질문인데 기획 상담으로 가는 문제

### 2-1. 원인

- `detectCampaignIntent`(`assistant.ts:151`)는 `CAMPAIGN_NOUNS` 하나와 `PLAN_VERBS` 하나가 있으면 참이 된다(`:50`). 걸러 내는 것은 결과물 요청, 절차 질문, 지식 수정, 가능성 질문(`asksPossibility`, `:161`)뿐이다. **"~하려면?", "무엇을 챙겨야 해?" 같은 질문은 거르지 않는다.**
- `intentPromptFor`(`:606`)는 `detectCampaignIntent` 만 본다. 그래서 규칙 기반과 AI 엔진 경로(`requestEngine` 이 같은 함수를 부른다) **둘 다에** 진행 확인 칩이 붙는다.
- `answer`(`:935`)는 `intentPromptFor` 가 칩을 주면 근거 없는 한 줄(`PPM(월정액) 프로모션이군요.`)을 돌려준다. 그 아래 `:961` 는 `!isQuestion(query)` 로 질문을 빼 주지만, 칩 분기가 먼저 돌아서 이 조건까지 내려오지 못한다. **두 곳의 판정이 서로 다르다.** 이것이 결함의 원인이다.

### 2-2. 판별 규칙

**위치**: `detectCampaignIntent` 안, 지금의 `if (asksPossibility(query)) return false`(`:161`) 자리. 이 줄을 아래 판정으로 **바꾼다**. `asksPossibility` 는 `isQuestion` 안에 이미 들어 있어서 중복이다.

```ts
/** "~하려면", "~만들려면"은 하겠다는 말이 아니라 조건을 걸고 묻는 말이다 */
const CONDITIONAL_ASK = /려면/
/** "할까 해", "해 볼까 하는데"는 묻는 말이 아니라 하려는 뜻이다 — isQuestion 의 '할까'·'볼까' 어미에 걸리지 않게 먼저 지운다 */
const PLAN_MUSING = /(?:할까|볼까)\s*(?:해|하는데|하고|하는|싶|생각|고민)/g

/** 기획 의도를 말한 게 아니라 묻고 있는지 — 묻고 있으면 진행 확인 대신 답을 한다 */
function asksRatherThanPlans(query: string): boolean {
  const q = query.replace(PLAN_MUSING, ' ')
  return CONDITIONAL_ASK.test(q) || isQuestion(q)
}

// detectCampaignIntent 안
if (asksRatherThanPlans(query)) return false
```

조건을 정리하면 이렇다.

| 조건 | 판정 | 예 |
| --- | --- | --- |
| `?`·`？` 가 있다 | 질문 | `… 프로모션 하려면?` |
| `려면` 이 있다 | 질문(물음표가 없어도) | `월정액 프로모션 하려면 전환동의 받아야 돼` |
| `isQuestion` 의 의문사·의문 어미·가능성·요청어(`뭐`, `무엇`, `몇`, `나요`, `가능해`, `알려` 등) | 질문 | `… 무엇을 챙겨야 해?`, `결재 누구한테 받아` |
| `할까/볼까` 뒤에 `해·하는데·하고·싶·생각·고민` | 질문이 아니다(그 부분만 지우고 나머지로 다시 본다) | `다음 달 쿠폰 프로모션 할까 해` |
| 그 밖 | 지금처럼 `CAMPAIGN_NOUNS` + `PLAN_VERBS` | `B tv+ 프로모션을 할인 쿠폰 방식으로 기획하려고 해` |

**같이 고칠 곳**

1. `answer` `:961` 의 `&& !isQuestion(query)` 를 지운다. 질문은 이미 `detectCampaignIntent` 에서 빠지므로 판정이 한 곳으로 모인다. 지우지 않으면 `할까 해` 처럼 `isQuestion` 이 참인 기획 발화가, 칩을 이미 받은 대화에서는 한 줄 답 대신 검색 결과로 간다(두 판정이 다시 갈린다).
2. `AppStore.tsx:384` 는 `detectCampaignIntent` 를 그대로 쓰므로 고칠 것이 없다. 이제 질문이 들어왔을 때 확인 칩 기록(`intentAskedRef`)을 되돌리지 않는다. 이 동작이 맞다.
3. (선택) `PLAN_VERBS` 에 `'돌려보'`, `'돌려 보'`, `'해보려'`, `'해 보려'` 를 더한다. 규약 78행의 기획 상담 예 `배너로 쿠폰 돌려보려는데` 가 지금은 기획 의도로 잡히지 않는다. 규약과 코드가 어긋나는 곳이다. `보려` 만 따로 넣으면 `쿠폰함 보려고` 같은 말이 걸려서 넣지 않는다.

**막히는 오답**: `B tv+로 5일 미만 동안 할인 쿠폰 프로모션 하려면?` → 지금은 진행 확인 칩과 `PPM(월정액) 프로모션이군요.` 한 줄, 근거 0건. 고친 뒤에는 칩 없이 `PPM(월정액) 기준입니다.` 와 근거 문서 2건.

### 2-4. 알려진 한계 · 범위 밖에서 찾은 것

- `isQuestion` 의 의문사 목록에는 `몇`·`어떤` 이 있다. 그래서 `어떤 프로모션을 기획하려고 해` 같은 드문 평서문도 질문으로 본다. 이 경우 질문으로 답하는 쪽이 근거 규칙(1순위)에 더 안전해서 그대로 둔다.
- **범위 밖 결함(보고만 함)**: `이번 달 B tv+ 프로모션 진행하려고 하는데요` → `detectDecision` 이 참이 된다(`DECIDE_CUES` 의 `'진행하려'`, `:335`). 그래서 진행 확인 대신 `정리했습니다. 이벤트명 · 이벤트 기간 · 이벤트 스킴만 알려 주시면…` 이 나온다. 기획 **시작** 을 방향 **결정** 으로 잘못 읽은 것이다. `'진행하려'` 를 `~로 진행하려` 처럼 무엇을 골랐는지 앞에 있을 때만 결정으로 세도록 하는 방안이 있다. `detectDecision` 은 정리 카드 흐름 전체에 영향을 주므로 따로 다룬다.

### 3-4. 규칙과 위치

1. **`SCOPE_ONLY_TERMS.PPM`(`:723`)에 `'해지방어'`, `'다크패턴'` 을 더한다.** 근거는 `ppv.md` 머리말과 `ppm.md` 해지방어 쿠폰 운영 절이다. 상품이 PPV 일 때 빠지지 않던 다크패턴 줄도 이것으로 빠진다.
2. **`keepUsable` 맨 앞에 "상품 모름" 분기를 둔다.**
   - 조건: `!search.scope` 이고, 이번 발화와 앞선 **사용자** 발화(`search.query` + `search.context`)에 PPM 전용 말이 하나도 없을 때.
   - 동작: PPM 전용 말이 있고 PPV 말(`단건`·`ppv`)은 없는 줄을 뺀다. 두 상품을 함께 말하는 비교 줄(예: `ppv.md` "PPV를 가르는 건…PPM에는 없는, PPV만의 설계 포인트")은 남긴다.
   - 예외: 질문이 `전환동의`·`약정`·`해지방어` 같은 PPM 전용 항목을 **직접 물으면** 빼지 않는다. 그 항목을 묻는 질문은 사실상 PPM 질문이다.
   - PPV 전용 줄은 빼지 않는다. PPV 쪽 말은 상품 이름(`단건`·`ppv`)뿐이고, `ppv.md` 가 밝히듯 PPM 담당자를 막아 세울 제약이 없다. 빼면 `쿠폰 적용 범위 기준 알려줘` 의 답(PPC-P-03 적용 범위 줄)이 사라진다.
3. **뺀 줄이 있으면 상품 칩을 붙인다.** `answer` 가 "상품 모름 분기에서 줄을 하나 이상 뺐다"는 표시를 돌려준다(예: `AssistantReply` 에 내부용 `scopeTrimmed?: true`). `withRefine`(`:1250`)에 `reply.scopeTrimmed && !slots.product && !asked.product` 이면 `{ kind: 'product-qa', question: INTENT_PRODUCT_RETRY_QUESTION, retry: query }` 를 붙이는 조건을 하나 더한다. 칩 문구("고르시면 그 상품 기준으로 다시 맞춰 드립니다")와 고른 뒤 동작(`AppStore.tsx` 의 `retry` 재전송, 대화당 한 번)은 지금 있는 것을 그대로 쓴다.
4. AI 엔진 경로는 엔진이 이 표시를 돌려주지 않으므로 칩을 붙이지 않는다. 엔진은 규약 문장(6절 ②)으로 맞춘다.

**막히는 오답**: `CBS 쿠폰 발급이 안 돼` → 지금은 PPC-P-02 "약정 월정액…5.4.1 이상 고객 대상으로만 약정 쿠폰을 발급" 줄이 답에 나온다. 고친 뒤에는 이 줄이 빠지고, CBS 매뉴얼 줄과 최대발급수량 줄(PPM 전용 말 없음)만 남는다.

**막히는 오답**: `ACS 캠페인 효율 좋은 방법` → 지금은 화면 메뉴 목록(캠페인 조회·타겟리스트 관리…)만 근거로 나온다. 고친 뒤에는 타겟팅 기준이 근거로 들어간다.

### 4-3. (c) `playbookCombo` 의 영화 전용 조합 — **영화라고 밝힌 PPV 에만 쓴다**

현재(`76b4a87`) 동작:

| 문장 | 고른 조합 | 문제 |
| --- | --- | --- |
| 영화 외 PPV 할인 쿠폰 선발급 프로모션 노출 구좌 잡아 줘 | 2. **영화** · 구매 전환 / 할인쿠폰 선발급 → "영화 GNB" | 영화가 아니라고 했는데 영화 구좌가 나온다 |
| 시리즈 PPV 할인 쿠폰 다운로드 프로모션 노출 구좌 잡아 줘 | 3. **영화** · 구매 전환 / 할인쿠폰 다운로드 | 같다 |
| PPV 할인 쿠폰 선발급 프로모션 노출 구좌 잡아 줘 (영화 여부 모름) | 2. **영화** · … | 모를 때 영화로 단정한다. (a) 카피 쪽 판단(모르면 공통)과 어긋난다 |
| 영화 PPV 할인 쿠폰 선발급 프로모션 노출 구좌 잡아 줘 | 2. 영화 · … | 맞음 |

원인은 둘이다. ① `playbookCombo`(`:839`)는 PPV 절의 1~6 조합을 모두 후보로 둔다. ② 조합을 고를 때 질문 단어를 세는데(`tokenize(search.query)`), `영화 외` 의 `영화` 가 "영화 ·" 조합 제목과 맞아 점수가 오른다.

**규칙** (위치: `playbookCombo`, `deliverableReply` 의 `kind === 'placement'` 분기 `:894`)

1. 후보 거르기: `search.scope === 'PPV' && search.ppvKind !== 'movie'` 이면 제목이 `/^\d+\.\s*영화\s*·/` 인 조합을 후보에서 뺀다. **영화라고 밝힌 PPV 만** 영화 조합을 쓴다. 영화 여부를 모를 때도 빼서 (a) 와 같은 원칙(모르면 공통)을 따른다.
2. 점수 계산에서 부정어 지우기: `tokenize(search.query.replace(NOT_MOVIE, ' '))`. `NOT_MOVIE`(`:227`)는 dev-front 가 이미 만든 정규식을 그대로 쓴다.
3. 남은 후보 중 질문과 맞는 조합이 없고(최고 점수 0) 뺀 영화 조합이 있었으면 조합을 고르지 않는다. 지금은 점수가 0이면 첫 조합(1. 단순 홍보)을 고르는데, 선발급을 물었는데 단순 홍보 구좌를 보여 주게 된다. 이때 `playbookCombo` 는 `{ movieOnly: true }` 를 돌려주고, `deliverableReply` 는 기존 대체 경로(MKI-B-00 노출 구좌 개요) 앞에 한 줄을 넣는다. "이 혜택 조합은 플레이북에 영화 PPV 기준으로만 있습니다." 문서에 없으면 없다고 말하는 규칙(64행)을 따른 것이다.

수정 후(임시 복사본 실측, 3번의 한 줄은 넣지 않고 셈):

| 문장 | 수정 후 조합 |
| --- | --- |
| 영화 외 PPV 할인 쿠폰 선발급 … 잡아 줘 | 조합 없음 → MKI-B-00 + "영화 PPV 기준으로만 있습니다" |
| 시리즈 PPV 할인 쿠폰 다운로드 … 잡아 줘 | 같음 |
| PPV 할인 쿠폰 선발급 … 잡아 줘 (모름) | 같음 |
| 영화 PPV 할인 쿠폰 선발급 … 잡아 줘 | 2. 영화 · 구매 전환 / 할인쿠폰 선발급 (유지) |
| 영화 PPV 할인 쿠폰 다운로드 … 잡아 줘 | 3. 영화 · … (유지) |
| 영화 외 PPV 시즌 특가 … 잡아 줘 | 6. 주요 상품 전체 · 구매 전환 / 시즌 특가 (유지) |
| 영화 외 PPV 단순 홍보 … 잡아 줘 | 1. 전체 콘텐츠 · 인지 / 단순 홍보 (유지) |
| PPV 시즌 특가 … 잡아 줘 (모름) | 6. (유지) |
| B tv+ 할인 쿠폰 … 잡아 줘 | 8. 전체 월정액 · 신규 가입 (유지, PPM 은 영향 없음) |

빈칸 템플릿 `placement` 틀은 `영화 외 PPV` 혜택 값을 `단순 홍보`·`시즌 특가` 둘로만 두었다(앞 문서 4-2). 그래서 템플릿으로 보낸 문장은 위 표처럼 모두 맞는 조합을 받는다. 이 수정은 직접 입력한 문장을 위한 것이다.

**막히는 오답**: `영화 외 PPV 할인 쿠폰 선발급 프로모션 노출 구좌 잡아 줘` → 지금은 "편성 영역 — Today B tv, 영화 GNB, WING UI 등"이 나온다. 고친 뒤에는 영화 구좌가 나오지 않는다.
