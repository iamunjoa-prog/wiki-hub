# 첫 로그인 안내 — 내 Claude Code·Codex 계정으로 챗봇 쓰기

상위 지시: "처음 계정 로그인할 때, Claude Code나 Codex 계정이 있는 사람은 바로 연결해 쓰도록 ZIP 파일과 가이드를 주면 어때? 간단한 설명도 넣고. 기획해서 예시 화면을 보여줘."

## 문제

**누가**: 편성·마케팅 실무자. 관리자에게 받은 허브 계정으로 배포 허브에 처음 로그인한다. 이 중 일부는 회사나 개인 용도로 Claude Code 또는 Codex 계정을 이미 갖고 있다.

**못 하고 있는 것**

| 실무자가 원하는 것 | 지금 일어나는 일 | 원인 |
| --- | --- | --- |
| 이미 가진 Claude Code·Codex 계정으로 챗봇 답을 받고 싶다 | 배포 허브 챗봇은 늘 Gemini API로 답한다. 내 계정을 연결할 방법이 화면에 드러나지 않는다 | CLI는 실무자 PC에서만 돌 수 있다. 그래서 로컬 허브를 내려받아 실행해야 하는데, 이 안내가 대시보드 오른쪽 "챗봇 답변 엔진" 패널의 `⚙ 연결 설정` / `내 PC에서 쓰기` 버튼을 눌러야 나오는 창에만 있다 |
| 로컬 허브를 왜 받아야 하는지 알고 싶다 | 설정 창 첫 줄은 "CLI로 답받으려면 내 PC에서 허브를 실행하세요"뿐이다. 무엇이 좋아지는지는 설명하지 않는다 | 설정 창은 이미 마음먹은 사람을 위한 화면이다 |
| 계정이 없으면 신경 쓰지 않고 바로 일하고 싶다 | 지금은 안내가 숨어 있어 문제가 없다. 안내를 앞으로 꺼내면 계정 없는 사람에게는 방해가 된다 | 대상이 둘로 갈린다 |

**목표**

1. 배포 허브에 처음 들어온 실무자가 따로 찾지 않아도, 한 번은 "내 계정으로 연결해 쓸 수 있다"는 안내를 본다.
2. Claude Code·Codex 계정이 있는 사람은 그 안내 창 안에서 ZIP을 받고 4단계로 실행까지 간다.
3. 계정이 없는 사람은 한 번 누르면 바로 허브로 돌아가고, 같은 안내를 다시 보지 않는다.
4. 안내 문구와 내려받기 동작은 기존 설정 창과 한 곳에서 관리한다. 두 화면의 안내가 따로 놀지 않게 한다.

## 현재 상태 (확인한 파일 경로 포함)

**로그인 흐름**

- `src/main.tsx`: `AuthGate` → `BrowserRouter` → `AppProvider` → `App` 순서로 감싼다. **`AuthGate` 는 `AppProvider`(토스트·엔진 상태) 바깥**에 있다.
- `src/components/AuthGate.tsx`: 상태는 `loading` / `demo` / `signedOut` / `signedIn` 네 가지다.
  - `fetchAuthStatus()` 가 `enabled: false` 이면 `demo` 로 로그인 없이 통과한다.
  - `signedOut` 이면 `LoginForm` 을 보여 준다. 화면에는 제목, "관리자에게 받은 허브 계정으로 로그인합니다.", 아이디·비밀번호, 도움말 한 줄이 있다.
  - `signedIn` 인데 `mustChangePassword` 이면 `PasswordForm` 을 보여 준다. 첫 로그인과 비밀번호 초기화 직후가 여기에 해당한다. 바꾸고 나면 `onDone` 으로 바로 허브가 열린다.
  - `useAuth().user` 는 `signedIn` 일 때만 값이 있고, `demo` 이면 `null` 이다.
- `src/lib/auth.ts`: `HubAccount` 필드는 `loginId·name·team·role·mustChangePassword·disabled·createdAt` 이다. **"안내를 봤는지" 같은 필드는 없다.** 세션은 HttpOnly 쿠키로 관리한다. 다시 접속하면 로그인 화면 없이 `signedIn` 으로 복원된다.
- `docs/accounts.md`:
  - 계정 저장소나 `HUB_AUTH_SECRET` 이 없으면 데모 계정으로 동작한다. **"지금 배포가 이 상태입니다."** 지금 배포에는 "첫 로그인"이라는 순간이 아직 없다.
  - 로컬 허브는 로그인 없이 데모 계정으로 동작한다.

**지금 있는 안내 (`src/components/CliStatus.tsx`, 방금 머지된 상태)**

- 상수: `LOCAL_URL`, `DOWNLOAD_URL = '/api/download-hub'`, `detectOs()`(Mac이 아니면 Windows), `launcher`.
- 배포 허브인지는 `isLocal = engineStatus 에 claude/codex 키가 있는지` 로 판단한다.
- 대시보드 패널(배포)에는 Gemini 행과 "Claude · Codex CLI / [내 PC에서 쓰기]" 행이 있다.
- 설정 창의 `!isLocal` 분기에는 다음이 들어 있다.
  - 엔진 상태 한 줄
  - OS 표시와 "Mac 안내 보기 / Windows 안내 보기" 전환
  - 4단계 안내
  - 폴더 구성 보조 한 줄
  - `로컬 허브 내려받기` 버튼과 `downloadHub()`: fetch → Blob, 실패 사유를 화면에 보여 주고 성공하면 토스트를 띄운다.
  - "이미 받아 두셨다면: 로컬 허브 열기 ↗"
- 이 블록은 **하나의 컴포넌트 안에 인라인으로** 들어 있다. 다른 화면에서 다시 쓸 수 없다.
- 스타일(`src/styles.css` 753~783행): `.cli-modal`(500px), `.cli-guide`, `.cli-steps`, `.cli-os`, `.cli-os-switch`, `.cmd`. 모달 공통은 974~985행 `.modal-back`·`.modal`·`.modal-body` 이고, 로그인 화면은 1202~1209행 `.login-*` 이다.

**로컬 허브 실행 시 하는 일 (`scripts/setup.ps1`, `start-hub.command`)**

- Node.js가 없으면 설치를 묻는다(Windows는 winget, Mac은 Homebrew).
- Claude·Codex CLI가 없으면 설치를 묻는다.
- 설치는 됐는데 로그인이 안 돼 있으면 "지금 로그인할까요? (브라우저가 열립니다)"라고 묻는다.
- 바탕화면 바로가기를 만들고 패키지를 설치한 뒤 브라우저를 연다.
- 정리하면 **ZIP을 풀고 실행기를 누른 뒤 Y만 누르면 CLI 설치와 계정 로그인까지 이어진다.** 안내 창은 이 흐름을 "Y를 누르고 내 계정으로 로그인"까지 알려 주면 된다.

**ZIP 구성 (`docs/plan/2026-11-12-hub-download-layout.md`, 머지됨)**: 풀면 `wiki-hub` 폴더에 `start-hub.bat`, `start-hub.command`, `읽어주세요.txt`, `hub/` 네 개만 보인다. `/api/download-hub` 는 계정 기능이 켜진 배포에서 로그인한 사람에게만 응답한다(`api/download-hub.ts` 14행).

## 이번 범위 / 범위 밖

### 이번 범위

1. **첫 안내 창** (`LocalHubOnboarding`) 신규. 표시 조건, 분기, 기록은 아래 설계를 따른다.
2. **공유 부품** `LocalHubGuide`: CliStatus 설정 창의 배포 분기를 이리로 옮긴다(동작은 같다).
3. **대시보드 패널의 다시 보기 진입점**: 버튼 이름은 그대로 두고 설명 한 줄을 더한다.
4. 안내 창·설정 창 문구 확정(wiki-ux), 계정 상태별 노출 규칙 확정(requests-planner).

### 범위 밖

- 로그인 화면 변경: 로그인 전에는 ZIP을 받을 수 없고, 첫 비밀번호 변경 흐름을 방해한다.
- 서버에 "안내 봤음"을 저장하는 것(`HubAccount` 필드 추가, `api/auth`·`api/users` 변경): dev-server 작업이 생기고 계정 저장소 구조가 바뀐다. 열린 질문 2에서 정한다.
- 배포 허브에서 내 Claude Code·Codex 계정을 바로 연결하는 것(로그인 위임·키 등록): CLI는 실무자 PC에서만 돈다. 실무자 계정 자격을 배포 서버에 맡기는 것은 보안 검토 대상이다.
- 로컬 허브의 setup 질문 순서·문구: 이미 설치와 로그인까지 묻는다. 이번 문제는 안내를 앞으로 꺼내는 것이다.
- OS별 ZIP, 바로가기 업데이트 문제: `2026-11-12-hub-download-layout.md` 열린 질문 2·3에서 다룬다.
- 로컬 허브의 작성자 기록(데모 계정 이름으로 남는 문제): 별도 계정 흐름이 필요하다. 열린 질문 5에서 안내 문구만 정한다.
- 답변 품질 비교 문구("더 정확하다" 같은 표현): 검증된 근거가 없다. 필요하면 chatbot-planner가 따로 정한다.

## 설계

### 1. 표시 조건 (dev-front, `AppShell` 안에 둔다)

`AuthGate` 는 `AppProvider` 바깥에 있다. 그래서 토스트와 엔진 상태를 쓰는 안내 창은 `AppShell`(AppProvider 안)에 둔다. `AuthGate` 는 고치지 않는다.

```
보여 준다 ⇔
  useAuth().user != null                       // 계정 기능이 켜진 배포 + 로그인함
  && engineStatus !== undefined && !isLocal    // 엔진 상태를 받은 뒤, 로컬이 아님
  && 기록이 'done' 이 아님
  && !(기록이 'later' && 같은 세션에서 이미 봄)  // sessionStorage 로 이번 세션 1회
  && (기록 없음 || 기록.shown < 2)
  && 현재 경로가 '/' (대시보드)                    // 문서 딥링크로 들어온 사람은 방해하지 않음
```

- 경로 조건 때문에 딥링크로 들어온 사람은 다음에 대시보드로 올 때 본다(경로 조건은 열린 질문 6).
- `mustChangePassword` 흐름을 마치면 `AuthGate` 가 바로 허브를 연다. 그러면 위 조건이 그대로 맞아 "첫 로그인 직후"에 뜬다.
- `isLocal` 판단은 CliStatus와 같은 함수를 쓴다. 공유 모듈로 옮긴다(설계 4).

### 2. 기록

| 행동 | 기록 | 다음에 |
| --- | --- | --- |
| "계정이 없어요 · 잘 모르겠어요" → `허브 시작하기` | `done` | 자동으로 다시 뜨지 않는다 |
| "있어요" → `로컬 허브 내려받기` 성공 | `done` | 자동으로 다시 뜨지 않는다 |
| `다음에`, 닫기, Esc, 바깥 클릭 | `later`, `shown += 1` | 다음 세션에 한 번 더 뜬다. 2회째 뒤에는 뜨지 않는다 |
| 다시 보기(대시보드 버튼)로 연 경우 | 기록을 바꾸지 않는다 | — |

"다음에" 로 닫으면 토스트를 띄운다: `대시보드 "챗봇 답변 엔진 → 내 PC에서 쓰기"에서 언제든 다시 볼 수 있습니다`

- 선택지는 처음에는 아무것도 고르지 않은 상태로 둔다. 둘 중 하나를 고르면 아래 내용이 펼쳐진다. 목업은 고른 뒤의 상태를 보여 준다.
- 버튼은 `src/styles.css` 규칙을 따른다. 주 동작(`로컬 허브 내려받기`, `허브 시작하기`)은 `.btn.primary` 하나만 쓴다. `다음에`·`닫기` 는 `.btn.sm` 기본형이다. `.btn.accent`(빨강)는 CLI 로그인처럼 상태 경고에만 쓰는 기존 쓰임새를 유지하고, 여기서는 쓰지 않는다.
- Windows/Mac 전환은 기존 `.cli-os` 표시와 `.cli-os-switch` 링크를 그대로 쓴다. 처음 값은 `detectOs()` 로 정한다.
- 화면 문구의 엔진 이름: 배포 허브에서 실무자는 "Gemini"를 몰라도 된다. 그래서 안내 창에는 "공용 AI 엔진"이라고 쓴다. 설정 창의 기존 "Gemini API" 표기는 그대로 둔다(열린 질문 7).
- 신규 CSS는 `.onb-modal`(560px, 창 안 스크롤), `.onb-choice`(선택지 두 칸), `.onb-foot`(바닥 줄)이다. 나머지는 기존 클래스를 쓴다.
- 목업에서 확인한 점: 폴더 보조 한 줄(muted)이 "됩니/다"처럼 음절 중간에서 끊겼다. 안내 창 본문에 `word-break: keep-all` 을 준다. 기존 설정 창에도 같은 줄이 있어 공유 부품에서 같이 고쳐진다.
- 목업: `login-onboarding.html`(상태 5개: 첫 화면, Windows, Mac, 없어요, 다시 보기). 정적 파일이라 저장소에는 넣지 않는다. PR이나 wiki-ux 문서에 캡처로 붙인다.

## 수용 기준

**표시 조건 (dev-front 검증, 브라우저 저장소를 비운 상태에서 시작)**

1. 계정 기능이 켜진 배포(또는 `/api/auth` 를 흉내 낸 로컬 빌드)에서 임시 비밀번호로 로그인하고 비밀번호를 바꾸면, 대시보드가 열리면서 안내 창이 한 번 뜬다.
2. 같은 계정으로 이미 안내를 `done` 처리한 브라우저에서 다시 로그인하면 안내 창이 뜨지 않는다.
3. `다음에` 를 누르고 같은 탭에서 다른 화면을 오가다가 대시보드로 돌아와도 다시 뜨지 않는다. 로그아웃 후 다시 로그인하면 한 번 더 뜬다. 거기서 다시 `다음에` 를 누르면 세 번째 로그인에서는 뜨지 않는다.
4. 계정 A가 `done` 처리한 같은 브라우저에서 계정 B로 로그인하면 B에게는 뜬다.
5. 로컬 허브(`npm run dev`, CLI 상태가 응답에 있음)와 계정 기능이 꺼진 데모 모드에서는 안내 창이 뜨지 않는다(열린 질문 1의 결정에 따라 데모 모드 기준은 바뀔 수 있다).
6. `/wiki/<문서>` 주소로 바로 들어오면 안내 창이 뜨지 않는다. 그 세션에서 대시보드로 이동하면 뜬다.
7. 엔진 상태를 확인하는 동안(`engineStatus === undefined`)에는 안내 창이 뜨지 않는다. 확인이 끝나고 배포로 판정되면 뜬다.

**화면 (dev-front 검증, 1280×800과 1440×900에서 캡처)**

8. 안내 창을 처음 열면 선택지 두 개가 보이고 아무것도 고르지 않은 상태다. "있어요"를 누르면 4단계 안내와 `로컬 허브 내려받기` 버튼이 보이고, "없어요"를 누르면 한 줄 안내와 `허브 시작하기` 버튼이 보인다. 둘을 오가도 창 크기가 화면 밖으로 넘치지 않는다(800px 높이에서 창 안 스크롤로 다 볼 수 있다).
9. Windows로 판정된 브라우저는 3단계에 `start-hub` 와 "Windows 배치 파일"이 함께 보인다. `Mac 안내 보기` 를 누르면 3단계가 `start-hub.command` 를 "우클릭 → 열기"로 바꿔 보여 주고, 링크 글자가 `Windows 안내 보기` 로 바뀐다.

## 열린 질문

1. **지금 배포는 데모 모드(로그인 없음)입니다.** 계정 기능을 켜기 전까지는 "첫 로그인"이 없어서 이 안내가 아무에게도 뜨지 않습니다. 계정 기능을 켤 때까지 기다릴까요, 아니면 데모 모드에서도 "브라우저당 1회"로 띄울까요? PM 의견: 계정 기능을 켜는 일정이 2주 넘게 남았다면 데모 모드에서도 브라우저 기준으로 띄우는 것이 낫습니다. 그 경우 로컬 허브(역시 데모)와 구분하는 기준은 `isLocal` 하나뿐이 됩니다.
2. **안내 기록을 서버에 둘까요?** 지금 제안은 브라우저 저장입니다. 이 경우 PC나 브라우저를 바꾸면 다시 뜹니다. 서버에 두면 dev-server가 `HubAccount` 에 필드를 하나 더하고 `api/auth` 에 동작을 하나 추가해야 합니다. PM 의견: 이번에는 브라우저 저장으로 하고, 다시 뜬다는 문의가 생기면 그때 서버로 옮깁니다.
3. **"다음에"를 누른 사람에게 몇 번 더 보여 줄까요?** 제안은 1회 더(총 2회)입니다. 0회(바로 끝)나 7일 뒤 1회도 고를 수 있습니다.
4. **다시 보기 진입점을 더 둘까요?** 지금은 대시보드 패널 하나입니다. 챗봇 창의 엔진 선택 줄(Claude·Codex가 비활성으로 보이는 곳)과 사이드바 아래 계정 줄도 후보입니다. PM 의견: 챗봇 창 엔진 줄이 실제로 Claude·Codex를 누르려다 막히는 순간이라 효과가 가장 클 것 같습니다. 다만 이번 범위에는 넣지 않았습니다.
