# 로컬 허브 첫 세팅 — 초보자가 판단할 일 없이 끝나게

상위 지시: 초보자가 "로컬 허브로 내 Claude Code·Codex 계정 쓰기"를 끝내기까지의 전 과정을 점검하고, 각 단계를 "알아서 처리" 또는 "초보자 말투로 쉽게"로 바꾸는 개편안을 낸다. 코드는 고치지 않는다.

상위 지시자 원칙(2026-11-12 새로 정함): **"이 위키 허브는 AI에 익숙하지 않은 초보자가 많이 쓴다. 꼭 다 알아서 해 줄 수 있어야 한다. 아니면 다 초보자 관점에서 쉽게."**

이 문서는 그 원칙을 로컬 허브 세팅 여정에 적용한 첫 기획이다. 판단 순서는 이렇다.

1. 묻지 않고 **알아서 처리**할 수 있는가 → 그렇게 한다.
2. 꼭 물어야 하는가 → **처음에 한 번**, 쉬운 한국어로, 번호나 버튼으로 묻는다.
3. 실패했는가 → 영어 원문 대신 **"지금 할 일" 한 줄과 로그 파일 위치**를 보여 준다.

---

## 문제

**누가**: 편성·마케팅 실무자. AI 도구에 익숙하지 않다. 검은 창(명령 프롬프트·터미널)을 거의 열어 본 적이 없고, Node.js·npm·CLI가 무엇인지 모른다. 회사 PC를 쓰므로 관리자 권한이 없을 수 있고, 회사망 보안 장비가 일부 접속을 막을 수 있다.

**상황**: 배포 허브 첫 안내 창에서 "Claude Code·Codex 계정이 있어요"를 고르고 ZIP을 받는다. 그다음부터는 검은 창이 하는 말을 혼자 읽고 판단해야 한다.

**못 하고 있는 것**

| 실무자가 원하는 것 | 지금 일어나는 일 | 원인 |
| --- | --- | --- |
| 받은 파일을 더블클릭하면 끝나기를 바란다 | 검은 창이 `(Y/N)` 질문을 최대 5번 한다(Node.js 1번, CLI 설치 2번, 로그인 2번). 화면 안내는 "쓰지 않는 쪽은 N"을 고르라고 한다 | `scripts/setup.ps1`, `start-hub.command` 가 단계마다 `Ask`/`ask` 로 묻는다 |
| 무엇을 묻는지 이해하고 싶다 | 질문에 `Node.js LTS`, `claude CLI`, `Homebrew`, `.msi` 같은 말이 그대로 나온다 | 개발자용 문구가 그대로 남아 있다 |
| 설치가 막히면 무엇을 하면 되는지 알고 싶다 | 2026-11-12에 실제로 winget이 Microsoft Store 원본 SSL 오류와 "--source를 지정하라"는 영어·한국어 혼합 메시지를 내고 멈췄다. 실무자는 다음에 할 일을 알 수 없었다 | 외부 도구(winget·msiexec·npm·brew·claude·codex·vite) 출력이 창에 그대로 나온다. 실패 문구도 원문 예외 메시지를 그대로 붙인다 |
| 보안 경고를 지나가고 싶다 | Windows "Windows의 PC 보호"(SmartScreen) 창에서 멈춘다. 안내 어디에도 "추가 정보 → 실행"이 없다 | 가이드와 `읽어주세요.txt` 에 보안 경고 단계가 빠져 있다 |
| 실패해도 다시 하면 되기를 바란다 | 몇몇 실패는 다음 행동 없이 창이 끝난다(Mac에 Homebrew가 없음, npm 권한 오류, 패키지 설치 실패) | 실패 뒤 다음 단계가 설계돼 있지 않다 |

**목표**: 초보자는 ZIP을 받은 뒤 **(1) 압축 풀기, (2) start-hub 더블클릭(보안 경고 통과 포함), (3) 브라우저에서 내 계정 로그인** 세 가지만 한다. 그 밖에 판단할 일은 없다.

## 현재 상태 (확인한 파일 경로 포함)

확인한 파일:

- `src/components/LocalHubOnboarding.tsx`
- `src/components/LocalHubGuide.tsx`
- `src/components/CliStatus.tsx`
- `src/lib/localHub.ts`
- `start-hub.bat`
- `scripts/setup.ps1` (PR #57 적용본, 이 브랜치 HEAD `8f9f474`)
- `start-hub.command`
- `server/hubZipRoot.ts`
- `server/hubZip.ts`
- `server/cliBridge.ts`(로그인 창 띄우기 113~129행)
- `vite.config.ts`
- `.gitattributes`

**전제**

- ZIP은 `server/hubZip.ts` `proxyHubZip` 이 GitHub **기본 브랜치** zipball을 받아 다시 묶어 만든다. **기본 브랜치에 머지되기 전의 수정은 실무자가 받는 ZIP에 들어가지 않는다.**
- ZIP 루트 구성은 `start-hub.bat`(ASCII 얇은 실행기), `start-hub.command`, `읽어주세요.txt`, `hub/` 다. 실제 실행기는 `hub/start-hub.bat` → `hub/scripts/setup.ps1`, Mac은 `hub/start-hub.command` 다(`server/hubZipRoot.ts`).
- 로컬 허브에서는 CLI가 연결돼 있지 않으면 Gemini API로 답한다. 그런데 Gemini 키는 실무자가 `.env.local` 을 직접 만들어야 생긴다(`CliStatus.tsx` 470~473행). **초보자의 로컬 허브에는 Gemini 키가 없으므로, CLI 로그인에 실패하면 규칙 기반 답변만 나온다.** 배포 허브(Gemini)보다 답이 나빠진다.

### 범위 밖

- **코드 서명(Windows Authenticode, Apple 공증)으로 보안 경고 자체를 없애는 일**: 인증서 비용과 발급 절차가 필요하다. 이 개편에서는 안내로 대신하고, 필요하면 별도 기획으로 다룬다.
- **설치 마법사형 앱(Electron·설치 프로그램 패키징)으로 바꾸는 일**: 배포·업데이트 구조가 통째로 바뀐다. 이번 개편으로 판단 지점을 없앤 뒤에도 부족하면 다시 검토한다.
- **로컬 허브 자동 업데이트(새 버전 알림·덮어쓰기)**: 첫 세팅 여정과 별개다. 별도 기획이다.
- **Linux 지원**: 대상 실무자가 쓰지 않는다.
- **배포 허브에서 CLI를 직접 연결하는 일**: CLI는 실무자 PC에서만 돌 수 있다. 구조상 불가능하다.
- **Gemini API 키 발급 안내 개편**: 초보자 여정의 필수 단계가 아니다. P1-4에서 "고급 설정"으로 접는 데서 멈춘다.
- **CLAUDE.md 직접 수정**: 지시대로 원칙 초안만 이 문서에 둔다. 반영은 PM 데스크가 승인받은 뒤 한다.

## 수용 기준

**검증 환경**(ops가 준비한다)

- W1: Windows 11, Node 없음, **관리자 권한 없는 일반 사용자**
- W2: Windows 10, Node 없음, winget의 msstore 원본이 고장 난 상태(SSL·인증서 폐기 확인 실패 재현)
- M1: macOS 15, Homebrew 없음, Node 없음
- M2: macOS 14, Homebrew 있음

**종합 기준 (P0 완료 판정)**

1. **AC-0 (전체)**: W1·W2·M1·M2에서 초보자가 하는 일이 다음뿐이다. ① 배포 허브에서 계정 종류 선택, ② ZIP 압축 풀기, ③ start-hub 더블클릭과 보안 경고 통과(안내 문구대로), ④ 브라우저 로그인. 이 밖의 **키보드 입력은 0회**이고, 그 상태로 브라우저에 로컬 허브가 열린다.

**세부 기준**

2. **AC-1 (질문 수)**: 배포 허브 안내 창에서 계정을 고른 뒤 받은 ZIP으로 실행하면, 검은 창의 질문은 **0개**다. 계정을 고르지 않고 받은 ZIP이면 질문은 **번호로 답하는 1개**다. `scripts/setup.ps1`·`start-hub.command` 에 `(Y/N)` 문자열이 없다(grep 0건).
3. **AC-2 (Node 자동 설치)**: W1·W2·M1에서 Node 설치 단계가 묻지 않고 진행된다. 관리자 비밀번호 입력 없이 끝나야 한다(A안 채택 시. B안이면 W1은 "막혔을 때 안내" 기준으로 판정한다).
4. **AC-3 (원문 출력 숨김)**: 정상 진행 중 창에 보이는 줄은 모두 한국어 진행 줄이다. winget·msiexec·npm·brew·claude·codex·vite 출력은 창에 나오지 않고 로그 파일에 남는다. 단, CLI가 브라우저 대신 터미널 입력을 요구하는 경우는 열린 질문 8의 결론에 따른다.
5. **AC-4 (막다른 길 없음)**: 다음 실패를 하나씩 일부러 내면, 매번 창에 ① 한국어 "지금 할 일" 한 줄과 ② 로그 파일 경로가 나오고 ③ 로그가 있는 폴더가 열린다.
   - Node 설치 실패
   - CLI 설치 실패
   - 로그인 미완료
   - 패키지 설치 실패
   - 회사망 인증서 오류
   - ZIP 안에서 실행
   - 이미 켜진 상태에서 재실행

   다음 행동 없이 창이 끝나는 경우는 0건이다.
6. **AC-5 (계정 연결 실패는 허브를 막지 않음)**: CLI 설치나 로그인에 실패해도 허브는 열린다. 창과 허브 화면에 "나중에 [로그인] 버튼으로 다시 할 수 있어요"가 보인다.
7. **AC-6 (안내 문구)**: `LocalHubGuide.tsx` 와 `readmeText` 출력에 다음이 들어 있다.
   - Windows: "Windows의 PC 보호", "추가 정보", "실행"
   - Mac: 보안 허용 경로(시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기)

   다음 말은 나오지 않는다(grep 0건): `Y를`, `N)`, `CLI`, `npm`, `winget`, `LTS`, `.msi`, `터미널에서`.
8. **AC-7 (재실행)**: 설치를 마친 PC에서 바탕화면 아이콘을 누르면 질문 0개로 브라우저가 열린다. 이미 켜진 상태에서 다시 누르면 새 포트로 하나 더 뜨지 않고 기존 허브(5173)가 열린다(P1-3).
9. **AC-8 (로그)**: 로그 파일이 한 곳에 하나 생기고, 단계별 시작·끝·종료 코드가 남는다. 계정 비밀번호와 토큰은 남지 않는다.
10. **AC-9 (호환)**: `setup.ps1` 은 Windows PowerShell 5.1에서 동작하고 UTF-8 BOM을 유지한다. 루트 `start-hub.bat` 은 ASCII + CRLF를 유지한다(`hubZipRoot.ts` 주석의 제약). `--check` 모드는 여전히 아무것도 설치하지 않는다.
11. **AC-10 (빌드)**: `npm run build` 가 통과한다. 공유 경로인 `server/hubZip.ts` 를 바꾸면 배포(`api/download-hub.ts`)와 로컬(`server/cliBridge.ts`) 양쪽에서 ZIP 내려받기를 확인한다.
