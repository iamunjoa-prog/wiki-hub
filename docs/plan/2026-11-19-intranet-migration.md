# 위키 사내 서버 이전 — 올해는 문서 보기만, 챗봇은 내년

작성 `plan-pm` · 2026-11-19
상위 지시: "올해 예산이 소진돼 유료 결제를 못 한다. 올해는 위키(문서 보기)만 사내 서버로 옮기고, 챗봇은 내년 예산·결재 뒤 사내 서버에 연결한다."
코드는 건드리지 않는다. 이 문서는 요구사항·범위·수용 기준·담당 분배와, 상위 지시자가 골라야 할 항목을 정리한다.

## 문제

| 누가 | 어떤 상황에서 | 무엇을 못 하나 |
| --- | --- | --- |
| 편성·마케팅 실무자 20명 | 업무를 모두 클라우드 PC(이하 클피)에서 한다. 클피는 외부 인터넷에 나갈 수 없다 | 지금 허브는 외부 배포(Vercel)에 있어 클피에서 열 수 없다. 위키 문서를 근거로 확인하려면 클피 밖 PC를 따로 써야 한다 |
| 허브 운영 담당 | 올해 예산이 소진돼 Vercel Pro·Gemini 유료로 전환할 수 없다 | 지금 쓰는 Vercel 무료(Hobby) 플랜은 비상업 약관이라 업무용으로 쓰기 곤란하고, Gemini 무료 등급은 입력한 내용이 학습에 쓰여 사내 문서를 넣을 수 없다. 지금 구조 그대로는 계속 운영할 방법이 없다 |
| 문서 담당(실무자) | 사내 서버에 올린 위키 문서를 고쳐야 할 때 | 사내에는 npm·Node 빌드 도구가 없다. 지금 화면은 문서를 **빌드할 때** 화면 파일 안에 묶어 넣기 때문에, 문서 한 줄을 고쳐도 외부에서 다시 빌드해 반입해야 한다. 문서 수정이 화면 반입 일정에 묶인다 |

정리하면 올해 할 일은 하나다. **클피에서 위키 문서를 읽을 수 있게 하고, 사내에서 빌드 없이 문서를 고쳐 반영할 수 있게 한다.** 챗봇·요청·승인처럼 서버가 필요한 기능은 올해 사내에서 쓰지 않는다.

### 상위 지시자와 확정된 사실 (11/19)

- 올해 Vercel 유료·Gemini 유료 결제 불가. 무료 플랜은 위 이유로 계속 쓰기 곤란.
- 올해는 위키(문서 보기)만 사내 서버로 이전. 챗봇은 내년 예산·결재 뒤 사내 서버에 연결.
- 클피는 외부 인터넷 불가. 사내 Git(깃허브와 비슷한 서버)과 DB가 있다. 사내 Git은 외부 GitHub와 연결되지 않는다.
- 배포 선례: 영화/시리즈 대시보드를 "파일을 클피로 옮겨 사내 별도 웹서버(이하 플레이그라운드)에 직접 업로드" 하는 방식으로 올렸다. 위키도 같은 길을 쓴다.
- 내년 챗봇: 결재 뒤 사내에서 쓸 수 있는 AI API를 받아 연결할 수 있다(외부 인터넷 직접 접속은 아님).

## 현재 상태 (확인한 파일 경로 포함)

기준: main `cd2d13e` (2026-11-19). 아래는 모두 파일을 직접 읽거나 grep 해서 확인했다.

### 1. 문서는 빌드할 때 화면에 묶인다

- `src/data/knowledgeDocs.ts` — `import.meta.glob('/지식/**/*.md', { query: '?raw', eager: true })` 로 `지식/` 아래 md 를 **빌드 타임에** 문자열로 읽는다. 같은 파일 안에서 프론트매터를 풀고(`parseFrontmatter`), parent→order 로 트리를 펴서(`flattenTree`) `knowledgeDocs` 를 만든다. 프론트매터에 `code` 가 없는 파일(`지식/README.md` 등)은 빠진다.
- `src/data/docs.ts` — `knowledgeDocs` 를 사이드바 순서(`docRank`)로 다시 정렬해 `docs` 로 내보낸다. 카테고리·서브메뉴 정의도 여기 있다.
- `docs` 를 **모듈 상수로 바로 import** 하는 곳: `src/store/AppStore.tsx`(초기 문서 목록), `src/lib/retrieval.ts`(검색 점수), `src/lib/assistant.ts`(챗봇), 그리고 화면 `src/pages/WikiDoc.tsx`, `WikiIndex.tsx`, `Dashboard.tsx`, `SearchResults.tsx`, `NewDoc.tsx`, `Approvals.tsx`, `src/components/AppShell.tsx`(카테고리). 즉 문서를 런타임에 읽게 바꾸면 "문서가 다 올 때까지 기다렸다가 화면을 그리는" 자리가 하나 필요하다.
- `지식/` — md 44개, 그중 `code` 가 있는 위키 문서 42개. 용량 약 340KB. 문서 안에 이미지 첨부는 없다(`![` 없음). 파일 이름은 모두 영문, 최상위 폴더 이름만 한글(`지식`).
- `scripts/check-anchors.mjs` — 문서 간 링크·소제목 앵커를 검사하는 Node 스크립트. 사내에서는 돌릴 수 없다.

### 3. 정적 서버에 그대로 올리면 깨지는 곳

- **라우팅**: `src/main.tsx` 가 `BrowserRouter` 를 쓴다. 주소가 `/wiki/PPC-P-02` 꼴이라, 그 주소로 바로 들어가거나 새로고침하면 웹서버가 모든 경로를 `index.html` 로 돌려줘야 한다. 지금은 `vercel.json` 의 `rewrites` 가 그 일을 한다. 플레이그라운드에 같은 설정이 있는지는 모른다.
- **소제목 앵커**: `src/pages/WikiDoc.tsx` 가 `location.hash`(`#h-...`)로 소제목에 스크롤한다. 본문 링크(`PPC-P-02#h-다크패턴-대응`)도 이 꼴이다. 해시 라우팅(`/#/wiki/...`)으로 바꾸면 주소에 `#` 이 두 번 들어가므로 이 부분을 같이 확인해야 한다.
- **본문 링크**: `WikiDoc.tsx` 의 `mdLink` 가 `<a href="/wiki/...">` 를 만들고 클릭을 가로채 이동한다. 해시 라우팅에서는 가운데 클릭·새 탭 열기가 깨진다.
- **하위 경로**: `vite.config.ts` 에 `base` 설정이 없다(기본 `/`). 플레이그라운드가 앱을 하위 경로(예: `/<앱이름>/`)에 올리면 `assets/` 경로가 깨진다. `src/data/sheets.ts` 의 기존 주소 모양을 보면 하위 경로 방식일 가능성이 높다.
- **외부 글꼴**: `index.html` 이 Pretendard 글꼴을 외부 CDN(jsdelivr)에서 받는다. 클피에서는 못 받아 기본 글꼴로 바뀐다(깨지지는 않지만 화면 줄바꿈이 달라진다).

### 4. 서버 쪽 지식 공유 규칙

- `server/knowledge.ts` — 로컬 중계(`server/cliBridge.ts`)와 배포 함수(`api/*`)가 같이 쓴다. 문서 목록은 `listDocPaths(knowledgeDir)`·`buildDocsBlock(knowledgeDir)` 처럼 **폴더 경로를 받아 파일시스템에서 읽는다.** 화면이 `import.meta.glob` 에 묶인 것과 달리 서버는 이미 "폴더를 읽는" 구조다. 내년 사내 서버도 같은 폴더를 가리키면 된다.
- `vercel.json` — `api/ask.ts` 가 `지식/**` 를 함수에 함께 싣는다(`includeFiles`). 화면 로딩 방식을 바꿔도 배포 챗봇은 영향이 없다.

### 5. 저장소 규칙과 어긋난 점 (이번 범위 밖, 기록만)

- `src/data/systems.ts` 에 시스템 접속 주소가 코드로 남아 있다. CLAUDE.md 는 "시스템 목록의 실제 주소는 코드에 두지 않는다"고 한다. 사내 이전과 별개로 `ops` 확인이 필요하다.

## 이번 범위 / 범위 밖

### 방향 (PM 데스크안을 검증한 결과)

1. **코드와 지식을 나눈다.** 화면 코드는 외부 GitHub에서 계속 개발하고, 빌드한 정적 파일만 가끔 반입한다. 지식 문서는 사내 Git이 원본이 되고, 사내에서는 빌드 없이 문서 폴더만 교체해 반영한다. → 검증: 서버는 이미 폴더를 읽는 구조라 문제없고, 화면만 런타임 로딩으로 바꾸면 된다. 타당하다.
2. **화면이 문서를 런타임에 읽는다.** 서버의 `knowledge/` 폴더에서 목록 JSON 과 md 를 받아 지금과 같은 파싱·정렬을 한다. → 검증: 파싱 함수는 그대로 옮길 수 있다. 문서를 모듈 상수로 import 하는 곳이 많아, **첫 화면을 그리기 전에 문서를 한 번 다 받아 두는 방식**이 고칠 곳이 가장 적다(42개·340KB, 사내망 기준 부담 없음).
3. **사내용 화면 모드**를 따로 빌드한다. 서버가 필요한 기능은 끄거나 안내로 바꾼다. → 검증: 일부 기능은 이미 "경로 없으면 꺼짐" 처리가 있지만, 정적 서버가 `/api/*` 에 404 화면이나 오류 화면을 줄 수 있어 **사내 모드에서는 아예 부르지 않게** 하는 편이 안전하다.
4. 올해 문서 수정은 사내 Git 웹 화면에서 머지 요청으로 한다. 허브의 `수정 제안` 버튼은 안내로 바꾼다.
5. 외부 GitHub `지식/`·Vercel 배포·Gemini 무료 챗봇을 언제 내릴지는 상위 지시자가 정한다(아래 결정 항목).
6. 내년 단계와 막히는 곳이 없는지 아래 [내년 단계 개요](#내년-단계-개요-올해-구조가-막지-않는지)에서 확인했다.

### 서버 문서 폴더 모양 (제안)

```
<플레이그라운드의 위키 앱 폴더>/
  index.html               ← 화면(반입물)
  assets/                  ← 화면(반입물). 글꼴 파일도 여기 포함
  hub-config.json          ← 사내 전용 설정(사내 Git 주소 등). 사내에서만 만든다
  knowledge/               ← 문서(사내 Git이 원본). 화면 반입 때 건드리지 않는다
    index.json
    guide/tour.md
    promotion/ppm.md
    ...
```

- 폴더 이름은 영문 `knowledge/` 로 한다. 한글 폴더 이름은 웹서버·업로드 도구에 따라 주소 인코딩이 깨질 수 있다.
- `index.json` 은 **파일 경로 목록만** 담는다. 제목·카테고리·순서는 지금처럼 각 md 의 프론트매터에서 읽는다. 그래서 **문서 내용·제목을 고칠 때는 `index.json` 을 건드리지 않는다.** 문서를 새로 넣거나 지우거나 이름을 바꿀 때만 한 줄 고친다.

```json
{
  "files": ["guide/tour.md", "promotion/ppm.md", "promotion/ppv.md"]
}
```

- 사내 Git 주소처럼 공개 저장소에 둘 수 없는 값은 `hub-config.json` 에 둔다. 화면은 이 파일이 없어도 동작해야 한다.
- 문서·목록은 브라우저가 매번 서버에 "바뀌었나"를 묻게(`cache: 'no-cache'`) 받는다. 그러면 문서를 바꾼 뒤 날짜·버전 값을 손으로 올리지 않아도 새로고침만으로 반영된다.

### 목록 JSON 을 npm 없이 만드는 방법 (검토)

| 방법 | 필요한 것 | 판단 |
| --- | --- | --- |
| A. 손으로 한 줄 고치기 | 사내 Git 웹 편집기만 | **기본안.** 새 문서·삭제·이름 변경 때만 손댄다(지금 기준 연 몇 회). 같은 머지 요청에 md 와 `index.json` 을 함께 올리게 체크리스트로 막는다 |
| B. 클피에서 목록 만들기 스크립트(PowerShell) 더블클릭 | 클피에서 PowerShell 실행 허용 | 보조안. 허용 여부 **미확인**. 허용되면 `ops` 가 반영 절차에 넣는다 |
| C. 사내 Git 의 자동 실행(CI) | 사내 Git 에 CI 기능·실행기 | 미확인. 있으면 머지할 때 자동 생성 가능 |
| D. 웹서버 폴더 목록 기능 | 플레이그라운드가 폴더 목록을 보여 줌 | 비추천. 서버 설정에 묶이고 모양이 서버마다 다르다 |

A 의 약점(목록에 안 넣은 새 문서는 화면에 안 보임)을 줄이기 위해 화면은 **목록에 있는데 파일을 못 받은 문서**를 위키 문서 목록 위에 한 줄로 알린다. 목록에 없는 파일은 정적 서버에서 알아낼 방법이 없으므로, 머지 요청 체크리스트로 막는다.

### 범위 밖

| 하지 않는 것 | 이유 |
| --- | --- |
| 사내 서버에서 챗봇 동작 | 내년 예산·결재 뒤 사내 AI API 를 받아야 한다 |
| 사내 로그인·계정·요청 기록(DB 연결) | 정적 서버에는 실행 환경이 없다. 클피 접속 자체가 사내 인증이라 올해는 로그인 없이 연다. 내년 사내 Node 서버와 함께 한다 |
| 편성표(B tv·빅배너)·Jira 스케줄 화면 | 외부 스프레드시트·외부 Jira 를 서버가 중계해야 하는데 사내에는 서버도 외부 인터넷도 없다 |
| 허브 안에서 문서 직접 편집·새 문서 작성 | 서버가 필요하다. 올해는 사내 Git 웹 화면에서 한다 |

| 문서 링크 검사(`check-anchors`) 사내 실행 | Node 가 필요하다. 깨진 링크는 화면이 "문서를 찾을 수 없음"으로 보여 주는 지금 동작에 맡긴다 |
| `src/data/systems.ts` 주소 정리 | 사내 이전과 별개다. `ops` 에 기록만 넘긴다 |
| 외부 Vercel 배포·Gemini 챗봇 내리기 실행 | 상위 지시자 결정 뒤 별도 작업으로 한다 |

## 수용 기준

### 문서 런타임 로딩

1. 사내 모드 빌드 결과 폴더에 `.md` 파일이 하나도 없고, 화면 자바스크립트 안에 문서 본문 문자열이 들어 있지 않다(예: `grep -r "PPC-P-02" dist-intranet/assets` 결과 0건).
2. 같은 `지식/` 묶음으로 열었을 때 런타임 로딩 화면의 위키 문서 목록(문서 수·순서·제목)이 지금 main 빌드와 똑같다(현재 42개).
3. 서버의 `knowledge/` 에 md 하나와 `index.json` 한 줄을 추가하고 **다시 빌드하지 않은 채** 브라우저를 새로고침하면, 새 문서가 사이드바와 위키 문서 목록에 나타난다.
4. 기존 md 의 본문 한 줄만 고쳐 올리면 `index.json` 을 건드리지 않고도 새로고침 한 번에 바뀐 내용이 보인다.
5. `index.json` 에 있는데 파일이 없는 경로가 있으면, 나머지 문서는 정상으로 보이고 위키 문서 목록 위에 "문서 N개를 불러오지 못했습니다" 와 해당 경로가 한 줄로 보인다.
6. `index.json` 자체를 못 받으면 빈 화면이 아니라 "문서 목록을 불러오지 못했습니다 — 지금 할 일: 관리자에게 알려 주세요" 안내가 보인다.
7. 외부 배포용 빌드(`npm run build`)를 Vercel 에 올렸을 때 문서 목록·본문이 지금과 같고, 배포 챗봇(`/api/ask`)의 근거 인용도 그대로 동작한다.

### 사내 모드 화면

8. 사내 모드에서 메인 → 위키 문서 목록 → 문서 → 검색을 차례로 열어도 브라우저 개발자 도구 네트워크 탭에 `/api/` 요청이 0건이다.
9. 사내 모드에서 외부 주소 요청이 0건이다(글꼴 포함). `grep -r "cdn.jsdelivr" dist-intranet` 결과 0건.
10. 오른쪽 아래 `챗봇` 버튼, 사이드바의 `내 요청 현황`·`승인 관리`·`계정 관리`·`Jira 스케줄 확인`, 편성표 메뉴가 사내 모드에서 보이지 않는다(남길지 여부는 Y1 확정안을 따른다).
11. 문서 화면의 `✎ 수정 제안` 자리에 `수정 요청 방법` 버튼이 있고, 누르면 그 문서의 파일 경로(예: `promotion/ppm.md`)와 사내 Git 에서 머지 요청을 올리는 순서가 보인다. `hub-config.json` 에 사내 Git 주소가 있으면 그 주소로 가는 링크가, 없으면 경로만 보인다.
12. 꺼진 화면의 주소(예: 새 문서, 승인 관리)로 직접 들어가면 오류가 아니라 "사내 허브에서는 아직 쓰지 않는 기능입니다" 안내와 위키로 돌아가는 버튼이 보인다.
13. 로그인 화면 없이 바로 열린다.

### 정적 서버·주소

14. 아무 설정 없는 정적 웹서버(예: 테스트용 `python -m http.server`)에서 **하위 경로**(`/wiki-test/`)에 올려도 화면·글꼴·문서가 모두 열린다.
15. 문서 주소(예: `.../#/wiki/PPC-P-02`)를 새 탭에 붙여 넣거나 새로고침해도 같은 문서가 열린다.
16. 소제목까지 붙은 주소로 들어가면 그 소제목으로 스크롤되고, 본문 안의 문서 링크를 가운데 클릭하면 새 탭에서 그 문서가 열린다.

### 공개 저장소 규칙

17. 이번 작업의 diff 에 사내 서버 주소·사내 Git 주소·제휴사 실명·금액이 0건이다. 사내 주소는 `hub-config.json`(사내에서만 만듦)에만 있다.

### 절차

18. `ops` 가 쓴 반입·반영 절차대로 개발자가 아닌 실무자 1명이 도움 없이 (a) 문서 1개 수정 반영, (b) 화면 새 버전 반입을 끝낸다. 막힌 단계는 절차 문서에 고쳐 넣는다.

## 반입·반영 절차 초안 (초보자 기준)

`ops` 가 Y0 결과로 확정한다. 여기서는 순서만 잡는다. 최종본은 사내 주소가 들어가므로 **사내 Git 에만** 둔다.

### A. 문서 고치기 (자주 — 문서 담당 누구나)

1. 클피에서 사내 Git 웹 화면을 열고 위키 문서 저장소로 들어간다.
2. 고칠 파일을 연다. 허브 문서 화면의 `수정 요청 방법` 을 누르면 파일 경로가 보인다(예: `promotion/ppm.md`).
3. 연필(편집) 버튼을 누르고 내용을 고친다. 맨 위 `---` 사이의 `updatedAt`(오늘 날짜)·`updatedBy`(내 이름)도 고친다.
4. 아래 설명 칸에 "무엇을 왜 바꿨는지" 한 줄을 쓰고, **새 브랜치로 저장 → 머지 요청 만들기**를 누른다.
5. 승인자가 확인하고 머지한다.
6. 반영 담당이 B 를 한다.

새 문서를 만들 때는 3번에서 새 파일을 만들고, **같은 머지 요청에서** `index.json` 의 `files` 에 새 파일 경로를 한 줄 추가한다. 문서를 지우거나 이름을 바꿀 때도 같다.

### B. 고친 문서를 허브에 반영하기 (머지 뒤 — 반영 담당)

1. 사내 Git 저장소 화면에서 **zip 으로 내려받기**를 누른다.
2. 내려받은 zip 을 오른쪽 클릭 → `압축 풀기`.
3. 플레이그라운드 관리 화면을 열고 위키 앱의 `knowledge` 폴더를 고른다.
4. 압축 푼 폴더의 내용을 `knowledge` 폴더에 업로드해 덮어쓴다. **`index.html`·`assets` 는 건드리지 않는다.**
5. 허브를 열고 `Ctrl + F5` 로 새로고침해 고친 문서를 확인한다.
6. 위키 문서 목록 위에 "문서 N개를 불러오지 못했습니다" 가 보이면 `index.json` 의 경로와 실제 파일 이름이 같은지 확인한다.

### C. 화면 새 버전 반입하기 (드묾 — 반영 담당)

1. 외부에서 `dev-front` 가 사내 모드로 빌드한 zip(`wiki-hub-intranet-<날짜>.zip`, 문서 미포함)을 받는다.
2. 대시보드 때와 같은 반입 절차로 클피에 옮긴다.
3. 클피에서 zip 을 압축 푼다.
4. 플레이그라운드에 올리기 **전에**, 지금 올라가 있는 `index.html`·`assets` 를 `이전버전_<날짜>` 폴더로 내려받아 둔다(되돌리기용).
5. 압축 푼 `index.html`·`assets` 만 올린다. `knowledge`·`hub-config.json` 은 건드리지 않는다. (Y0 에서 "업로드가 폴더 전체를 갈아엎는다"로 확인되면, 사내 Git 에서 받은 `knowledge` 와 `hub-config.json` 을 같이 올리는 순서로 바꾼다.)
6. 허브를 열고 확인: 메인 → 위키 문서 목록 → 문서 하나 → 검색. 이상하면 4번에서 받아 둔 이전 버전을 다시 올린다.

| 화면 반입 업로드가 `knowledge/` 까지 지운다 | 사내 문서가 사라진 채 열린다 | Y0 에서 업로드 방식 확인. 절차 C 4·5번. 원본은 사내 Git 에 있으므로 B 로 복구 가능 |
| 플레이그라운드가 하위 경로·SPA 설정을 지원하지 않는다 | 새로고침·주소 공유 때 404 | 해시 라우팅 + `base` 상대 경로를 기본으로 구현(수용 기준 14·15) |
| 해시 라우팅과 소제목 앵커(`#h-...`)가 겹친다 | 소제목 링크가 안 먹힌다 | dev-front 가 수용 기준 16 으로 확인. 필요하면 소제목을 쿼리 값으로 옮긴다 |
| `index.json` 과 실제 파일이 어긋난다 | 새 문서가 안 보이거나 빈 문서 | 머지 요청 체크리스트(Y2) + 화면 경고 줄(수용 기준 5) |
| 브라우저·서버 캐시로 옛 문서가 보인다 | 고쳤는데 안 바뀐 것으로 보임 | `no-cache` 로 받기. Y0 에서 서버 캐시 헤더 확인 |
| 병행 기간에 외부 `지식/` 과 사내 Git 이 둘 다 고쳐진다 | 원본이 둘이 되어 한쪽 수정이 사라진다 | 이관일을 정해 그날부터 외부 `지식/` 수정 중단(결정 D1) |
| 사내 문서를 외부 저장소로 옮겨 적는다 | 공개 저장소 규칙 위반(금액·제휴사 실명) | 사내 → 외부 방향 흐름은 만들지 않는다. 외부 견본 문서 갱신은 외부에서만(결정 D1·D9) |
| 사내에서 링크 검사를 못 돌린다 | 깨진 문서 링크가 쌓인다 | 화면의 "찾을 수 없음" 표시. 내년 사내 Node 서버에서 검사 재개 |
| 반입 승인에 시간이 걸린다 | 화면 버그 수정이 늦다 | 화면 반입은 묶어서 드물게. 문서 수정은 반입과 무관(이번 구조의 목적) |
| Gemini 무료 등급 챗봇이 계속 켜져 있다 | 실무자가 사내 내용을 입력하면 학습에 쓰인다 | 결정 D3 |

## 내년 단계 개요 (올해 구조가 막지 않는지)

내년 예산·결재 뒤 사내에 Node 서버를 두고 사내 AI API·사내 DB 를 연결한다.

| 내년에 할 것 | 올해 구조와의 관계 |
| --- | --- |
| 사내 Node 서버에서 `server/` 코드 실행, 같은 앱 폴더의 `knowledge/` 를 읽음 | `server/knowledge.ts` 는 이미 폴더 경로를 받아 읽는다. 올해 `knowledge/` 폴더가 그대로 근거 문서가 된다. **막지 않음** |
| 챗봇을 사내 AI API 로 연결 | `server/` 의 엔진 선택 자리에 사내 API 어댑터를 하나 더한다(`chatbot-planner` 가 대화 규약 점검, `dev-server` 구현). 화면은 사내 모드 플래그에서 챗봇만 다시 켠다. **막지 않음** |
| 계정·대화 이력·요청 기록을 사내 DB 로 | 지금 계정은 외부 Redis(`server/accounts.ts`)에 있다. 저장 창구가 한 파일에 모여 있어 DB 로 바꾸기 쉽다. `AuthGate` 는 `/api/auth` 가 생기면 자동으로 로그인 화면을 띄운다. **막지 않음** |
| 허브 안 수정 제안 → 사내 Git 머지 요청 자동 생성 | 지금은 외부 GitHub PR(`server/github.ts`). 사내 Git 에 API 가 있어야 한다(Y0 확인). 없으면 올해 방식(웹 화면 안내)을 유지 |
| 시스템 목록을 사내 DB 로 | `server/systemsFile.ts` 가 "DB 가 생기기 전까지의 자리"로 창구를 모아 두었다. **막지 않음** |
| 라우팅 | 서버가 생기면 모든 경로→`index.html` 을 직접 줄 수 있어 일반 주소로 되돌릴 수 있다. 해시 주소로 저장해 둔 즐겨찾기가 깨지지 않게 한동안 둘 다 받는다 |

올해 사내 모드는 "기능별로 켜고 끄는 플래그" 로 만든다(한 덩어리 스위치가 아니라). 내년에는 서버가 생긴 기능부터 하나씩 켠다.

## 상위 지시자 결정 항목

| 항목 | 현재 | 제안 | 영향 | PM 의견 |
| --- | --- | --- | --- | --- |
| D1. 외부 GitHub `지식/` | 위키 문서의 원본 | 사내 Git 이관일을 정하고, 그날부터 외부 `지식/` 은 **개발용 견본**으로 동결(실무 수정 중단) | 원본이 하나로 정리된다. 외부 Vercel 화면 문서는 이관일 기준으로 멈춘다 | 동결 권장. 완전 삭제는 개발·Vercel 이 견본을 써야 하므로 비추천 |
| D2. Vercel 배포를 내리는 시점 | 운영 중(무료 Hobby 플랜 — 약관상 업무용 부적합) | 사내 위키 첫 업로드 + 실무자 리허설(수용 기준 18) 통과 뒤 1~2주 병행하고 내림 | 병행 동안 실무자가 두 주소를 쓴다 | 병행 기간은 최소로. 약관 위험이 있어 오래 두지 않기를 권장 |
| D3. Gemini 무료 챗봇 | 배포 챗봇이 쓸 수 있음(엔진 목록) | **사내 위키 오픈과 상관없이 지금 바로** 배포 환경에서 Gemini 키를 빼서 끈다 | 배포 허브 챗봇이 꺼지거나 다른 엔진만 남는다 | 즉시 끄기 권장. 입력 학습 위험은 기다릴 이유가 없다 |
| D4. 목록 JSON 관리 | 없음(빌드가 폴더를 읽음) | 손으로 한 줄 고치기(방법 A)를 기본. PowerShell·CI 가 확인되면 보조로 추가 | 새 문서 때마다 한 줄 손질 | A 권장. 도구 없이 오늘 바로 되는 유일한 방법 |
| D5. 주소 방식 | 일반 주소(`/wiki/...`) | 해시 주소(`/#/wiki/...`). Y0 에서 서버 설정이 가능하면 일반 주소 유지 | 해시 주소는 보기에 덜 깔끔하지만 서버 설정이 필요 없다 | Y0 결과로 정하되 기본은 해시 |
| D6. 시스템 바로가기 화면 | 공유 드라이브 JSON 을 로컬 허브가 읽음 | 사내 모드에서는 앱 폴더의 `systems.json`(사내에서만 작성)을 **읽기 전용**으로 보여 줌. 요청·승인은 끔 | 클피에서 시스템 주소를 한곳에서 찾는다. 주소는 사내에만 있다 | 권장. 실무자 체감이 크고 공개 저장소 규칙과도 맞다. 숨김도 가능 |
| D7. Target 캠페인 달력 화면 | 사내 플레이그라운드 쪽 API 를 화면이 직접 부름 | Y0 에서 클피 접속이 확인되면 사내 모드에 남김, 아니면 숨김 | 남기면 문서 외 업무 화면 하나가 사내에서도 된다 | 확인 결과에 따름 |
| D8. 사내 Git 머지 승인자 | 외부에서는 관리자 계정이 승인 관리 화면에서 승인 | 문서 저장소 머지 권한자 1~2명 지정 | 승인자가 없으면 수정이 멈춘다 | 지금 허브 관리자와 같은 사람 권장 |
| D9. 사내 문서의 기재 규칙 | 공개 저장소라 금액·제휴사 실명 금지 | 사내 Git 은 비공개이므로 **같은 규칙 유지**를 기본으로 하되, 완화할지 결정 | 완화하면 사내 문서가 더 구체적이 되지만 외부 견본과 영원히 갈라진다 | 올해는 유지 권장. 내년 사내 챗봇 근거가 갖춰진 뒤 재검토 |
| D10. 외부 개발 중 문서 견본 | 외부 `지식/` 그대로 | D1 동결본을 개발·테스트 견본으로 사용 | 화면 개발은 외부에서 계속 가능 | D1 과 묶어서 결정 |

## 열린 질문

- 이관일(외부 `지식/` 동결일)을 언제로 할지 — D1·D2 와 묶어서.
- 반영 담당(절차 B·C 를 하는 사람)을 누구로 할지 — `ops` 역할을 실제로 맡을 실무자 1명.
- 플레이그라운드 업로드 권한을 받을 수 있는지, 대시보드 때 담당자에게 문의해야 하는지.
