# 문서 작성 규칙(HUB-03) 초보자용 재구성과 "챗봇으로 고치기" 안내

작성 2026-11-26 · plan-pm · 브랜치 `claude/epic-tesla-34okcx` 기준

> 상위 지시(원문): "위키 > 문서 작성 규칙 메뉴가 초보자가 보기에 너무 어렵거든~ 이런거 다 상관없이 챗봇 통해 수정하면 알아서 수정된다는것도 곳곳에 넣어주면 좋을거같거든"

## 문제

**누가** — 편성·마케팅 실무자(비개발자). 문서 내용이 틀린 걸 발견했거나, 알고 있는 걸 위키에 남기고 싶은 사람.

**어떤 상황에서** — "이용 안내 › 문서 작성 규칙(HUB-03)"을 열면 첫 화면이 폴더 경로(`지식/promotion/`), 파일명 규칙(영문 소문자+하이픈), YAML 프론트매터 예시, `subcategory` 값 목록, `#h-소제목` 링크 문법, `npm run check:anchors` 순서로 나온다.

**무엇을 못 하나**
1. 실무자는 이 문서를 "형식을 맞춰야만 문서를 고치거나 쓸 수 있다"로 읽고 그만둔다. 첫 줄에 "형식을 못 맞춰도 본문만 주면 정리해 드립니다"라고 적혀 있긴 하다. 그런데 **누구에게, 어디서, 어떻게** 주는지가 없다.
2. 실제로는 형식을 몰라도 되는 길이 두 개 있다. 문서 화면의 `✎ 고치기` + `AI에게 부탁`, 그리고 챗봇 대화다. 하지만 HUB-03·HUB-01·새 문서 화면 어디에도 이 두 길이 "형식 대신 쓰는 방법"으로 소개돼 있지 않다.
3. "챗봇에게 말하면 고쳐진다"를 그대로 적으면 사실과 다르다. 실제로는 **수정안(초안) → 사람이 제출 → 관리자 승인 → 다음 배포 때 반영** 순서다. 게다가 아래 "현재 상태" 3번처럼 **챗봇 쪽 초안 카드는 지금 화면에 뜨지 않는다.**

### 3. 중요 — 챗봇 초안 카드는 지금 화면에 없다

- 서버는 `action` 을 돌려준다 (`server/knowledge.ts` 558행 `return { text, sourcePaths, action }`).
- 화면의 응답 타입 `AskResponseBody`(`src/lib/assistant.ts` 1266~1273행)에는 `action` 칸이 없다. 그래서 받아도 버린다. `src/` 전체에 "제안 제출" 문자열도, 초안 카드 컴포넌트도 없다. 이전 `ProposeEdit.tsx` 의 `제안 제출` 버튼은 1c7b74e에서 페이지와 함께 지워졌다. 그 버튼은 챗봇 카드가 아니었다.
- 그런데 규약(`assistant-prompt.md` 255행)은 엔진에게 "아래 카드에서 확인하고 **[제안 제출]**을 눌러 주세요."라고 쓰게 한다. **지금 엔진이 연결된 사용자가 "고쳐줘"라고 하면 "아래 카드"라는 답만 오고 카드는 뜨지 않는다.** 이건 이번 지시와 별개로 이미 생긴 어긋남이다.
- 카드 구현은 `docs/plan/2026-11-13-chat-doc-draft-and-attachments.md` 차례 1-3(dev-front)에 잡혀 있었다. 문구는 `docs/sections/requests-chat-draft.md` 에 있다. 이번 브랜치에서는 반영되지 않은 상태다.
- 엔진이 없을 때 쓰는 규칙 기반 답변(`src/lib/assistant.ts` 816~836행)은 "위키 문서는 대화로 바로 고칠 수 없고, 화면에서 제출합니다."로 답한다. 엔진이 없을 때는 이 말이 사실이다.

그래서 "챗봇에게 말하면 수정안을 만들어 준다"는 안내는 **카드가 뜨고 나서야** 사실이 된다. 지금 당장 사실인 것은 "문서 화면의 `AI에게 부탁`에 말로 적으면 AI가 형식을 맞춰 고쳐 준다"이고, 이것도 AI가 연결돼 있어야 한다.

1. **HUB-03 재구성.** 실무자용 앞부분과 관리자용 뒷부분으로 나눈다. 기존 규약 내용은 지우지 않고 아래로 옮긴다.

### 범위 상세 1. HUB-03 재구성안

#### 1-1. 새 순서

```
## 이 문서는                                  ← 고침: 2문장. "형식은 몰라도 됩니다. 이 문서 앞부분만 읽으세요"
## 형식은 몰라도 됩니다 — 말로 고치는 법          ← 새로 씀 (실무자용 핵심)
## 이것만은 지켜 주세요                         ← 새로 씀: 3줄 요약 + "사내 정보 주의"로 안내
## 사내 정보 주의                              ← 원래 9번을 위로 올림. 제목·내용·H3 그대로
## 관리자용 — 저장소 형식 규약                   ← 새로 씀: 1~2문장 + 아래 장 지도 표
## 파일 하나 = 문서 하나                         ← 원래 그대로
## 프론트매터                                  ← 원래 그대로
## 상태 표기                                   ← 원래 그대로
## 문서 톤앤매너                                ← 원래 그대로
## 문서끼리 링크하기 (### 소제목을 고쳤으면…)       ← 원래 그대로
## 본문 작성 (### 주의 상자)                     ← 원래 그대로
## 컨플루언스에서 옮기는 법                       ← 원래 그대로
## 다음에 볼 문서                               ← 줄 추가: "챗봇이 답을 못 한다 → HUB-04"
```

- 기존 H2·H3 **제목 글자는 그대로** 둔다. `propose.md` 의 **사내 정보 주의** 참조와 혹시 모를 앵커 링크를 지키기 위해서다.
- 관리자용 장은 H3로 내리지 않는다. 내리면 그 안의 H3(링크 검사, 주의 상자, 별표)가 H4가 되어 오른쪽 목차에서 빠진다(`writing.md` 120행: 목차는 `##`·`###`만). 대신 "관리자용 — 저장소 형식 규약" 장 하나를 칸막이로 두고, 그 장에 뒤 장들의 지도 표를 둔다. 표는 HUB-03이 스스로 정한 "이 문서 안의 챕터" 규칙을 따른다.
- 프론트매터: `version: 4`, `updatedAt` 은 반영한 날, `updatedBy` 는 가린 표기로 쓴다. `code`·`title`·경로는 바꾸지 않는다.

   | 하고 싶은 것 | 이렇게 말하거나 누릅니다 |
   | --- | --- |
   | 읽던 문서가 틀렸다 | 문서 오른쪽 `이 문서로 묻기` → "이 부분 ○○를 △△로 고쳐줘" *(카드 반영 뒤)* / 또는 `✎ 고치기` → 장 도구줄 `AI에게 부탁` |
   | 문서에 내용을 보태고 싶다 | 챗봇에 "「문서 제목」에 ○○ 내용을 넣어줘" |
   | 새 문서를 만들고 싶다 | 챗봇에 "새 문서로: ○○ 정리해줘" 또는 위키 문서 목록 `+ 새 문서` |

3. **예시 발화 3개 이상.** 실제 문서 제목을 쓰되 제휴사 실명·금액은 넣지 않는다. 예: "「담당자·결재 라인」에서 판촉용 쿠폰 결재 기준을 팀장 전결로 고쳐줘. 지난주 팀 회의에서 정했어." 예시는 chatbot-planner가 `assistant-prompt.md` 의도 판정 5단계로 돌렸을 때 `edit`·`new` 로 바로 가는 문장만 고른다.
4. **그다음 일어나는 일 4단계**: 수정안(초안)이 카드로 뜸 → 확인하고 `[제안 제출]` → **대기 중**(내 요청 현황) → 관리자 승인(머지) → **다음 배포 때** 위키에 반영. 상태 이름은 HUB-02·`MyRequests.tsx` 와 같은 **대기 중 · 머지됨 · 닫힘**을 쓴다.
5. **안 되는 것 한 줄**: 대화로 "올려"라고 해도 제출되지 않는다. 버튼으로만 제출된다. 문서 삭제·이동은 대화로 할 수 없다.
6. **조건 한 줄**: "AI가 연결돼 있어야 말로 고칠 수 있습니다. 연결이 안 되면 `✎ 고치기`로 화면에서 직접 고치면 됩니다 — 이때도 마크다운은 몰라도 됩니다." + [챗봇 답변 엔진 안내](HUB-04) 링크.
7. 마지막에 "이 아래 관리자용 규약은 읽지 않아도 됩니다. 챗봇과 편집 화면이 형식을 맞춥니다." 한 줄.

#### 1-3. "이것만은 지켜 주세요" 장

- 사람 이름·부서명은 별표 하나로 가린다(`홍*동`, `미디어*팀`).
- 사내 주소·제휴사가 드러나는 프로모션명은 넣지 않는다.
- 가려진 이름을 실명으로 채우지 않는다.
- → 자세한 건 **사내 정보 주의**. 편집 화면과 챗봇도 검사하지만 사람이 먼저 지키는 규칙이라는 WHY 한 줄.

### 범위 상세 3. 표준 문구 (확정은 D2)

- **피하는 표현**: "알아서 수정됩니다", "바로 반영", "자동으로 반영", "반영했습니다". 실제로는 승인과 다음 배포를 거친다.
- **문구 A (문서용, 합니다체)**: "형식은 몰라도 됩니다. 챗봇에게 무엇을 어떻게 고칠지 말하면 형식에 맞춘 수정안을 만들어 드립니다. 확인하고 제출하면 관리자 승인을 거쳐 다음 배포 때 위키에 반영됩니다."
- **문구 B (문서 보기 화면, 해요체 1줄)**: "틀린 곳이 있나요? 위 버튼을 눌러 말로 고쳐 달라고 하세요. 수정안을 만들어 드려요."
- **문구 C (새 문서 본문 칸, 해요체 1줄)**: "마크다운을 몰라도 돼요. 그냥 쓰거나, 챗봇에 '새 문서로 …'라고 말하면 형식을 맞춘 초안을 만들어 드려요."
- 화면 문구 B·C·P2 문구에는 "승인" 단계를 넣지 않는다. 제출 확인 창과 완료 화면이 이미 "대기 중 → 승인 → 다음 배포"를 알린다(`NewDoc.tsx` 164행, `SubmitEditDialog.tsx`). 한 줄 안에 단계를 다 넣으면 길어진다.
