# 처음 온 사람도 바로 쓰는 허브 — 업무 시작 카드 · 빈칸 질문 · 예시 placeholder (1차)

작성 `plan-pm` · 2026-11-19
상위 지시: "위키 허브를 처음 접속한 사람, AI에 익숙하지 않은 사람도 잘 쓰게 하자. 추천 순서대로 진행하고, 그 흐름대로 UI/UX 전체 화면 개편이 필요한지 검토해 달라."
1차 범위 ①②③은 상위 지시자 승인됨. ④~⑧은 이번에 기획 메모만 남긴다.

---

## 문제

이 허브의 사용자는 편성·마케팅 실무자다. 처음 접속했거나 AI 대화에 익숙하지 않은 실무자가 아래 상황에서 막힌다.

1. **첫 화면에서 할 일을 모른다.** 대시보드를 열면 맨 위에 숫자 카드 4개(전체 문서·카테고리별 수·이번 주 업데이트·대기 요청)가 먼저 보인다. 이 숫자는 관리자·숙련자에게는 쓸모가 있지만, 처음 온 사람은 "그래서 나는 여기서 무엇을 누르면 되나"를 알 수 없다. 그나마 보이는 숫자 하나("이번 주 업데이트")도 실제 이번 주 수치가 아니다(버그, 아래 현재 상태 참고).
2. **무엇을 어떻게 물어야 할지 모른다.** 어시스턴트 입력창에는 "질문 입력…"만 쓰여 있다. 대화가 비어 있을 때만 예시 질문 버튼이 보이고, 한 번 대화를 시작하면 예시가 사라진다. AI에 익숙하지 않은 사람은 빈 입력창 앞에서 질문 문장을 직접 만들어야 하고, 상품 유형·기간·혜택처럼 답에 꼭 필요한 조건을 빠뜨리기 쉽다. 빠뜨리면 어시스턴트가 되물어 한 바퀴를 더 돌게 된다.
3. **어떤 질문이 통하는지 감이 없다.** 질문 예시는 빈 대화 상태에서만, 그것도 한 묶음으로만 보인다. 입력하려고 커서를 둔 순간에는 아무 힌트가 없다.

## 이번 범위 / 범위 밖

### 이번 범위 (1차)

- **① 대시보드 업무 시작 카드**
  - 대시보드 맨 위에 "오늘 무엇을 하시나요?" 제목과 업무 시작 카드 3~4개: 프로모션 기획 / 편성 확인 / 정책 확인 / 시스템 사용법.
  - 카드마다 한 줄 설명과, 누르면 가는 곳(화면 이동 또는 어시스턴트 질문)을 정한다. 연결 방식은 기존 `navigate()` 와 `useApp().ask()` 만 쓴다.
  - 기존 KPI 4칸은 카드 아래로 내리거나 한 줄 요약으로 축소한다(어느 쪽인지는 wiki-ux 안, 열린 질문 Q1).
  - `weekly` 버그 수정: 고정 날짜 비교를 없애고 실제 '이번 주' 기준으로 센다(기준 정의는 열린 질문 Q2). `updatedAt` 이 `'-'` 이거나 비어 있는 문서는 세지 않는다.
- **② 빈칸 채우기형 질문 템플릿**
  - 예: "[상품]으로 [기간] 동안 [혜택] 프로모션 하려면?" — 빈칸을 누르면 고를 값이 버튼으로 뜨고, 모두 고르면 완성된 문장이 미리 보이며 보내기로 기존 `send()`(= `ask()`)에 넘긴다.
  - **서버·`api/`·`server/knowledge.ts`·`server/assistant-prompt.md` 변경 없이** 화면에서 문장을 완성하는 방식으로 한다.
  - 템플릿 수는 1차에 2~3개(프로모션 기획형 필수, 나머지는 chatbot-planner 안).
  - 템플릿 문구·빈칸 값은 화면 코드에 흩지 않고 `src/lib/assistant.ts` 의 상수(예: `QUESTION_TEMPLATES`)로 한곳에 둔다.
- **③ 입력창 placeholder 순환**
  - "질문 입력…" 대신 실제 예시 질문 4~6개를 일정 간격으로 순환한다.
  - 입력창에 포커스가 있거나 글자가 들어 있으면 순환을 멈춘다. `prefers-reduced-motion` 이면 순환하지 않고 첫 예시만 보인다.
  - `aria-label` 은 지금처럼 고정 문구로 둔다(placeholder 는 화면낭독기가 일정하게 읽지 않는다).
  - 예시 문장은 `src/lib/assistant.ts` 상수로 두고, ②·`SUGGESTED_QUESTIONS` 와 문장이 겹치지 않게 chatbot-planner 가 고른다.
- **"UI/UX 전체 화면 개편 필요 여부" 검토** — wiki-ux 가 아래 [전체 화면 개편 검토 범위](#전체-화면-개편-검토-범위-wiki-ux) 절에 따라 판단안을 낸다. 판단만 하고 구현은 하지 않는다.
- **2차 ④~⑧ 기획 메모** — 아래 [2차 기획 메모](#2차-기획-메모-이번엔-구현하지-않음) 절. 이번엔 메모만.

## 수용 기준

### ① 업무 시작 카드 · KPI · weekly

- A1. 대시보드(`/`)를 열면 첫 화면(스크롤 없이, 1280×800 창 기준)에 "오늘 무엇을 하시나요?" 제목과 업무 시작 카드 3~4개가 KPI보다 **위에** 보인다.
- A2. 카드 이름은 최소 "프로모션 기획", "편성 확인", "정책 확인", "시스템 사용법" 4개 업무를 덮는다(3개로 합칠 경우 어느 둘을 합쳤는지 wiki-ux 문구표에 적혀 있다).
- A3. 각 카드는 **한 번 클릭**으로 wiki-ux 문구표에 적힌 목적지에 닿는다. 화면 이동 카드는 해당 라우트가 열리고, 질문 카드는 어시스턴트 독이 열리며 문구표에 적힌 문장이 사용자 말풍선으로 그대로 보내진다.
- A4. 카드는 키보드 Tab 으로 차례로 닿고 Enter/Space 로 동작한다(`button` 또는 링크 요소).
- A5. 기존 KPI 4가지 정보(전체 문서 · 카테고리별 · 이번 주 업데이트 · 승인 대기/내 대기 요청)는 사라지지 않고 카드 아래에 남는다. 승인 대기/내 대기 요청은 지금처럼 클릭하면 `/approvals`·`/requests` 로 간다.
- A6. "이번 주 업데이트" 는 Q2에서 정한 기준(기본안: 한국 시간 이번 주 월요일 0시 이후)으로 센다. 확인 방법: 문서 3개의 `updatedAt` 을 각각 이번 주 월요일·지난주 일요일·오늘로 둔 상태에서 숫자가 2가 된다. `updatedAt` 이 `'-'` 인 문서는 세지 않는다.
- A7. `Dashboard.tsx` 에 `'2026-08-25'` 같은 고정 날짜 문자열이 남아 있지 않다(`grep -n "2026-08-25" src/` 결과 없음).
- A8. 관리자·실무자 두 역할 모두에서 카드가 같은 위치에 보인다(역할에 따라 달라지는 것은 기존 KPI·요청 패널뿐).

### ② 빈칸 채우기 템플릿

- B1. 어시스턴트 독에서 템플릿을 고르면 문장 안 빈칸이 버튼으로 보이고, 빈칸을 누르면 그 빈칸에 들어갈 값 목록이 버튼으로 뜬다. 키보드로만도 끝까지 고를 수 있다.
- B2. 빈칸이 하나라도 비어 있으면 보내기 버튼이 비활성이고, 다 채우면 완성 문장이 미리 보이며 보내기를 누르면 그 문장이 **글자 하나 바뀌지 않고** 사용자 말풍선으로 들어간다.
- B3. 템플릿 경로는 `ask()` 만 호출한다. `server/`·`api/` 파일과 `server/assistant-prompt.md` 에 diff 가 없다.
- B4. chatbot-planner 가 정한 템플릿별 시험 조합(최소 템플릿당 3조합)을 보냈을 때, 이미 문장에 들어간 상품 유형(PPM/PPV, B tv+ 등)을 **다시 묻는 칩이 뜨지 않는다**(대화 규약 7행 "이미 답을 들은 것을 다시 묻지 않는다"). 진행 확인 칩(네/아니요)이 뜨는 것이 맞는지는 chatbot-planner 메모에 템플릿별로 적혀 있고, 실제 동작이 그 메모와 같다.
- B5. 빈칸 값은 모두 `지식/` 문서에 근거가 있는 값이다(chatbot-planner 메모에 값마다 근거 문서 경로가 적혀 있다). 문서에 없는 혜택·상품을 고를 수 없다.
- B6. 템플릿 문구·값은 `src/lib/assistant.ts` 한곳의 상수에만 있고, 매출 금액·제휴사 실명이 없다. '캠페인'이라는 말은 Target 프로모션 맥락이 아니면 쓰지 않는다.
- B7. 대화가 이미 진행 중일 때도 템플릿을 열 수 있는 입구가 독 안에 있다(지금 예시 질문처럼 빈 대화에서만 보이는 것이 아님).

### ③ placeholder 순환

- C1. 입력창이 비어 있고 포커스가 없을 때 placeholder 가 예시 질문 4~6개를 wiki-ux 가 정한 간격(기본안 4초)으로 돌아가며 보여 준다.
- C2. 입력창에 포커스가 가거나 글자가 하나라도 있으면 순환이 멈춘다. 포커스를 떠나고 비어 있으면 다시 돈다.
- C3. OS 에서 동작 줄이기(`prefers-reduced-motion: reduce`)를 켜면 순환하지 않고 첫 예시만 보인다.
- C4. `aria-label="어시스턴트에게 질문"` 은 그대로다.
- C5. 예시 문장은 모두 담당 범위(`server/assistant-prompt.md` 58행) 안의 질문이고, chatbot-planner 가 실제로 보내 봤을 때 근거 문서가 붙은 답이 나온 문장만 들어간다.
- C6. 독을 닫았다 열거나 화면을 옮겨도 콘솔 오류·타이머 누수가 없다(언마운트 시 타이머 해제).

### 공통

- D1. `npm run build` 통과.
- D2. 바뀐 문구 전체가 wiki-ux 문구표(`docs/ux/`)와 글자 단위로 같다.
- D3. 공개 저장소 규칙: 바뀐 파일 어디에도 매출 금액·제휴사 실명이 없다.

### 판단 기준 (화면마다 아래 표를 채운다)

| 기준 | 확인 방법 | 개편 신호 |
| --- | --- | --- |
| K1. 첫 행동이 보이는가 | 화면을 처음 연 사람이 스크롤 없이 "다음에 누를 것" 하나를 짚을 수 있는가 | 첫 화면에 행동 없이 정보만 있음 |
| K2. 업무 기준 길찾기 | 대표 과업 5개(아래)를 각각 몇 클릭에 끝내는가. 기준 3클릭 | 3클릭을 넘는 과업이 2개 이상 |
| K3. 메뉴 이름이 업무 언어인가 | 메뉴·버튼 이름이 실무자 말(업무)인지 시스템 말(데이터 구조)인지 | 같은 대상에 이름이 둘 이상이거나 시스템 말이 다수 |
| K4. 막다른 길 | 빈 서브메뉴, 준비 중 화면, 결과 없는 검색에서 다음 행동이 안내되는가 | 안내 없이 끝나는 화면이 여러 묶음에 걸쳐 있음 |
| K5. 어시스턴트와 문서의 오가기 | 답에서 근거 문서로, 문서에서 질문으로 한 번에 갈 수 있는가 | 한쪽 방향이 끊김 |
| K6. 일관성 | 같은 동작(목록 행, 전체 보기, 뒤로)이 화면마다 같은 모양·위치인가 | 묶음마다 패턴이 다름 |
| K7. 용어 규칙 | '캠페인'이 Target 프로모션에만 쓰였는가, 외부 연동이 "프로모션 자동화"로 불리는가 | 위반이 여러 화면에 있음 → 용어 정리는 ops 와 함께 |

대표 과업 5개: ① PPV 프로모션 기획 조건 묻기 ② 이번 주 Today B tv 편성 확인 ③ 혜택 정책(예: 중복 적용 가능 여부) 확인 ④ 시스템 매뉴얼에서 특정 기능 사용법 찾기 ⑤ 문서 수정 제안 남기기.

### 결론 형식

- 판정은 셋 중 하나: **부분 개선으로 충분** / **틀(사이드바·상단바·독)만 개편** / **전체 개편**.
- 판정 근거로 위 K1~K7 표와 과업별 클릭 수를 붙인다.
- 개편이 필요하다면 1차 ①②③ 결과물이 버려지지 않는지(새 구조에서도 그대로 쓰이는지)를 한 줄로 밝힌다. 버려진다면 1차 구현 전에 PM 데스크에 먼저 알린다.
- 검토 결과는 검토 요청 표(항목 · 현재 · 제안 · 영향 · PM 의견 칸 중 PM 의견은 비워 둠)로 낸다.
