## 1. Vercel 배포 함수 수

### 확인한 사실

| 항목 | 내용 | 출처 |
| --- | --- | --- |
| 제한 | Hobby는 **배포 1번에 함수 12개**. Pro·Enterprise는 제한 없음 | Vercel Docs `functions/runtimes` 「Functions created per deployment」, `limits` 표 |
| 세는 방법 | Next.js·SvelteKit이 아닌 프레임워크(이 허브는 Vite)와 프레임워크 없는 함수는 **`api/` 파일 1개 = 함수 1개** | 같은 절 |
| 지금 `api/` | `ask` `auth` `chatlog` `createDoc` `download-hub` `edit` `engines` `proposals` `proposeEdit` `publicCheck` `schedule` `users` — **12개** | 저장소 |
| 지금 배포 | PR #95 머지 커밋(`94636f2`) Production 배포가 성공했다 | GitHub 배포 상태 |
| `vercel.json` | `functions` 에 `ask`(지식 번들·300초), `edit`(프롬프트·300초), `download-hub`(60초) 설정이 있다. 함수 수와는 무관하다 | 저장소 |

### 결론

- **지금은 배포된다.** Hobby라면 12/12로 한도에 꽉 찼다.
- **`api/` 에 파일이 하나만 더 생겨도 Hobby에서는 배포가 막힌다.** 이미 열린 Production은 그대로지만 새 배포가 실패해 그 뒤의 수정이 모두 멈춘다.
- 현재 Vercel 프로젝트가 Hobby인지 Pro인지는 콘솔(Settings → Billing)에서만 알 수 있다. 개인 계정 범위에 있어 Hobby일 가능성이 높다. **확인 필요.**

### 앞으로의 규칙 (제안)

새 API가 필요하면 `api/` 에 파일을 새로 만들지 말고, 비슷한 기존 함수에 `?view=` 나 본문 `action` 으로 붙인다. `api/chatlog.ts` 가 `view=status|mine|all|usage` 로 이렇게 만들어졌다.

### 자리가 더 필요할 때의 대안 (제안만, 코드 작업은 dev-server)

| 안 | 내용 | 줄어드는 수 | 영향 |
| --- | --- | --- | --- |
| A. 새 파일 금지 (위 규칙) | 새 기능은 기존 함수의 `view`/`action` 으로 | 0 (늘지 않음) | 비용 없음. 함수 하나가 커진다 |
| B-1. 문서 PR 계열 합치기 | `proposals`(목록) · `proposeEdit`(수정 제안) · `createDoc`(새 문서) → 하나. 셋 다 GitHub PR을 다루고 `createDoc`·`proposeEdit` 은 같은 호출 제한(`RATE_PR`)을 쓴다 | 2개 | `vercel.json` `rewrites` 로 예전 주소를 새 함수로 돌리면 화면은 안 바꿔도 된다. 로컬 `server/cliBridge.ts` 경로도 같이 맞춰야 한다 |
| B-2. 작은 함수 합치기 | `engines`(7줄) · `publicCheck` → 하나, 또는 `users` 를 `auth` 에 합치기(계정 계열) | 1~2개 | B-1과 같다. 계정 기능은 회귀 확인이 필요하다 |
| C. Pro 전환 | 함수 수 제한이 없어진다 | 제한 해제 | 유료. 상위 지시자 결정 |
| D. 함수 하나로 모두 받기 | `api/[...path].ts` 하나에서 경로로 나눈다 | 11개 | 권하지 않는다. `ask` 의 지식 번들·300초 설정이 모든 요청에 붙어 무거워진다 |

- `vercel.json` `functions` 에 설정이 있는 `ask`·`edit`·`download-hub` 는 합치지 않는다. 시간 제한·포함 파일이 함수 단위라서다.
- PM 의견: 지금은 A로 막고, 13번째가 꼭 필요해지면 B-1부터 한다.

## 2. Upstash 무료 한도를 넘으면

### 무료 플랜 한도

| 항목 | 한도 | 출처 |
| --- | --- | --- |
| 월 명령 수 | 50만 | Upstash 가격 페이지 FAQ |
| 데이터 용량 | 가격 페이지 FAQ는 **250MB**, 같은 페이지의 용량 표는 **256MB** 로 적혀 있다 | Upstash 가격 페이지 |
| 월 대역폭 | 10GB | 같은 표 |
| 초당 명령 | 10,000 | 같은 표 |
| 데이터베이스 수 | 무료 계정 1개 | 같은 페이지 FAQ |
| 오래 안 쓰면 | 30일 이상 쓰지 않으면 보관(archive) 처리 후 백업에서 새로 만들어 복구 | Upstash Redis FAQ |

- 관리자 화면의 추정치는 용량 한도를 256MB(정확히는 256×1024×1024바이트)로 잡는다(`server/chatLog.ts`). 공개 문서 숫자가 둘이라 **월 점검 때는 Upstash 콘솔에 보이는 한도를 기준으로 한다.**

### 넘으면 생기는 일

| 넘은 것 | Upstash 동작 | 출처 |
| --- | --- | --- |
| 월 명령 50만 | 넘은 뒤의 명령은 **읽기·쓰기 모두 오류**(`ERR max requests limit exceeded`)로 돌아온다. 지우지 않는다 | Redis FAQ, Troubleshooting 「ERR max requests limit exceeded」 |
| 용량 | 기본 설정(eviction 꺼짐)에서는 **쓰기를 거절**한다(`ERR DB capacity quota exceeded`). **읽기·삭제는 된다.** 데이터를 지우지 않는다 | Features 「Eviction」, Troubleshooting 「ERR DB capacity quota exceeded」 |
| 초당 명령 | 잠시 늦춰서(throttle) 처리한다 | Redis FAQ |
| 대역폭 | 무료 플랜 동작은 공개 문서에 따로 없다(고정 요금제는 트래픽 차단). **확인 필요** | 가격 페이지 FAQ |

- **eviction(꽉 차면 오래된 키 지우기)은 켜지 않는다.** 켜면 만료가 있는 키(대화 기록·잠금)부터 무작위로 지우다가 모자라면 **계정 키까지 무작위로 지운다.** 계정이 사라지는 쪽이 쓰기 거절보다 나쁘다.
- 결제 수단을 넣으면 사용량 과금(pay-as-you-go)으로 자동 전환되고 한도가 풀린다. 데이터는 그대로다.
- 월 명령 수가 언제 다시 0이 되는지(달력 기준 날짜·시간대)는 공개 문서에 없다. **확인 필요.** 관리자 화면 추정치는 KST 달력 월로 센다.

### 계정 로그인에 미치는 영향

계정·로그인 잠금·호출 횟수 제한·대화 기록이 **같은 Redis 하나**를 쓴다. 지금 코드(`server/accounts.ts`, `server/auth.ts`, `server/guard.ts`, `api/auth.ts`)를 읽고 정리했다.

| 상황 | 월 명령 50만 초과 | 용량 초과 |
| --- | --- | --- |
| 새로 로그인 | **안 된다.** 잠금 확인부터 실패해 오류(502)가 난다 | 비밀번호가 맞으면 **된다**(읽기와 삭제만 쓴다) |
| 비밀번호를 틀림 | 위와 같다 | 실패 횟수를 못 써서 "틀렸습니다"(401) 대신 오류(502)가 나고, **5번 틀림 잠금이 동작하지 않는다** |
| 이미 로그인한 사람 | 세션 확인 때 계정을 못 읽어 **모든 API가 "로그인이 필요합니다"(401).** 챗봇·AI 수정·새 문서·수정 제안·내려받기가 막힌다 | 계정을 읽을 수 있어 그대로 쓴다. 단 **호출 횟수 제한이 풀린다**(세지 못하면 통과시키도록 되어 있다) |
| 첫 로그인 비밀번호 변경 | 안 된다 | **안 된다**(계정 저장이 쓰기다). 새로 발급한 사람은 허브에 들어가지 못한다 |
| 계정 발급·초기화·사용 중지 | 안 된다 | **안 된다.** 퇴사·이동자를 막을 수 없다 |
| 대화 기록 | 저장 실패. 답에는 영향 없음(저장 실패는 조용히 넘긴다) | 같다 |
| 로컬 허브(실무자 PC) | 영향 없음(Redis를 쓰지 않는다) | 영향 없음 |
| 풀리는 때 | 다음 달 명령 수 초기화, 또는 유료 전환 | 기록이 90일 만료로 빠지거나, 관리자가 기록을 지우거나, 유료 전환 |

- 명령 초과는 로그인 전체가 멈추는 사고다. 하루 저장 상한(500건)과 월 점검의 70% 경고가 이것을 막는 장치다.
- 용량 초과는 로그인 자체는 되지만 비밀번호 변경·계정 관리·잠금이 멈춘다. 이 상태가 보이면 관리자 화면에서 오래된 기록을 지워 자리를 만든다(삭제는 용량 초과 중에도 된다).

## 3. 월 1회 점검표

**언제** 매월 20일 전후 1회(월말까지 열흘쯤 남아 조치할 시간이 있을 때). 값이 70%에 가까웠던 달은 그달 말에 한 번 더 본다.
**누가** ops. 관리자 계정으로 허브에 로그인할 수 있어야 한다.
**경고 기준** **70%** — `docs/assistant/chat-log-review.md` 2-1, 관리자 화면 사용량 띠의 경고색과 같은 값이다.

### 순서

1. **Upstash 콘솔 값 적기** — Vercel 프로젝트 → Storage → 연결된 Upstash Redis → Upstash 콘솔 열기 → 데이터베이스 상세/사용량 화면. 아래를 적는다.
   - 이번 달 명령 수(Commands), 데이터 용량(Data Size), 이번 달 대역폭(Bandwidth)
   - 콘솔에 보이는 각 한도(용량 한도는 250MB/256MB 중 콘솔 값을 쓴다)
   - Eviction 이 **꺼져 있는지**
2. **허브 관리자 화면 값 적기** — 배포 허브 → 내 업무 › 대화 기록 → 맨 위 사용량 띠 4칸.
   - 오늘 저장(/하루 상한), 최근 90일, 저장 용량(추정), 이번 달 명령 수(추정)
   - 이번 달에 "상한을 넘어 n건은 내용 없이 건수만 남았어요"가 뜬 날이 있었는지(날짜 목록에서 본다)
3. **두 값 맞춰 보기**
   - 명령 수: 콘솔 ÷ 추정. **콘솔이 더 큰 것이 정상이다.** 추정에는 페이지 열 때의 로그인 확인, 관리자·본인 기록 조회, 계정 관리, 수정 제안 등 호출 제한 카운트가 빠져 있다.
   - 용량: 콘솔 ÷ 추정. 추정은 기록 1건을 2.5KB로 친 값이고 계정 키(1MB 미만)는 빠져 있다.
   - 이 비율을 점검 기록에 남긴다. 지난달보다 비율이 크게 바뀌었으면(예: 1.5배 → 3배) 추정 계수(`server/chatLog.ts` 의 건당 명령·용량 값)를 다시 맞출지 dev-server에 넘긴다. ops는 코드를 고치지 않는다.
4. **경고 판정** — 하나라도 해당하면 경고다.

   | 항목 | 경고 |
   | --- | --- |
   | 이번 달 명령 수(콘솔) | 35만(50만의 70%) 이상 |
   | 월말 예상 명령 수 | 콘솔 값 × (그달 날짜 수 ÷ 지난 날짜 수)가 35만 이상 |
   | 데이터 용량(콘솔) | 콘솔 한도의 70% 이상 |
   | 대역폭(콘솔) | 7GB(10GB의 70%) 이상 |
   | 하루 상한 초과 | 이번 달에 한 번이라도 있음 |
   | Eviction | 켜져 있음 → 바로 끈다 |

5. **경고면 PM 데스크에 표로 보고** — 항목 · 콘솔 값 · 추정 값 · 비율 · 원인 추정. 사용량 숫자는 매출이 아니므로 적어도 된다. 기록 속 질문 원문·제휴사명은 적지 않는다.
   - 고를 수 있는 것: 하루 상한 낮추기(`HUB_CHATLOG_DAILY_CAP`), 보관 일수 줄이기(`HUB_CHATLOG_DAYS`), 유료 전환. **고르는 것은 상위 지시자다.** 환경값을 바꾸는 작업은 결정 뒤 ops가 Vercel 환경변수에서 한다.
6. **토큰 배포 금지 재점검** — 아래 4절의 확인을 다시 돌린다.
7. **점검 기록 남기기** — 아래 표에 한 줄 추가한다.

## 4. Redis 토큰을 실무자 PC에 넣지 않는다

`KV_REST_API_URL`·`KV_REST_API_TOKEN`(또는 `UPSTASH_REDIS_REST_*`) 하나로 모든 계정 해시와 대화 기록을 읽고 지울 수 있다. 이 값은 Vercel 환경변수에만 둔다. 예외는 관리자 PC의 `.env.local` 하나다(기획서 D1 (나)).

### 2026-11-20 점검 결과

| 대상 | 확인한 것 | 결과 |
| --- | --- | --- |
| 설치 스크립트 `scripts/setup.ps1`·`install-hub.sh` | `.env` 계열 파일을 만들거나 쓰는 코드, Redis 변수 이름 | 없음 |
| 업데이트 `scripts/update-hub.ps1` | `.env` 계열 처리 | `.env.local` 등 내 설정은 건드리지 않고 그대로 둔다. 값을 넣지 않는다 |
| 허브 ZIP (`server/hubZip.ts`, `api/download-hub.ts`) | ZIP에 들어가는 것 | 공개 저장소 zipball + 실행기 2개 + 안내 txt + 버전 파일 + 고른 계정 종류(`hub-setup.json`, `{accounts}` 만). 환경변수 값은 들어가지 않는다. `.env*.local` 은 `.gitignore` 라 zipball 에도 없다 |
| `.env.example` | Redis 줄 | 빈 값 주석 + "실무자 PC에는 넣지 않습니다 … 로컬 허브는 관리자 PC만 예외" 안내가 있다 |
| 화면의 `.env.local` 안내 (`src/components/CliStatus.tsx`, `src/pages/Systems.tsx`) | 실무자에게 넣으라고 하는 값 | `GEMINI_API_KEY`, `HUB_SYSTEMS_FILE` 뿐. Redis 없음 |
| 위키 안내 (`지식/guide/schedule.md`, `지식/guide/systems.md`) | 같음 | `JIRA_BASE_URL`·`JIRA_PROJECT_KEY`, `HUB_SYSTEMS_FILE` 뿐. Redis 없음 |
| `docs/accounts.md`·`docs/jira-mcp-setup.md` | 같음 | Redis는 Vercel 연결로 자동 입력된다는 설명만 있다. 이번에 "실무자 PC에 넣지 않는다" 절을 추가했다 |

### 다시 점검하는 법

저장소 루트에서 아래를 돌려 나오는 곳이 위 표의 자리뿐인지 본다. 새 자리가 나오면 그 파일이 실무자에게 값을 넣게 하는지 읽어 본다.

```
git grep -n -e KV_REST_API -e UPSTASH_REDIS -- . ':!docs/plan' ':!docs/ops'
git grep -n "env.local" -- scripts src 지식
```

- 정상 위치: `.env.example`, `docs/accounts.md`, `server/redisStore.ts`, `server/accounts.ts`, `docs/ux/2026-11-20-chat-history.md`(배포 허브 저장 꺼짐 안내 문구에 변수 이름만).
- 실무자 PC에 토큰이 들어간 것을 알게 되면: Upstash 콘솔에서 토큰을 새로 발급(rotate)하고 Vercel 환경변수를 바꾼 뒤 다시 배포한다. 그 PC의 `.env.local` 에서 줄을 지운다.
