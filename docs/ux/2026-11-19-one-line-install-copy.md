## 2. 내려받기 화면 Mac 보기 — `LocalHubGuide.tsx` (반영: dev-front)

### 2-1. 배치 (Mac 보기만. Windows 보기는 지금과 같다)

```
[계정 4지선다]                                   ← AccountChoice (변경 없음)
G-31  아래 한 줄을 복사해 터미널에 붙여 넣으면 설치돼요.      ← cli-note muted (상태에 따라 G-34/G-35/G-31a 로 바뀜, aria-live="polite")
┌ G-30 명령 (고정폭, 줄바꿈 허용) ───────────────┐ [ 복사 ]   ← 명령 칸 + btn primary
└──────────────────────────────────────────────┘
G-36  명령어 대신 파일(ZIP)로 받기                           ← cli-os-switch 모양 작은 링크
(G-04 실패 표시 — ZIP 링크를 눌렀다 실패했을 때만, 지금 자리·모양 그대로)
G-40 설치 순서 (Mac)                   [Windows 안내 보기]    ← cli-os
1. G-41  2. G-42  3. G-43  4. G-44                           ← cli-steps
▸ 자세히 보기                                                ← cli-more (G-51~G-59, 그 아래 공통 G-06·G-07·기록 줄)
```

- 명령 칸과 [복사]를 계정 선택 **바로 아래**, 지금 내려받기 버튼 자리(`cli-dl`)에 둔다. 1366×768 에서 [복사]까지 스크롤 없이 보여야 한다(기획 F-1).
- 명령 칸은 기존 `.cmd` 스타일(설정 창 `Cmd`)과 같은 결로 쓴다. 다만 긴 명령이 잘리지 않게 `word-break: break-all` 로 줄을 바꾸고, 칸 전체를 눌러도 복사되게 한다. [복사]는 칸 오른쪽(좁으면 아래)에 `btn primary` 로 둔다. 새 색·간격 토큰은 만들지 않는다.
- 복사 처리는 `ReportCard.tsx` `copyText` 와 같은 순서(클립보드 → 실패하면 선택)로 하되, 실패 시 숨은 textarea 가 아니라 **명령 칸 글자를 전체 선택**해 둔다(F-3).
- 계정을 고르기 전(`account === null`): 명령 칸 자리는 비워 둔 채 흐린 테두리만 보이고 위 한 줄은 G-31a, [복사]·ZIP 링크는 누를 수 없다. 무엇을 받게 되는지 자리를 먼저 보여 주는 지금 내려받기 버튼 규칙과 같다.
- `onDownloaded` 는 [복사] 성공 때와 선택 대체(G-35) 때 모두 부른다. ZIP 링크로 받았을 때도 지금처럼 부른다.
- 화면에 "입력하세요"·"실행하세요"를 쓰지 않는다. 사용자가 하는 일은 "복사 → 붙여 넣기 → return" 뿐이다.

## 3. 설치 스크립트 창 — `scripts/install-hub.sh` (반영: dev-server)

### 3-0. 출력 규칙

- copy 문서 4-0절을 그대로 따른다. 창에는 이 표의 줄만 나온다. `curl`·`ditto`·`unzip` 출력은 `{기록}` 으로만 보낸다. 줄머리에 영어 꼬리표 없음, 색 규칙 같음(진행 기본색, 완료 초록, 계속 가능한 문제 노랑, 멈춤 빨강).
- 단계 번호 `[n/N]` 은 쓰지 않는다. 설치 스크립트의 일은 받기 하나뿐이고, 이어서 `start-hub.command` 가 자기 `[n/N]` 을 낸다. 두 번호가 섞이지 않게 한다.
- 이어 붙는 순서: W-61·W-62 → (W-63 → W-65) 또는 W-66 → (W-67) → (W-69) → `start-hub.command` 의 W-01 이하. W-65·W-66 뒤에 W-01 "플랫폼 담당 지식 허브를 준비합니다."가 바로 와도 어색하지 않게 W-6x 에는 "켭니다"·"준비합니다"를 쓰지 않았다.
- `{계정들}` 은 copy 문서 4-0절과 같다("Claude", "ChatGPT", "Claude와 ChatGPT").
- 키 입력이 필요한 곳(W-91m)은 `</dev/tty` 로 읽는다(기획 D4).

- 언제 내나: **바탕화면 아이콘(`플랫폼 담당 지식 허브`)이 링크이고, `readlink` 결과가 `~/Downloads/wiki-hub` 로 시작할 때만** 낸다. 다운로드 폴더 목록을 직접 읽지 않는다. 터미널이 다운로드 폴더를 읽으면 macOS 가 "터미널이 '다운로드' 폴더에 접근하려고 합니다" 창을 새로 띄우기 때문이다(3장 확인 필요 1).
- 노란색(계속 가능한 안내)으로, 폴더 열기(`open -R`)는 하지 않는다. 지우는 것은 사용자가 한다.
