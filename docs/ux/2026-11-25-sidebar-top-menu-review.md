## 2. 중복 후보 검증

### 2-1. 검색 — 중복 맞음

- 사이드바 [검색] 은 자체 입력이 없다. `focusSearch()` 가 서랍을 닫고 상단바 입력(`#hub-search`)에 포커스를 옮길 뿐이다 (381-385행).
- 상단바는 모든 화면에 늘 보이므로, 사이드바 [검색] 1클릭 = 상단바 입력 1클릭. **줄여 주는 걸음이 없다.**
- 휴대폰 폭에서는 오히려 길다: 서랍 [검색] = 메뉴 열기 → 검색 **2탭**, 상단바 입력은 메뉴 버튼 옆에 늘 있어 **1탭**.
- Ctrl K 표시도 두 곳에 같이 찍혀 있어, 초보자에게 "검색이 두 종류인가"로 읽힐 여지가 있다.
- 홈 묻기 바의 Enter 검색은 홈 화면 본문의 큰 입력으로 성격이 다르다(질문을 그대로 들고 간다). 중복으로 보지 않는다.

### 2-2. 묻기 — 부분 중복 맞음. 실제로는 "넓은 화면 2곳 + 홈 1곳", "휴대폰 2곳 + 홈 1곳"

- 상단바 [묻기] 와 FAB 는 **같은 화면에 동시에 뜨지 않는다** (FAB 는 761px 이상에서 숨김, 상단바 묻기는 760px 이하에서 숨김). 이 둘은 폭별로 자리를 나눠 가진 한 입구다. 중복 아님.
- 사이드바 [묻기] 는 두 폭 모두에서 위 입구와 겹친다. 진짜 중복은 이것 하나다.
- 사이드바 [묻기] 고유 문제 2가지:
  1. 창이 열려 있어도 사라지지 않는다. 상단바 [묻기]·FAB 는 `!assistant.open` 일 때만 보이는데 사이드바 것은 늘 있어, 창이 열린 상태에서 누르면 아무 변화가 없다.
  2. 휴대폰 폭 서랍에서 누르면 서랍이 닫히지 않는다. `openDock` 은 주소를 바꾸지 않아 "주소가 바뀌면 서랍을 닫는다"(703-705행)에 걸리지 않는다. 서랍(z-index 50)이 창을 덮어 사용자는 한 번 더 바깥을 눌러야 창을 본다 — 실질 3탭.
- 이 항목은 identity-redesign 3-1 당시 "FAB 만 있던 상태"에서 추가한 것이다. 이후 3-2 에서 넓은 화면의 묻기가 상단바로 올라가면서 추가 이유(FAB 가 목차를 가림)가 이미 해소됐다.
- 홈 묻기 바 [묻기] 는 **입력한 질문을 바로 보낸다** (`ask(q)`). 빈 창만 여는 다른 입구와 하는 일이 다르고, 홈에서는 상단바 묻기를 테두리형(`ask="line"`)으로 낮춰 빨간 버튼이 하나뿐이다. 중복이 아니라 역할 분담이 이미 돼 있다.

### 2-3. 승인 대기 ↔ 승인 관리 — 중복 맞음, 이름도 갈린다

- 관리자 사이드바에서 고정 줄 "승인 대기"와 관리 묶음 "승인 관리"가 둘 다 `/approvals` 다. 그 화면에 있으면 **두 줄이 동시에 선택 표시(on)** 된다.
- 이름: 고정 줄 "승인 대기", 관리 묶음 "승인 관리", 상단바 위치 표시(`PAGE_LABEL`) "승인 관리", 홈 큐 카드 링크 "승인 관리 ›". 화면 이름은 "승인 관리"가 다수이고, "승인 대기"는 건수의 이름이다.
- 배지 규칙도 다르다: 고정 줄은 0건이면 숨김, 관리 묶음은 0도 표시.

### 2-4. 내 요청 — 역할에 따라 자리가 바뀜, 맞음

- 실무자: 고정 줄 4번째(대기 배지 있음). 관리자: 고정 줄에서 빠지고 "내 기록" 묶음으로 내려간다(배지 없음).
- 관리자도 요청을 낸다(문서 제안·편성표 승격·시스템 등록). 위키 트리를 펼치면 "내 기록"이 첫 화면 밖으로 밀려, 관리자의 내 요청은 **스크롤 + 1클릭**이다. 실무자는 스크롤 0, 1클릭.
- 데모 권한 버튼으로 실무자↔관리자를 바꾸면 같은 자리의 메뉴 이름이 "내 요청"↔"승인 대기"로 바뀐다. 같은 자리 = 같은 메뉴라는 기대가 깨진다.
- 관리자의 홈에는 내 요청으로 가는 길이 없다(큐 카드·요청 패널이 모두 승인 쪽). 사이드바가 유일한 길이다.

### 2-5. 홈 ↔ 브랜드 로고 — 중복 아님

- `.brand` 는 `div` 이고 링크가 아니다. 홈으로 가는 길은 사이드바 [홈] 하나뿐이다. 겹치지 않는다.
- 상단바 위치 표시도 홈을 뿌리로 두지 않는다(위키·편성/스케줄이 뿌리). 홈 버튼은 지워서는 안 된다.

## 3. 판단 기준

- **상단바 = 지금 화면에서 바로 하는 동작** (찾기·묻기·오늘 날짜). 모든 화면에 늘 보인다.
- **사이드바 = 가는 곳(목적지)**. 고정 줄은 "메뉴를 펼쳐도 밀리면 안 되는 목적지"만 둔다.
- 한 동작의 입구는 한 화면 폭에서 하나. 홈 본문처럼 하는 일이 다른 입구는 예외로 둔다.
- 같은 자리에는 역할과 상관없이 같은 메뉴. 역할이 더해 주는 것은 줄을 **추가**할 뿐 바꾸지 않는다.

### 4-1. 추천 최종 배치

```
상단바 (모든 화면, 왼쪽 → 오른쪽)
  [≡ 메뉴](760px 이하만) · 위치 › … · [⌕ 문서·코드·구좌 검색  Ctrl K] · 11.25 수 KST · [묻기]
  - 묻기: 761px 이상은 상단바, 760px 이하는 오른쪽 아래 떠 있는 버튼(FAB). 창이 열리면 둘 다 숨는다
  - 홈 화면만: 상단바 [묻기]는 테두리형, 본문 묻기 바의 [묻기]가 빨간 버튼

사이드바
  ▮▮▮ CUE 플랫폼 담당 지식 허브        (링크 아님, 그대로)
  ─ 고정 줄 ─────────────────────────
   ⌂ 홈
   ▢ 내 요청                    n     ← 실무자·관리자 같은 자리, 대기 1건 이상일 때 배지
   ✓ 승인 관리                  n     ← 관리자만 추가되는 줄
  ─────────────────────────────────
  위키 …                              (변경 없음)
  업무 화면 …                         (변경 없음)
  내 기록
   ◷ 내 대화 기록                     (기록이 켜진 경우만. 없으면 묶음째 숨김)
  관리                                (관리자만)
```

- 고정 줄: 실무자 4줄 → 2줄, 관리자 4줄 → 3줄. 첫 화면에서 위키 트리가 1-2줄 위로 올라온다.

## 6. 반영 나누기 (dev-front)

한 커밋으로 묶어도 되지만, 되돌리기 쉽게 아래 둘로 나눈다. 정보구조 데이터 파일(`docs.ts`·`knowledgeDocs.ts`·`scheduleNav.ts`)은 바뀌지 않는다.

**커밋 1 — 메뉴 구조 (`AppShell.tsx` `Sidebar`)**

1. 고정 줄에서 [검색] 버튼과 [묻기] 버튼을 뺀다. 쓰이지 않게 되는 `focusSearch` 정리. `SEARCH_INPUT_ID` 는 상단바 입력 id 로 남겨도 된다.
2. 고정 줄을 `홈 · 내 요청(모두, 배지) · 승인 관리(관리자만, 1건 이상 배지)` 로 바꾼다. 역할에 따른 삼항 분기를 "내 요청은 늘, 승인 관리는 추가"로.
3. 내 기록 묶음에서 관리자용 "내 요청"을 뺀다. 묶음 표시 조건은 `showMyChatLog` 만.
4. 관리 묶음에서 "승인 관리"를 뺀다. 남는 줄이 없으면 묶음 제목도 그리지 않는다.
5. 홈 큐 카드·요청 패널(`Dashboard.tsx`)은 손대지 않는다 — 이미 "승인 관리 ›" 이름을 쓴다.

**커밋 2 — 화면 (`styles.css`)**

- `.nav-search`, `.nav-hint` 규칙 제거(쓰는 곳이 없어짐). 새 색·간격은 만들지 않는다.
- 지금 dev-front 가 사이드바 하위 트리 들여쓰기 CSS 를 고치는 중이라 `styles.css` 가 겹친다. **그 작업이 머지된 뒤에** 커밋 2 를 올린다.

## 7. 검수 기준 (반영 PR 이 오면)

- 넓은 화면: 검색 입구는 상단바 입력 하나, 묻기 입구는 상단바 버튼 하나(홈은 + 묻기 바).
- 760px 이하: 서랍 안에 검색·묻기 없음, FAB 로 1탭에 창이 열린다.
- 관리자로 `/approvals` 에 있을 때 선택 표시가 사이드바에 한 줄만.
- 데모 권한을 바꿔도 고정 줄 2번째는 늘 "내 요청".
- 관리자 고정 줄의 내 요청 배지 수 = 실무자 셈과 같은 규칙(`myPendingCount`).

## 8. 확인 필요

- 고정 줄 관리자 판단은 `session.role`(데모 전환 포함), 계정 관리는 `account.role` 이다. 승인 관리 줄은 기존대로 `session.role` 을 따른다. 두 기준을 맞출지는 requests-planner 판단.
- 관리 묶음이 데모 관리자에게 빈 묶음이 되는 경우 제목을 숨기는 것으로 했다. 다른 안이 있으면 requests-planner 와 맞춘다.
- 화면 밖 관찰: 760px 이하에서 어시스턴트 창(`.dock`, 최소 320px)이 본문 옆에 붙어 본문을 좁힌다. 이번 범위 밖이며 따로 본다.
