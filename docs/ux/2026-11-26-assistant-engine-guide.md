## 2. (a) 「이렇게 물어보세요」 엔진 예시 질문

### 2-1. 질문 4개

| 키 | 버튼 글자 (= 보내는 말) | 답하는 문서 절 |
| --- | --- | --- |
| `connect` | 내 AI 계정은 어떻게 연결해? | HUB-04 「내 PC용 허브에서 로그인할 때」 또는 「웹 주소 허브에서 처음 시작할 때」 |
| `benefit` | 내 AI 계정을 연결하면 뭐가 좋아? | 「내 AI 계정으로 쓰면 좋은 점」 |
| `compare` | 공용 AI와 내 AI 계정은 뭐가 달라? | 「공용 AI와 내 AI 계정, 무엇을 쓸까요」 |
| `tips` | 챗봇에 어떻게 물어보면 잘 답해? | 「챗봇에 잘 묻는 법」 |

- 버튼 글자에 "Gemini"·"Codex"·"비교해"를 쓰지 않는다. 이름 규칙(F5)과, "비교해"가 리포트 판정(`report.ts` 22행)에 걸리는 것을 피한다.
- "구독"도 쓰지 않는다 — 1-2절의 PPM 오판을 버튼이 일으키지 않게.

### 2-2. 노출 조건 — 어시스턴트 첫 화면에서만 (홈 예시 질문은 그대로)

상태는 `assistant.engineStatus` 와 `isLocalStatus()` (`localHub.ts`) 로 가른다.

| 상태 | 판정 | 목록 |
| --- | --- | --- |
| 내 PC 허브 · 내 계정 미연결 | `isLocal` 이고 claude·codex 모두 `loggedIn` 아님 (공용 키 유무 무관) | **앞에** `connect`, `benefit` + 기존 앞 6개 |

| 내 PC 허브 · 내 계정 연결됨 | `isLocal` 이고 하나라도 `loggedIn` | 기존 7개 + **뒤에** `tips` |
| 확인 중(`undefined`) · 상태 모름(`null`) | | 기존 7개 + 뒤에 `tips` |

- 늘 8개를 넘지 않는다. 앞에 2개를 넣을 때는 기존 마지막("모바일 B tv 외부연동 규격 알려줘")을 뺀다.

- 버튼을 누르면 지금처럼 `send(q)`. 별도 동작 없음.

## 3. (b) 답의 형태

### 3-1. 의도 판별 — `detectEngineTopic(query): EngineTopic | null`

`answer()` 의 `detectKnowledgeEdit` 바로 다음, `detectDeliverable` 앞에 둔다. `askAssistant` 도 엔진을 부르기 전에 한 번 부른다(3-4절).

```ts
export type EngineTopic = 'about' | 'which' | 'benefit' | 'connect' | 'trouble' | 'compare' | 'short' | 'tips'

/** 답변 엔진을 가리키는 말 — '계정' 단독은 ACS 사번·계정 관리와 겹쳐 세지 않는다 */
const ENGINE_NOUNS = /ai\s*계정|내\s*계정|개인\s*계정|구독\s*계정|유료\s*구독|계정\s*연결|claude|클로드|chatgpt|챗\s*gpt|챗지피티|codex|코덱스|gemini|제미나이|공용\s*ai|공용\s*엔진|답변\s*엔진|ai\s*엔진|챗봇\s*엔진|pc\s*용?\s*허브|로컬\s*허브/i
/** 엔진 이름 없이 챗봇 자체를 묻는 말 — tips·short·which 만 받는다 ("지금 어떤 AI로 답해?"도 여기서 잡는다) */
const CHATBOT_NOUNS = /챗봇|어시스턴트|어떤\s*ai\s*(?:로|가)|무슨\s*ai/i

// 위에서부터 처음 걸리는 것
const ENGINE_TOPIC_CUES: [EngineTopic, RegExp][] = [
  ['trouble', /안\s*(?:돼|되|열|바뀌)|실패|오류|에러|막혀|멈춰/],
  ['compare', /차이|달라|다른\s*점|다르|비교|장단점|단점|vs|어느\s*(?:게|쪽)|뭐가\s*나아|뭘\s*써|무엇을\s*쓸/i],
  ['benefit', /좋은\s*점|장점|이점|뭐가\s*좋|좋아\??$|왜\s*연결|연결해야|필요해/],
  ['tips', /잘\s*(?:묻|물어|쓰|답|질문)|효과적|팁|어떻게\s*물어/],
  ['short', /왜\s*(?:짧|이상|엉뚱)|답이\s*짧|규칙\s*기반|ai\s*없이/i],
  ['which', /누가\s*답|어떤\s*ai\s*(?:로|가)|무슨\s*ai|지금.*(?:엔진|ai)/i],
  ['connect', /연결|로그인|설치|받(?:아|을|는)|다운|켜|쓰는\s*(?:법|방법)|사용\s*(?:법|방법)|어떻게\s*(?:써|쓰)/],
]
```

판별 순서:

1. `SYSTEM_DOCS` 이름(acs·cbs·swing)이나 `jira`, `WORK_TERMS`(쿠폰·배너·프로모션…)가 있으면 `null` — "ACS 계정", "Jira 스케줄"은 기존 검색이 맞는 문서를 찾는다(재현에서 확인).
2. `ENGINE_NOUNS` 가 걸리면 `ENGINE_TOPIC_CUES` 에서 첫 주제. 아무 주제도 안 걸리면 `'about'`.
3. `ENGINE_NOUNS` 없이 `CHATBOT_NOUNS` 만 걸리면 `tips`·`short`·`which` 중 걸린 것만, 아니면 `null`.

판별 예 (수용 기준 표 1에서 그대로 확인):

| 질문 | 결과 |
| --- | --- |
| 내 AI 계정은 어떻게 연결해? | connect |
| 내 AI 계정을 연결하면 뭐가 좋아? | benefit (connect 보다 먼저) |
| 공용 AI와 내 AI 계정은 뭐가 달라? / Gemini 장단점 알려줘 | compare |
| 챗봇에 어떻게 물어보면 잘 답해? / 챗봇 엔진 효과적으로 쓰는 방법 | tips |
| Claude 로그인이 안 돼 | trouble |
| 챗봇 답이 왜 짧아? | short |
| 지금 어떤 AI로 답하고 있어? | which |
| 유료 구독 계정 연결하면 뭐가 좋아? | benefit (**PPM 아님**) |
| Gemini가 뭐야? | about |
| ACS 계정 신청은 어떻게 해? / Jira 스케줄 확인은 어떤 계정으로 돼? | null (기존 검색) |
| B tv+ 구독 쿠폰 프로모션 | null |

### 3-2. 규칙 기반 답 — HUB-04 절을 제목으로 집어 그대로 인용

문서 검색 점수를 쓰지 않는다. `docs.find(d => d.code === 'HUB-04')` → `parseSections(body)` → **제목이 정확히 같은 절**.

| 주제 | 절 제목 (HUB-04 v3 에 있음) | 첫 줄(결론) | 목록 |
| --- | --- | --- | --- |
| about | 챗봇은 어떤 AI로 답하나요? | lines[0] | lines[1..3] 3줄 |
| which | 어떤 AI가 답했는지 보는 법 | **상태 첫 줄** (아래) | lines[1..4] 중 앞 3줄 |
| benefit | 내 AI 계정으로 쓰면 좋은 점 | lines[0] | lines[1..4] 4줄 |
| connect · 내 PC 허브 | 내 PC용 허브에서 로그인할 때 | 없음 (목록 앞 리드 금지 규칙) | lines[0..3] 4단계 |
| connect · 웹 주소 허브 | 웹 주소 허브에서 처음 시작할 때 | 없음 | lines[0..3] 4단계 |
| connect · 모름 | 내 AI 계정 연결하기 | lines[0] | 위 두 절의 lines[0] 을 한 줄씩 |
| trouble | 연결이 안 될 때 | lines[0] | lines[1..4] 4줄 |
| compare | 공용 AI와 내 AI 계정, 무엇을 쓸까요 | lines[0] | lines[1..4] 4줄 |
| short | AI 없이 답할 때 | **상태 첫 줄** (아래) | lines[1..4] 4줄 |
| tips | 챗봇에 잘 묻는 법 | lines[0] | lines[1..4] 4줄 |

- 목록 줄은 `· ` + 줄. 문서 제목 줄(`**제목** (코드)`)은 넣지 않는다 — 근거는 문서 카드가 보여 준다.
- 모든 답이 **5줄 이내**다 (첫 줄 + 목록 4줄, 또는 목록 4줄).
- `sources`: `[{ docId: HUB-04.id, anchor: <그 절 앵커>, label: '출처 · 챗봇 답변 엔진 안내' }]`. 앵커는 위키 화면이 쓰는 절 앵커 함수와 같은 것을 쓴다.
- 절을 못 찾으면(문서 제목이 바뀜) `null` 을 돌려 기존 검색으로 떨어진다 — 빈 답을 내지 않는다.
- 이 답에는 `intent`·`brief`·`withRefine` 칩을 붙이지 않는다.

상태 첫 줄 (which·short 에서 절의 첫 줄 대신). 규칙 기반은 엔진이 없거나 모두 실패했을 때만 돌므로 늘 "AI 없이" 상태다:

| 상태 | 첫 줄 |
| --- | --- |
| 내 PC 허브 · 엔진 0개 | 지금은 내 AI 계정이 연결되지 않아 문서에서 찾은 문장만 모아 보여 드리고 있습니다. |
| 웹 주소 허브 · 엔진 0개 | 지금은 공용 AI를 쓸 수 없어 문서에서 찾은 문장만 모아 보여 드리고 있습니다. |
| 상태 모름 | 지금은 AI 연결 상태를 확인하지 못해 문서에서 찾은 문장만 모아 보여 드리고 있습니다. |
| 엔진이 있었지만 모두 실패(`fallback` 있음) | 절의 lines[0] 그대로 (실패 이유는 기존 `fallbackNotice` 가 보여 준다) |

`answer()` 가 허브 종류를 알아야 하므로 `AskOptions` 에 `hub?: 'local' | 'deploy' | 'unknown'` 를 더해 `AppStore` 에서 `isLocalStatus(engineStatus)` 로 채운다.

답 예 — 내 PC 허브, 엔진 0개, "내 AI 계정은 어떻게 연결해?":

```
· 홈의 챗봇 답변 엔진 칸이나 어시스턴트의 연결하기에서 계정 줄의 로그인을 누릅니다.
· 브라우저에 열린 로그인 화면에서 내 계정으로 로그인합니다.
· 검은 창이 하나 더 열려도 닫지 말고 두면, 끝날 때 저절로 닫힙니다.
· 로그인이 끝나면 상태가 저절로 연결됨으로 바뀝니다.
[연결하기]                                   ← 행동 버튼 (3-3절)
답변 · 규칙 기반 (문서 기준)
```

답 예 — 웹 주소 허브, "공용 AI와 내 AI 계정은 뭐가 달라?":

```
간단히 찾아보는 질문은 공용 AI로도 충분하고, 여러 조건을 따지거나 리포트가 필요하면 내 AI 계정을 권합니다.
· 공용 AI는 설치 없이 바로 쓰고, 보통 20~40초 안에 답합니다.
· 공용 AI는 빨리 답하도록 깊이 생각하는 단계를 짧게 잡아 둡니다.
· 리포트는 내 AI 계정에서만, Jira 스케줄 확인은 내 Claude 계정에서만 됩니다.
· 공용 AI는 붐비면 가벼운 예비 AI로 바뀌거나 사용 한도에 걸릴 수 있습니다.
```

### 3-3. 답 끝 행동 버튼 — 메시지에는 주제만 저장하고 버튼은 그릴 때 정한다

`ChatMessage` 에 `engineTopic?: EngineTopic` 하나만 더한다. 버튼은 **지금 상태**로 고른다 — 연결한 뒤에는 같은 답 아래 버튼이 저절로 바뀐다.

| 지금 상태 | 버튼 | 누르면 |
| --- | --- | --- |
| 내 PC 허브 · 내 계정 미연결 | [연결하기] | 공용 설정 창 (F2) |
| 내 PC 허브 · 연결됨, 주제 connect·trouble | [연결 설정 열기] | 공용 설정 창 |
| 웹 주소 허브, 주제 connect·benefit·compare | [내 PC에서 쓰기] | 공용 설정 창 (`!isLocal` 갈래 = 계정 고르기·내려받기) |

### 3-4. 엔진이 있을 때 (AI가 답하는 길)

- `askAssistant` 에서 `detectEngineTopic(query)` 가 있으면 `opts.modeOverride` 가 비어 있을 때 `'qa'` 로 보낸다 — "뭐가 나아?"가 리포트 제안 칩·리포트로 번지지 않게(`server/knowledge.ts` `detectReportIntent` 의 `JUDGMENT`).
- AI 답에도 `engineTopic` 을 실어 3-3절 버튼을 같은 규칙으로 붙인다. 본문에는 버튼 얘기를 쓰지 않도록 대화 규약을 고쳤다(5절).
- `withNextStep`·`withRefine` 는 `engineTopic` 이 있으면 건너뛴다 (PPM 세부 칩 방지).
- `readSlots`·`latestProduct` 는 `detectEngineTopic(text)` 가 걸린 사용자 발화를 **상품 판별에서 뺀다** — "유료 구독 계정" 뒤의 PPV 질문이 PPM 으로 걸러지지 않게.

## 4. (c) 확정 문구 — F1 · F3 · F4

공통 표현: AI 없이 답하는 상태는 어디서나 **"문서에서 찾은 내용만 보여 드려요"** 로 부른다. "간단한 답"은 쓰지 않는다 — 규칙 기반 답은 간단해서가 아니라 문장을 새로 쓰지 못해서 짧다(HUB-04 「AI 없이 답할 때」). 화면 문구는 해요체, 대화 본문은 합니다체를 유지한다.

### 4-1. F1 — 어시스턴트 입력칸 위 상태 줄

| 상태 | 판정 | 문구 | 버튼 |
| --- | --- | --- | --- |
| 확인 중 | `engineStatus === undefined` | ● 연결 상태를 확인하는 중… | 없음 |
| 내 계정 연결됨 | claude·codex 중 하나 `loggedIn` | 답변 엔진 [Claude] [ChatGPT] [공용 AI] | ⚙ |
| 공용 AI로만 | 내 계정 없음 + gemini `loggedIn` | ● 공용 AI로 답해요 · 차이 보기 | ⚙ |
| 내 계정 미연결 (내 PC 허브) | `isLocal`, 쓸 수 있는 엔진 0개 | ● 내 AI 계정이 연결 안 됐어요 · 문서에서 찾은 내용만 보여 드려요 | **[연결하기]** (강조) |
| AI 엔진 없음 (웹 주소 허브) | `!isLocal`, 쓸 수 있는 엔진 0개 | ● 지금은 AI 엔진을 쓸 수 없어요 · 문서에서 찾은 내용만 보여 드려요 | ⚙ (내 PC에서 쓰기 안내) |
| 상태 모름 | `engineStatus === null` | ● 문서에서 찾은 내용만 보여 드려요 | 없음 |

UX 설계안과 달라진 것: "간단한 답만 드려요" → "문서에서 찾은 내용만 보여 드려요". **웹 주소 허브·공용 키 없음** 줄과 **확인 중** 줄을 더했다 (설계안에 없던 상태 — 지금 `EngineToggle` 은 둘 다 아무것도 안 그린다).

### 4-2. F3 — 연결된 뒤

| 자리 | 문구 | 조건 |
| --- | --- | --- |
| 토스트 | {Claude} 계정이 연결됐어요. 이제 내 계정으로 답해요 | `waiting` → `loggedIn` 으로 바뀐 순간 (지금 자리 `CliStatus.tsx` 67행) |
| 설정 창 그 계정 줄 | 안내: 이제 챗봇이 {Claude} 계정으로 답해요. 버튼: **[바로 물어보기 ›]** (강조) | 이번에 로그인이 끝난 계정 줄에만. 이미 연결돼 있던 계정에는 없음 |
| 직전 규칙 기반 답 아래 칩 | **[내 계정으로 다시 묻기]** · 보조 글: 같은 질문을 {Claude} 계정으로 다시 보내요 | 아래 |

[내 계정으로 다시 묻기] 붙는 조건 — 모두 참일 때, **대화에서 가장 최근의 해당 답 하나에만**:

- `answeredBy === RULE_BASED_LABEL` 이고 `fallback` 이 비었음 (엔진이 없어서 규칙 기반)
- `engineTopic` 없음 (연결 방법 답을 다시 묻는 것은 의미가 없다)
- `intent` 없음 (진행 확인·상품 확인 칩이 있는 답은 흐름이 따로 있다)
- 지금 claude·codex 중 하나가 `loggedIn`

누르면 그 답 직전 사용자 질문을 `via: '내 계정으로 다시 묻기'` 로 다시 보낸다(사용자 말풍선 위에 작게 보임). 한 번 누르면 칩은 사라진다. {Claude} 자리는 실제로 답할 엔진(`assistant.engine`)의 화면 이름(F5)이다.

### 4-3. F4 — 엔진 없이 받은 답 아래 한 줄

`.fallback-notice` 자리. 조건은 `answeredBy === RULE_BASED_LABEL` 이고 `fallback` 이 비었고 **`engineTopic` 이 없을 때** (엔진 안내 답은 자기 버튼이 있다).

| 상태 | 문구 | 버튼 |
| --- | --- | --- |
| 내 PC 허브 | 내 AI 계정이 연결되지 않아 문서에서 찾은 내용만 보여 드렸어요. | [연결하기] (보통 버튼) |
| 웹 주소 허브 | 지금은 AI 엔진을 쓸 수 없어 문서에서 찾은 내용만 보여 드렸어요. 계속되면 관리자에게 알려 주세요. | 없음 |
| 상태 모름 | AI 연결 상태를 확인하지 못해 문서에서 찾은 내용만 보여 드렸어요. 잠시 후 다시 물어보세요. | 없음 |

함께 고칠 것 (같은 답에 같은 말이 두 번 나오지 않게):

- `assistant.ts` 797-801행 `DELIVERABLE_TAIL` ("AI 답변 엔진이 연결되면 …")을 지운다. F4(엔진 없음)와 `fallbackNotice`(엔진 실패)가 그 자리를 맡는다. 엔진이 실패한 경우에는 "연결되면"이 틀린 말이기도 하다.
- `DELIVERABLE_LEAD` 의 "지금은 규칙 기반으로 답하고 있어" → "지금은 AI 없이 답하고 있어".
