## 1. 아이덴티티

### 1-1. 콘셉트 한 줄

**"오늘 무엇이 나가는지, 그 근거가 어디 있는지 — 송출실 큐시트처럼 읽히는 편성·프로모션 허브."**

일반 협업툴은 "문서를 쓰고 모으는 곳"이다. 우리 실무자는 "이번 주 어느 구좌에 무엇이 나가고, 그 결정의 근거 문서가 무엇인지"를 찾으러 온다. 그래서 화면의 기본 단위를 **문서**가 아니라 **큐(cue): 날짜 · 구좌 · 근거**로 본다.

### 1-2. 키워드 3개

| 키워드 | 뜻 | 화면에서 보이는 모습 |
| --- | --- | --- |
| **온에어 (On-Air)** | 지금·이번 주 나가는 것이 먼저 보인다 | 홈 '이번 주 큐' 7칸 띠, 진행 중 표시용 빨간 램프, 오늘 날짜가 늘 상단바에 있다 |
| **근거 (Source)** | 모든 답과 숫자는 문서 코드로 거슬러 올라간다 | 챗봇 '이 답의 근거 문서' 카드, 문서 코드(PPC-ACS 등)를 타임코드처럼 고정폭 숫자로 표시 |
| **규격 (Spec)** | 구좌·배너 규격·일정처럼 실무 단위로 쪼개 보인다 | 편성표 칸처럼 모서리가 거의 없는 태그, 카테고리 색 띠, 적용대상 [PPM]/[PPV]/[공통] 칩 |

### 1-3. 이름

| 항목 | 제안 | 비고 |
| --- | --- | --- |
| 정식 이름 | 플랫폼 담당 지식 허브 (그대로) | 로그인 화면·문서 제목에 이미 쓰인다. 바꾸지 않는다 |
| 사이드바 표기 | **CUE** 워드마크 + 작은 글씨 "플랫폼 담당 지식 허브" | 방송 진행표(큐시트)에서 따온 말. 특정 회사 상표가 아니다 |
| 브랜드 마크 | 컬러바 3칸(이용 안내·프로모션·편성 색)을 가로로 붙인 12×12 사각형 | 방송 컬러바를 단순화한 모양. 회사 로고를 쓰지 않는다 |
| 챗봇 이름 | **큐 어시스턴트** (창 제목), 버튼은 "묻기" | 지금 "챗봇"·"무엇이든 물어보세요"가 섞여 있다. 하나로 맞춘다 |

"CUE" 표기는 선택안이다. 받아들이지 않으면 브랜드 마크(컬러바)와 정식 이름만 쓰고, 나머지 설계는 그대로 쓸 수 있다 (아래 단계표 '확인 필요').

### 1-4. 말투 (안내 문구 톤)

기준: **방송 PD가 옆자리 동료에게 짧게 알려 주는 말.** 해요체, 한 문장 40자 안팎, 결론부터 말한다.

| 상황 | 쓰지 않는 말 | 쓰는 말 |
| --- | --- | --- |
| 빈 화면 | 데이터가 존재하지 않습니다 | 아직 올라온 문서가 없어요. 첫 문서를 제안해 보세요 |
| 실패 | 오류가 발생했습니다 | 목록을 못 읽었어요. 지금 할 일: 새로고침 · 로그: 개발자 도구 콘솔 |
| 최신성 | 이 문서는 오래되었을 수 있습니다 | 90일 넘게 확인 안 된 문서예요. 담당자에게 확인하고 쓰세요 |
| 챗봇 근거 없음 | 죄송합니다, 답변할 수 없습니다 | 위키에서 근거를 못 찾아서 답하지 않았어요. 문서 제안으로 남길까요? |
| 진행 중 | 처리 중입니다… | 문서 3개를 읽는 중이에요 (보통 10초) |

용어 규칙은 그대로 지킨다: **캠페인**은 Target 프로모션에만, 외부 연동 페이지는 **프로모션 자동화**, B tv+ 는 **[PPM]** 표시. 제휴사 실명·금액은 화면 예시에도 넣지 않는다(시안의 가짜 데이터도 "A사 월정액", "OO 영화 단건"처럼 쓴다).

| 공통 패턴 | 전 | 후 |
| --- | --- | --- |
| 상태 표시 | 테두리 글자 태그(`.tag ok/no/wait`) | ON AIR 램프 + 같은 글자. 상태 이름("대기 중·머지됨·닫힘·승인됨·반려됨")은 **바꾸지 않는다** |
| 행 순서 | 태그 · 제목 · 날짜 · 상태 (상태가 오른쪽 끝) | 상태 · 종류 · 제목 · 날짜 · 행동. 눈이 먼저 닿는 왼쪽에 상태 |
| 종류 전환 | 탭 3개 (각 탭 건수) | 상태 요약 띠 + 종류 칩. 전체를 한 목록으로 보고 거른다 (종류별 0건 탭을 오가며 찾지 않는다: 대기 건 찾기 최대 3클릭 → 0~1클릭) |
| 안내 상자 | 목록 위 회색 상자 | 목록 아래 ⓘ 한 줄 (첫 화면에서 목록이 먼저 보이게) |
| 승인 관리 | 목록·상세 2분할 | 구조 유지, 왼쪽 목록에 램프·종류 색만 더한다 |

탭 → 칩 통합, 행 순서 변경이 요청 흐름에 영향이 있는지는 **requests-planner 확인 후** 반영한다(아래 확인 필요).

Notion식 상태 칸반은 넣지 않는다. 요청 건수가 적고(데모 기준 0~3건), 상태가 사람이 끌어 옮기는 것이 아니라 GitHub PR·승인 결과로 정해지기 때문이다. 끌어 옮길 수 없는 칸반은 오해를 만든다.

## 7. 시안 페이지 만들 때 메모 (PM용)

- 화면 4장(홈 · 문서 · 챗봇 열린 문서 · 내 요청) × 라이트/다크 = 8장이면 판단에 충분하다.
- 가짜 데이터: 문서 코드·제목은 실제 공개 문서(`지식/`)의 것을 써도 된다(이미 공개). 일정·요청은 "홈 9월 편성표 승격", "A사 월정액 프로모션"처럼 실명·금액 없이.
- 캠페인이라는 말은 시안에서도 Target 프로모션(ACS 캠페인 화면) 말고는 쓰지 않는다.
- 시안에 실제 회사 로고·서비스 로고 이미지를 넣지 않는다. 서비스 이름 글자(B tv, 모바일 B tv)는 지금 메뉴에 쓰는 그대로만.
