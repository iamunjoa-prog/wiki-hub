### 2-2. 하단 칸 높이가 안 맞는 이유 — CSS 규칙이 죽어 있고, 내용 양이 한쪽으로 쏠려 있다

측정값 (실무자, 요청 1건, 별표 시스템 3개, 연결됨):

| 화면 | 왼쪽 열 | 오른쪽 열 (요청 / 시스템 / 엔진) | 바닥 차이 |
| --- | --- | --- | --- |
| 1920×1080 창 열림 | 294px | 513px (81 / 259 / 149) | **왼쪽 아래 219px 빈 공간** |
| 1920×1080 창 닫힘 | 294px | 513px | 219px |
| 1440×900 창 닫힘 | 294px | 513px | 219px |
| 1920×1080 창 열림 · 관리자(대기 2건) | 294px | 552px (120 / 259 / 149) | 258px |
| 1440×900 창 열림 | 294px | 513px — **오른쪽 열이 왼쪽 열 아래로 내려감** | 해당 없음(한 열) |

원인은 둘이다.

1. **CSS 규칙이 아무것도 잡지 못한다.** `styles.css` 659-663행은 "오른쪽 열의 마지막 패널이 남는 세로 공간을 채워 왼쪽 열과 바닥선을 맞춘다"는 규칙인데, 대상이 `.right > .panel:last-child` 다. 엔진 칸이 들어오면서 오른쪽 열의 마지막 자식은 `.panel` 이 아니라 `<div id="engine">`(`Dashboard.tsx` 293행)가 됐다. 그래서 이 규칙은 지금 아무 칸에도 걸리지 않는다. 왼쪽 열은 `align-items: stretch`(656행)로 열 자체는 늘어나지만 안의 패널이 늘어나지 않아 패널 아래가 비어 보인다.
2. **내용 양이 오른쪽에 쏠려 있다.** 왼쪽은 7줄 고정(294px) 한 칸, 오른쪽은 칸 3개다. 오른쪽 범위(계산값): 가장 작을 때 요청 0건 81 + 시스템 빈 상태 약 180 + 엔진 149 + 사이 24 = 약 434px, 클 때는 요청 4건 약 197 + 시스템 카드 n개(카드당 약 68px, **상한 없음**) + 엔진 미연결 약 200 + 24. CSS 를 고쳐도 왼쪽 칸 안에 140~400px 빈 공간이 남는다.

덧붙여, 창을 열면 본문 폭이 줄어 두 열 기준 폭(480 + 300 + 14px, 657-658행)이 안 들어가는 순간 한 열로 내려앉는다. 창 너비 기본값이 화면의 33%(`AssistantDock.tsx` 346행)라 대략 화면 폭 1,630px 미만(계산값)에서는 창을 열면 늘 한 열이다. 이때는 높이보다 **쌓이는 순서**가 중요하다. 지금 순서는 최근 문서 → 요청 → 시스템 → 엔진.

## 3. 연결 흐름 개선안

원칙: **홈 엔진 칸 = 계정 관리(로그인·다시 확인·설정)**, **어시스턴트 = 이번 답을 누가 하는지(상태 한 줄 + 고르기)**. 설정 창은 하나만 두고 어디서 열어도 같은 창이다.

### 3-1. 제안 5가지

| # | 제안 | 해결 | 전 → 후 |
| --- | --- | --- | --- |
| F1 | **어시스턴트 입력칸 위에 엔진 상태를 글자로.** 지금 `EngineToggle` 줄을 상태 줄로 바꾼다. 연결됨: "답변 엔진 [Claude][ChatGPT] ⚙". 미연결(로컬): 버튼 대신 "● 내 계정이 연결 안 됨 · 간단한 답만 드려요 [연결하기]". 공용 엔진으로만 답할 때: "● 공용 AI로 답해요 · 차이 보기". 상태를 모르면(`engines` null): "● 문서에서 찾은 내용만 정리해 드려요" | P1 | 마우스 올려야 앎 → 질문 쓰는 자리에서 0클릭으로 보임 |
| F2 | **설정 창을 어디서나 연다.** `CliStatus` 안의 설정 창을 떼어 앱 전체에서 한 번 그리고, 홈 칸 [⚙ 연결 설정] · 인사 줄 상태 · 어시스턴트 [연결하기]·⚙ 가 모두 같은 창을 연다 | P2 | 어시스턴트 → 연결 3클릭(길을 알 때) → **1클릭**(설정 창) + [로그인] 1 = 2클릭, 어느 화면에서나 |
| F3 | **연결되면 바로 질문으로.** 로그인 성공을 감지한 순간(`CliStatus.tsx` 66행 자리) ① 토스트 "Claude 계정이 연결됐어요" ② 설정 창 해당 줄에 [바로 물어보기 ›] — 누르면 설정 창 닫고 어시스턴트 열고 입력칸에 커서 ③ 어시스턴트에 직전 "규칙 기반" 답이 있으면 그 답 아래에 [내 계정으로 다시 묻기] 칩 | P4 | 연결 후 묻기 바·묻기 버튼을 스스로 찾음 → 1클릭으로 입력칸 |
| F4 | **미연결 상태에서 받은 답에 이유와 할 일 한 줄.** 엔진이 하나도 없어 규칙 기반으로 답했을 때 답 아래: "내 계정이 연결되지 않아 문서에서 찾은 내용만 정리했어요. [연결하기]". 배포 허브에서 공용 키가 없을 때는 "지금은 AI 엔진을 쓸 수 없어 문서에서 찾은 내용만 정리했어요. 계속되면 관리자에게 알려 주세요." (연결하기 버튼 없음) | P3 | 이유 없음 → 답 바로 아래에서 1클릭으로 설정 창 |
| F5 | **이름을 하나로.** 화면에 보이는 이름은 "Claude · ChatGPT · 공용 AI" 셋만 쓴다. "Codex"·"Gemini" 는 관리자용 코드 줄(`AssistantDock.tsx` 142·189행)과 설정 창 "고급 설정(담당자용)" 안에만 남긴다. 저장값(`'codex'`, `'gemini'`)과 대화 기록의 원래 값은 그대로 둔다 — 보이는 이름만 바꾼다 | P5 | 같은 계정을 세 이름으로 → 한 이름 |

함께 정리할 작은 것:

- 홈 엔진 칸은 계정 관리만 한다. 지금 내용 그대로 두고 링크 여백(P8)만 고친다.
- 인사 줄 상태(`EngineLine`)는 F5 이름을 따르고, 미연결일 때는 스크롤 대신 설정 창을 연다(F2). 연결됨일 때는 지금처럼 엔진 칸으로 스크롤.
- P7(예시 질문 겹침)은 열린 질문 7번으로 넘긴다.

## 4. 하단 칸 높이 맞추기 — 안 비교

| 안 | 내용 | 장점 | 단점 | 구현 난이도 |
| --- | --- | --- | --- | --- |
| 1. 바닥선만 맞춤 | 죽은 규칙(659-663행)을 "각 열의 마지막 칸이 남는 높이를 채운다"로 고친다 | 고칠 곳이 CSS 몇 줄. 테두리 바닥선이 맞는다 | 왼쪽 칸 안에 219px 안팎 빈 공간이 그대로 남는다. 겉만 맞음 | 하 |
| 2. 칸 높이 고정 + 안쪽 스크롤 | 칸마다 높이를 정하고 넘치면 칸 안에서 스크롤 | 높이가 늘 같다 | `.content` 스크롤 안에 또 스크롤 — 초보자가 숨은 항목을 놓친다. 시스템 카드가 반쯤 잘려 보인다. 짧은 칸은 여전히 빈다 | 중 |
| 3. 항목 수 상한 + 더 보기 | 시스템 3개까지 + "외 n개 · 전체 ›"(이미 있는 머리 [전체 ›] 와 같은 곳으로). 요청 4줄, 문서 7줄은 그대로 | 높이 범위가 정해진다(시스템 칸 최대 259px). 시스템 화면이 이미 있어 막다른 길이 없다 | 혼자서는 쏠림(왼쪽 1칸 vs 오른쪽 3칸)을 못 고친다 | 하 |
| 4. 엔진 칸을 왼쪽 열로 | 왼쪽: 최근 갱신 문서 + 챗봇 답변 엔진 / 오른쪽: 요청 + 시스템 | 열마다 칸이 2개로 균형. 한 열로 내려앉을 때 엔진 칸이 4번째 → 2번째로 올라온다(P6) | 엔진 칸이 오른쪽 어시스턴트 창과 멀어진다 — F1(창 안 상태 줄)이 있으면 문제 작음 | 하 |
| 5. 엔진 칸을 접어 인사 줄 + 설정 창으로 | 하단에서 엔진 칸을 빼고, 인사 줄 상태와 설정 창(F2)이 그 일을 맡는다 | 중복이 가장 적다. 하단이 2칸 대 1칸 구조로 단순해진다 | 미연결 초보자가 [로그인] 버튼을 홈에서 바로 못 본다(인사 줄 1클릭 더). 웹 주소 허브의 "내 PC에서 쓰기" 입구도 인사 줄로 옮겨야 한다 | 중 |
| 6. 2×2 격자, 행 높이 통일 | [최근 문서 · 요청] / [시스템 · 엔진] 으로 놓고 행마다 높이 맞춤 | 칸 경계가 반듯하다 | 1행이 294px vs 81px 로 요청 칸 안에 213px 빈 공간. 문제를 옮길 뿐 | 중 |

### 4-1. 추천 — 안 4 + 안 3 + 안 1 (엔진 칸 왼쪽 이동 · 시스템 3개 상한 · 바닥선 맞춤)

예상 높이 (계산값, 지금 칸 높이 측정값으로 합산):

| 경우 | 왼쪽 (문서 294 + 사이 12 + 엔진) | 오른쪽 (요청 + 사이 12 + 시스템) | 남는 빈 공간 |
| --- | --- | --- | --- |
| 실무자, 요청 1, 시스템 3, 연결됨 | 455 | 81 + 12 + 259 = 352 | 103 (지금 219) |
| 관리자, 대기 2, 시스템 3 | 455 | 391 | 64 (지금 258) |
| 요청 4, 시스템 3 (가장 큼) | 455 | 468 | 13 |
| 미연결(안내 상자 포함) | 약 506 | 352 | 154 |

- 남는 공간은 **짧은 열의 마지막 칸 안 아래쪽**에 빈칸으로 둔다. 카드·줄이 늘어나지 않게 한다(시스템 카드 격자는 위에 붙임).
- 한 열로 내려앉을 때 순서: 최근 갱신 문서 → 챗봇 답변 엔진 → 요청 → 시스템.
- 빈 공간을 더 줄이려면 최근 갱신 문서를 5줄로(열린 질문 2번): 실무자 기준 103 → 31px.

### 4-2. 대안 — 안 5 + 안 3 + 안 1 (엔진 칸 접기)

F2(설정 창 공용화)가 먼저 반영돼야 한다. 하단은 왼쪽 최근 문서 294 vs 오른쪽 요청 + 시스템 352(실무자 기준) — 빈 공간 58px. 엔진 중복이 가장 적지만, 미연결 초보자의 [로그인]이 1클릭 멀어진다(홈 → 인사 줄 → 설정 창 [로그인]). 추천안을 먼저 반영하고, 엔진 칸이 실제로 덜 쓰이는지 본 뒤 고르는 순서를 권한다.

dev-front 보고(3개)보다 하나 더 있다 — 홈 묻기 바 [묻기]는 창이 열려도 빨강으로 남는다. 그리고 **연결된 상태에서도** 4개다. 미연결만의 문제가 아니다.

원인:

1. 빨강 규칙이 두 문서에 다르게 적혀 있다. identity-redesign 2-4 "한 화면에 빨강 덩어리 하나", 이 문서 수용 기준 11 "홈 본문은 [묻기] 하나, 어시스턴트 미연결 상태는 [연결하기] 하나". 11번은 본문과 창을 따로 셌고, 엔진 칸 [로그인]·[↩]·선택 칸은 어느 쪽에도 적혀 있지 않았다.
2. [로그인]·[↩]·선택 칸은 이 규칙이 생기기 전부터 빨강이었다(`--accent` 가 빨강 하나뿐이던 때). 상단바 [묻기]만 "창이 열리면 숨김"·"홈은 테두리형"으로 정리됐다.

### A-2. 규칙 (확정안)

| # | 규칙 |
| --- | --- |
| R1 | **빨강 = "지금 누를 다음 한 걸음".** 화면 전체(본문 + 어시스턴트 창)에 **0개 또는 1개**. 모달(설정 창 등 뒤를 가리는 창)이 떠 있으면 모달 안에서 0~1개 |
| R2 | 빨강은 **누르는 버튼에만.** 선택된 상태(엔진 고르기 선택 칸, 탭)는 남색(`--text`) 바탕으로 — 이미 `.btv-seg button.on`(1807행)이 쓰는 모양 |
| R3 | 어시스턴트 창이 열려 있으면 빨강은 **창 안에만.** 본문의 묻기 버튼(상단바·묻기 바)은 창이 열리면 숨기거나 테두리형. 상단바 [묻기]가 이미 이렇게 동작한다 |
| R4 | 누를 수 없는 버튼(비활성)은 빨강으로 그리지 않는다. 흐린 빨강은 "누를 수 있는 것" 처럼 보인다 → 테두리형 비활성 |
| R5 | 홈 엔진 칸·설정 창의 [로그인]은 계정 관리 버튼이라 본문에서 빨강을 쓰지 않는다. 미연결 신호는 지금 있는 것(인사 줄 "엔진 연결 안 됨"·앰버 점·"로그인이 필요해요" 앰버 글자·`.cli-alert` 안내 상자)이 맡는다 |
| R6 | 지우기 같은 되돌릴 수 없는 버튼은 빨강(온에어)이 아니라 위험 색 영역이다 — 이번 범위 밖, A-6 참조 |

수용 기준 11을 이렇게 바꾼다:

> 11. 빨간 버튼은 화면 전체(본문 + 어시스턴트 창)에 최대 1개, 모달이 떠 있으면 모달 안 최대 1개. 홈은 창이 닫혀 있으면 묻기 바 [묻기], 창이 열려 있으면 A-3 표대로. 선택된 엔진 칸과 비활성 버튼은 빨강이 아니다.
