## 2. 구조 변경 (메뉴·라우트) — dev-front 커밋 1

| 바뀌는 것 | 전 | 후 | 파일 |
| --- | --- | --- | --- |
| 라우트 2개 추가 | 없음 | `/chat-log` (관리자 "대화 기록"), `/my-chat-log` ("내 대화 기록") | `src/App.tsx` |
| 사이드바 "내 업무" | 내 요청 현황 · 승인 관리 · 계정 관리 | 내 요청 현황 · **내 대화 기록** · 승인 관리 · 계정 관리 · **대화 기록** | `AppShell.tsx` |
| "내 대화 기록" 보이는 조건 | — | `account` 가 있고(웹 주소 허브 로그인) 저장 상태 `enabled` 가 `true` 일 때만 | 같은 곳 |
| "대화 기록" 보이는 조건 | — | `account?.role === 'admin'` 이고 `enabled` 가 `true` 일 때만. 계정 관리와 같은 조건을 쓴다. **`session.role` 로 판단하지 않는다** — 내 PC용 허브는 데모 버튼으로 관리자가 될 수 있고, 거기서는 기록을 읽을 API가 없다 | 같은 곳 |

이름과 자리를 이렇게 정한 이유:

- **"내 요청 현황"의 탭으로 넣지 않는다.** 그 화면의 탭은 모두 "제출 → 승인/반려" 상태가 있는 요청이다(`MyRequests.tsx:45-55`). 대화 기록에는 상태가 없어서 탭으로 넣으면 같은 화면 안에서 성격이 섞인다. 요청 섹션 흐름은 requests-planner 몫이라 그 화면을 건드리지 않는 쪽이 선이 깔끔하다.
- **관리자 메뉴 이름은 "대화 기록", 사용자 메뉴는 "내 대화 기록"** 으로 "내 요청 현황 / 승인 관리" 처럼 "내 ~ / 관리용" 짝을 맞춘다. 관리자 메뉴는 승인 관리·계정 관리 뒤, 묶음 맨 아래에 둔다(기획서 5절 "같은 묶음").
- 저장이 꺼진 곳(내 PC용 허브 대부분, 계정 기능 꺼진 데모)에서는 두 메뉴 모두 **숨긴다**. 눌러도 막다른 길이기 때문이다. 위키 트리의 "준비중" 처리(`AppShell.tsx:73-78`)는 "언젠가 생길 문서" 용이라 여기 쓰지 않는다.
- 저장 상태(`view=status`)는 앱이 열릴 때 **한 번만** 묻고 `AppStore` 에 둔다. 사이드바 메뉴·챗봇 창 고지·"지난 대화" 링크가 같은 값을 본다. 묻다가 실패하면 셋 다 숨긴다(기획서 6절: 응답이 없으면 문구를 보이지 않는다).

**"지난 대화" 링크**

| 항목 | 설계 |
| --- | --- |
| 위치 | `.dock-head` 오른쪽, 닫기 ▸ 바로 왼쪽. 글자 버튼 하나(`.cli-os-switch` 처럼 밑줄 없는 회색 글자 버튼, 12px) |

#### 머리·안내

- `.panel-head`: 제목 "대화 기록" · `tag solid` "관리자 전용" · 오른쪽 "새로고침" 버튼(`btn sm`). 승인 관리(`Approvals.tsx:105-110`)와 같은 모양이다.
- 그 아래 `.hint` 한 덩어리(A-2). 90일 자동 삭제, 내보내기 없음, 공개 저장소로 옮길 때 경향으로 쓰기, 웹 주소 허브의 "중간에 멈춤" 한계(기획서 3절 "취소의 한계")를 한곳에 모은다. 처음 쓰는 관리자가 읽을 양은 3줄이다.

#### 사용량 띠

| 칸 | 큰 숫자 | 작은 줄(`.sub`) | 경고색 조건 |
| --- | --- | --- | --- |
| 오늘 저장 | `오늘 건수 / 하루 상한` (예: 312 / 500) | 상한 초과가 있으면 A-5. 없으면 비움 | 상한의 70% 이상 |
| 최근 90일 | `n건` | "90일 지나면 저절로 지워져요" | 없음 |

- 모양은 대시보드 `.kpi-grid` 를 그대로 쓴다. 대시보드보다 낮은 띠가 맞으므로 큰 숫자는 20px로 줄인 변형(`.kpi-grid.compact`)만 더한다.

- 사용량을 못 읽으면 띠 4칸에 "—" 를 넣고 띠 아래에 E-3 한 줄. **목록은 그대로 보인다**(사용량 실패가 목록을 막지 않는다).

#### 같은 대화 보기

- 1클릭으로 **넓은 창**(`.modal-back.report-wide-back` > `.modal.report-wide`, `ReportCard.tsx:336-337` 와 같은 모양)을 연다. 주소는 바꾸지 않는다.

- 들어온 질문의 말풍선은 왼쪽에 `--accent` 2px 선을 두르고, 창이 열릴 때 그 위치로 스크롤한다.

- 불러오는 중 A-15, 못 읽으면 E-1 문구를 창 안에 보인다.

#### 이 질문 기록 지우기 (D4)

- "한 건"은 화면에서 **질문 한 줄**이다. 한 질문의 시도가 여러 개면 모두 함께 지운다. 질문 원문이 시도마다 들어 있어서, 일부만 지우면 잘못 넣은 개인 정보가 남는다.
- 확인 창은 반려 사유 창(`Approvals.tsx:9-44`)과 같은 `.modal` 모양, 입력칸은 없다.

```
┌ 이 기록을 지울까요? ───────────────────┐
│ 오늘 14:02 · 홍길동                    │
│ "쿠폰 결재선은 누가 승인하나요?"        │  ← 질문 앞 60자
│ 지우면 되돌릴 수 없어요.               │
│ 엔진을 바꿔 다시 시도한 기록 1건도      │  ← 시도가 2개 이상일 때만
│ 함께 지워져요.                         │
│ [지우기]  [취소]                       │
└────────────────────────────────────────┘
```

- 처음 초점은 **[취소]** 에 둔다. Enter를 잘못 눌러 지우는 일을 막는다. [지우기]는 `btn primary`(빨강 강조색)를 쓴다.
- 지우는 중에는 두 버튼을 잠그고 [지우기] 글자를 "지우는 중…"으로 바꾼다.
- 성공하면 창을 닫고 그 줄을 목록에서 뺀 뒤 토스트 D-4 "기록을 지웠어요". 사용량 띠는 다음 새로고침 때 맞춘다.
- 일부만 지워졌거나 실패하면 창을 닫지 않고 창 안에 E-5. 다시 [지우기]를 누르면 남은 것만 다시 지운다.

## 5. 휴대폰 폭 (760px 이하)

기존 기준점은 `styles.css:1525` 의 760px 하나다. 새 기준점을 만들지 않는다.

| 화면 | 760px 이하에서 |
| --- | --- |
| 챗봇 창 고지 | 그대로 2~3줄로 감싼다. 글자를 줄이지 않는다 |
| "지난 대화" | 누르면 챗봇 창을 닫고 본문으로 간다(3-1). 1절 390px 캡처처럼 창이 열린 채면 본문이 70px라 읽을 수 없다 |
| 사용량 띠 | `.kpi-grid` 를 2칸 × 2줄로. 칸 이름은 줄이지 않고 감싼다 |
| 필터 | 기간 칩 줄만 늘 보이고, 나머지(사용자·엔진·모드·결과·근거 없음)는 "조건 더 보기 ({켜진 수})" `btn sm` 아래로 접는다. 켜진 조건이 있으면 버튼에 수가 보인다 |
| 관리자 목록 줄 | 한 줄에 다 넣지 않고 3줄로 쌓는다. 1줄: 모드 tag · 시각 · 이름 · 결과 tag. 2줄: 질문 앞부분(2줄까지). 3줄(회색 작은 글자): 엔진 경로 · 근거 수 · 걸린 시간 |
| 펼친 줄의 시도 표 | 표 대신 시도마다 2줄 목록("1. Claude · 실패 · timeout" / "120.0초 · 내 PC용 허브") |
| 같은 대화 창 | 화면 꽉 채움(가로 100%, 세로 100%). 닫기 ✕ 는 머리 오른쪽에 고정 |
| 지우기 확인 창 | 기존 `.modal` 그대로(가로 `calc(100vw - 32px)` 로 줄어드는지 확인) |
| 내 대화 기록 카드 | 카드 폭 100%. [복사] 버튼은 시각 줄 오른쪽 그대로 |

## 8. API에 기대는 것 (dev-server 확인 필요)

기획서 5절 API로 대부분 되지만 아래 세 가지는 계약에 없거나 모호하다.

| # | 화면에 필요한 것 | 기획서 계약 | 요청 |
| --- | --- | --- | --- |
| P-1 | 같은 대화 보기: 한 `chatId` 의 기록 전부 | `view=all` 에 `chatId` 필터가 없다 | `view=all&chat=<chatId>` (최대 200건, 관리자만). 안 되면 같은 대화 보기는 "지금 불러온 목록 안에서만" 보여 주는 약한 형태가 된다 |
| P-2 | 질문 한 줄 지우기: 같은 `turnId` 의 시도 전부 | `DELETE ?id=` 한 건씩 | 화면이 id마다 여러 번 부르면 되므로 필수는 아니다. `DELETE ?turn=<turnId>&chat=<chatId>` 가 있으면 일부만 지워지는 경우(E-5)가 줄어든다 |
| P-3 | "지난 대화"·"내 대화 기록" 보이는 조건 | `view=status` 는 `{ enabled, retentionDays }` 뿐 | `view=status` 에 `mine: boolean`(이 허브에서 본인 기록을 볼 수 있나)을 더해 주면 화면이 `account`·`isLocalStatus` 를 따로 조합하지 않아도 된다. 없으면 dev-front는 "`account` 있음 && `enabled`" 로 판단한다 |
