## 1. ① 대시보드 업무 시작 카드

### 1.1 현재 흐름 (경로)

`src/App.tsx` `/` → `src/pages/Dashboard.tsx` → `.dash-wrap` 안에 `.kpi-grid`(62–90행) → `.dash-cols`(92행~, 왼쪽 최근 문서·요청 / 오른쪽 `CliStatus`·자주 사용하는 시스템). 첫 화면에서 "업무를 시작하는" 버튼은 0개.

### 1.2 바뀐 배치 (위 → 아래)

```
TopBar (그대로)
.dash-wrap
 ├─ [새] .task-head   "오늘 무엇을 하시나요?"                  처음이라면: 지식 허브 둘러보기
 ├─ [새] .task-grid   [프로모션 기획] [편성 확인] [정책 확인] [시스템 사용법]
 ├─ .kpi-grid (그대로 4칸, 위치만 카드 아래로 · margin-top 14px)
 └─ .dash-cols (그대로)
```

- 카드는 역할(관리자·실무자) 상관없이 같은 4장, 같은 순서, 같은 위치(A8). 숨기기·접기 없음(Q5).
- 1280×800, 독 닫힘 기준 세로 예산: 상단바 44 + 여백 16 + 제목 줄 약 28 + 카드 약 92 + 간격 14 + KPI 약 112 ≈ 306px → 카드와 KPI 모두 스크롤 없이 보인다(A1). 독을 열면(본문 약 560px) 카드가 2×2 로 접혀 약 190px, 그래도 KPI 까지 첫 화면 안.

**제목 줄 `.task-head`**

- 왼쪽: 제목. 화면의 첫 제목이라 요소는 `<h2>` 로 두되, 모양은 기존 `.panel-head` 제목과 같은 `.label.strong` 을 쓴다(새 글자 크기를 만들지 않음).
- 오른쪽(`margin-left: auto`): 첫 방문 안내 링크. 패턴은 `WikiIndex.tsx` 80–84행 `.wiki-first` 와 같게 `처음이라면: <Link>{문서 제목}</Link>` 형태. 대상은 `docs.find((d) => d.code === 'HUB-01')` (`지식/guide/tour.md`, 경로 `/wiki/HUB-01`). 문서가 없으면 줄을 그리지 않는다. 링크 글자는 문서 제목을 그대로 쓴다(현재 "지식 허브 둘러보기").

**카드 그리드 `.task-grid`**

- `display: grid; grid-template-columns: repeat(auto-fit, minmax(180px, 1fr)); gap: 8px; margin-top: 8px;` — 본문 폭 ≥ 약 760px 이면 4열, 독을 열어 좁아지면 2열, 600px 이하 1열.
- 카드 요소는 `<button type="button" className="link-card task-card">` — 기존 `.link-card`(styles.css 535–549행, 시스템 카드와 같은 테두리·hover 그림자) 재사용. 새 색 없음.
- 카드 안 3줄 (모두 기존 클래스):
  1. `.t` 카드 이름 (`.link-card .t` 굵게)
  2. 설명 한 줄 — `<span className="muted">`, 13px, 두 줄 넘으면 그대로 줄바꿈(말줄임 금지: 처음 온 사람이 끝까지 읽어야 하는 문장)
  3. 가는 곳 힌트 — `<span className="mono muted">` 12px, 끝에 `→`. 이 줄이 "어시스턴트가 열리는지 / 화면으로 가는지"를 미리 알려 준다
- 키보드: 4장 모두 `button` 이라 Tab 순서대로 닿고 Enter/Space 로 동작(A4). 포커스 표시는 브라우저 기본 + `.link-card:hover` 와 같은 테두리.

**KPI**

- 4칸·클래스·클릭 동작(승인 대기 → `/approvals`, 내 대기 요청 → `/requests`) 모두 그대로(A5). 위치만 카드 아래.
- "이번 주 업데이트" 칸에만 보조 줄 하나 추가: `<span className="sub muted">{M}/{D}(월)부터</span>` — 월요일에 숫자가 작게 보여도 기준을 바로 알 수 있게(Q2 단점 보완). 예: 2026-11-19(목) → `11/16(월)부터`.

### 1.4 "이번 주 업데이트" 세는 규칙 (Q2 확정)

dev-front 구현 기준(문장으로 정의, 코드는 dev-front):

1. 오늘 날짜는 **PC 시간대와 상관없이 한국 시간**으로 구한다(`Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })` → `YYYY-MM-DD`). 요일도 한국 시간 기준.
2. 이번 주 월요일 = 오늘이 월요일이면 오늘, 일요일이면 6일 전, 그 밖에는 (요일 − 1)일 전.
3. 센다: `updatedAt` 이 `YYYY-MM-DD` 꼴이고 `월요일 ≤ updatedAt ≤ 오늘` 인 문서.
4. 세지 않는다: `'-'`, 빈 값, 날짜 꼴이 아닌 값, 오늘보다 뒤 날짜(오타 방어).
5. `Dashboard.tsx` 에 고정 날짜 문자열을 남기지 않는다(A7).
6. 보조 줄 `{M}/{D}(월)부터` 는 2번에서 구한 월요일로 만든다(앞자리 0 없이).

확인(A6): 문서 3개의 `updatedAt` 을 이번 주 월요일 · 지난주 일요일 · 오늘로 두면 2.

## 2. ② 빈칸 채우기형 질문 템플릿 (독 안 UI)

### 2.1 입구 — 두 군데 (Q4 확정)

| 입구 | 위치 | 보이는 조건 | 동작 |
| --- | --- | --- | --- |
| 독 | `QuickActions`(`AssistantDock.tsx` 296–315행) "바로 확인하기" 줄의 **4번째 버튼** `빈칸 채워 질문하기` | **항상** — `QuickActions` 는 `messages.length` 와 상관없이 독 머리 아래 고정이라 빈 대화·진행 중 대화 모두 보인다(B7) | 패널 열기/닫기 토글. `aria-expanded` 로 열림 상태 표시. 처음 열면 템플릿 목록 첫 번째(프로모션 기획형)가 골라진 상태 |
| 대시보드 | ① 카드 1 "프로모션 기획" | 대시보드 첫 화면 | 독을 열고 프로모션 기획형으로 패널을 연다(§2.6) |

- 아이콘: `QuickIcon` 에 연필 모양 1개 추가(`name: 'pencil'`, path `M4 20h4L19 9l-4-4L4 16v4Z` 정도, 14px 선 아이콘 규칙 그대로). 새 색 없음.
- 기존 `프로모션 기획 시작하기`(= `send(PLAN_STARTER)`)는 **그대로 둔다** — 진행 의도 확인 → 어드민 연결 흐름이라 빈칸 질문과 목적이 다르다. 두 버튼이 나란히 있어 헷갈리는지는 dev-front 반영 후 검수 때 다시 본다(보고 표 "확인 필요").

### 2.2 패널 위치와 모양

- 패널 `.dock-template` 은 **`.dock-log` 와 `.dock-foot` 사이**에 끼운다. 대화 기록 위가 아니라 입력창 바로 위에 두어 "여기서 만든 문장이 이 입력창 자리로 보내진다"는 관계가 보이게 한다. 열려 있는 동안 `.dock-log` 는 남은 높이로 줄고 스크롤된다(이미 `flex: 1; overflow: auto`).
- 테두리·바탕: `border-top: 1px solid var(--border); background: var(--surface-subtle); padding: 10px 12px; display: flex; flex-direction: column; gap: 8px;` — `.dock-quick` 과 같은 간격 체계. 최대 높이 `50%` 넘으면 패널 안에서 스크롤.
- 패널을 연 채로 일반 입력창도 쓸 수 있다(입력창을 막지 않음).

```
┌ 빈칸 채워 질문하기 ───────────────────────── [닫기] ┐
│ 질문 틀  (프로모션 기획) (정책 확인) (시스템 사용법) │  ← .suggest 버튼, 고른 것 aria-pressed=true
│                                                        │
│ [ 상품 ▾ ] 프로모션을 [ 혜택 ▾ ] 방식으로 기획하려고 해 │  ← 문장 줄: 글자 + 빈칸 버튼
│                                                        │
│ 상품 고르기                                            │  ← 지금 고르는 빈칸 이름
│ (B tv+) (지상파·종편·CP 월정액) (영화 PPV) (영화 외 PPV)│  ← .suggest 값 버튼
│                                                        │
│ 보낼 문장                                              │
│ 빈칸 2개를 채우면 문장이 완성됩니다                    │  ← 다 채우면 완성 문장으로 바뀜
│                                        [취소] [보내기] │
└────────────────────────────────────────────────────────┘
```

### 2.3 요소별 규칙

| 요소 | 마크업·클래스 | 규칙 |
| --- | --- | --- |
| 머리 | `.panel-head` 와 같은 한 줄: 왼쪽 `.label.strong` 제목, 오른쪽 `.btn.sm` `닫기` | `닫기` = 취소와 같은 동작 |
| 질문 틀 고르기 | 라벨 `.label` + `.suggest` 버튼 묶음 (`role="group"`, `aria-label="질문 틀"`) | 버튼 글자 = 템플릿 `label`. 다른 틀을 고르면 채운 빈칸은 모두 비운다(확인 창 없음 — 다시 고르는 데 클릭 3번이면 충분). 같은 틀을 다시 누르면 아무 일 없음 |
| 문장 줄 | `<p className="tpl-sentence">` 안에 고정 글자(`span`)와 빈칸(`button`)을 문장 순서대로 | 글자 크기·글꼴은 `.msg-text` 와 같게(보낼 말풍선과 같은 모양으로 미리 보이게) |
| 빈칸 버튼 — 비어 있음 | `button.tpl-slot.empty` · 글자 = 빈칸 이름 + ` ▾` · 테두리 `1px dashed var(--line)` | `aria-label="{빈칸 이름} 빈칸, 비어 있음"` |
| 빈칸 버튼 — 채움 | `button.tpl-slot.filled` · 글자 = 고른 값 · 테두리 실선 `var(--line)`, 글자 `var(--text)` | `aria-label="{빈칸 이름} 빈칸, {값} 선택됨"` |
| 빈칸 버튼 — 지금 고르는 중 | `.tpl-slot.on` · 테두리·글자 `var(--accent)` (`.suggest button:hover` 와 같은 색) | `aria-expanded="true"`, `aria-controls` = 값 목록 id. 한 번에 하나만 `on` |
| 값 목록 | 라벨 `{빈칸 이름} 고르기` + `.suggest` 버튼 묶음 (`role="group"`) | 지금 `on` 인 빈칸의 값만 보인다. 이미 고른 값 버튼은 `aria-pressed="true"` + `.on` 강조. 값 버튼 글자 = 빈칸에 들어갈 글자 그대로(별도 표시 이름 없음 — 보이는 글자와 보내는 글자가 같아야 B2 가 성립) |
| 보낼 문장 | 라벨 `.label` `보낼 문장` + 본문 | 빈칸이 남았으면 `빈칸 {남은 수}개를 채우면 문장이 완성됩니다`(muted). 다 채우면 완성 문장을 `.msg.user` 모양(오른쪽 말풍선과 같은 바탕) 한 덩이로 보인다 |
| 취소 | `.btn.sm` `취소` | 패널을 닫고 빈칸을 모두 비운다. 포커스는 입구 버튼(독의 `빈칸 채워 질문하기`)으로 |
| 보내기 | `.btn.sm.accent` `보내기` | §2.4 비활성 조건. 누르면 `ask(완성 문장)` 1회 → 패널 닫힘 → 빈칸 비움 → 포커스는 입력창으로 |

**처음 열 때와 고를 때의 자동 이동 (클릭 수를 줄이는 핵심)**

- 패널이 열리면 **첫 번째 빈칸이 자동으로 `on`** 이고 그 값 목록이 이미 펼쳐져 있다 → 빈칸을 따로 누르지 않고 바로 값을 고른다.
- 값을 고르면 `on` 이 **다음 빈 빈칸**으로 자동으로 옮겨 간다(문장 순서로 다음, 없으면 앞쪽 빈 빈칸). 빈 빈칸이 하나도 없으면 `on` 을 없애고 값 목록을 접는다.
- 채운 빈칸을 누르면 그 빈칸이 다시 `on` 이 되고 값을 바꿀 수 있다. 바꾼 뒤에는 위 규칙대로 다음 빈 빈칸으로(없으면 접힘).
- 그래서 확정 템플릿(빈칸 2개)은 **값 2번 + 보내기 1번 = 3클릭**(대시보드에서 오면 카드 1번 더해 4클릭), 타이핑 0.

**빈칸이 다른 빈칸에 딸린 경우** — 확정 템플릿 3개 모두 두 번째 빈칸(`[혜택]`·`[정책 항목]`)이 `dependsOn: 'product'` 다. 상품에 따라 고를 수 있는 값이 다르다(예: `단건(PPV)` 를 고르면 PPM 전용 항목인 전환동의·약정·해지방어가 보이지 않음).

- 상수에서 빈칸이 `dependsOn: '<앞 빈칸 id>'` 를 가지면, 앞 빈칸이 비어 있는 동안 이 빈칸 버튼은 `disabled` 이고 `title` 은 고정 문구 `앞 빈칸을 먼저 고르세요`(문구표 A-9)다. 앞 빈칸 이름을 끼워 넣지 않는 이유는 받침에 따라 조사가 바뀌기 때문이다.
- 앞 빈칸 값을 바꾸면 딸린 빈칸은 비운다.

### 2.4 보내기 비활성 조건

보내기 버튼은 아래 중 하나라도 맞으면 `disabled`:

| 조건 | 버튼 `title` (마우스 올리면) |
| --- | --- |
| 빈칸이 하나라도 비어 있음 (B2) | `빈칸을 모두 채워 주세요` |
| 어시스턴트가 답을 만드는 중 (`assistant.pending === true`) | `답을 받는 중에는 보낼 수 없습니다` |

- 두 조건이 함께면 위쪽(빈칸) 문구를 쓴다.
- 답을 받는 중에도 패널 열기·빈칸 고르기는 된다(다음 질문을 미리 준비할 수 있게). `pending` 이 끝나면 보내기가 저절로 켜진다. 기존 `리포트로 자세히 받기` 칩도 `disabled={assistant.pending}` 이라 같은 결이다.

### 2.5 키보드 흐름 (B1 — 키보드만으로 끝까지)

1. Tab 으로 `빈칸 채워 질문하기` → Enter → 패널 열림, 포커스는 **지금 `on` 인 빈칸의 첫 값 버튼**.
2. Tab/Shift+Tab 으로 값 사이 이동, Enter/Space 로 고름 → 다음 빈칸이 `on` 이 되고 포커스는 **그 빈칸의 첫 값 버튼**으로 옮겨 간다.
3. 마지막 빈칸을 채우면 포커스는 `보내기` 로.
4. 탭 순서(패널 안): 닫기 → 질문 틀 버튼들 → 문장 줄의 빈칸 버튼들 → 지금 값 목록 → 취소 → 보내기.
5. 패널 안 어디서든 `Esc` = 취소(패널 닫고 빈칸 비움, 포커스는 입구 버튼). 입력창에 포커스가 있을 때의 Esc 는 건드리지 않는다.
6. 화면낭독기: 패널은 `role="region"` + `aria-label="빈칸 채워 질문하기"`. 빈칸 수 안내 문장(`빈칸 n개를 채우면…`)에 `aria-live="polite"` 를 걸어 값을 고를 때마다 남은 수가 읽히게 한다.

### 2.6 대시보드 카드에서 열기 (Q3 확정 — 상태 연결)

- 현재 대시보드가 독을 여는 길은 `useApp().ask(text)`(독 열고 바로 보냄)와 `openDock()` 뿐이다. "패널을 연 채로 독 열기"는 없는 길이라 **`src/store/AppStore.tsx` 에 작은 상태 하나가 필요하다**: 예) `openQuestionTemplate(templateId)` = `setDockOpen(true)` + "열 템플릿 id" 저장, 독은 이 값을 받아 패널을 연 뒤 값을 지운다. 서버·`api/` 변경 없음.
  - 기획 문서는 "연결 방식은 `navigate()` 와 `ask()` 만"이라고 적었지만, Q3(나)를 고르면서 이 한 가지가 늘어난다. PM 데스크 확인 필요 항목으로 올린다.
- 동작 규칙:
  - 독이 닫혀 있으면 열고, 패널을 프로모션 기획형으로 연다.
  - 독·패널이 이미 열려 있고 **같은 템플릿**이 골라져 있으면 채운 빈칸을 유지한다(실수로 카드를 다시 눌러도 잃지 않게). 다른 템플릿이면 프로모션 기획형으로 바꾸고 빈칸을 비운다.
  - 포커스는 첫 빈 빈칸의 첫 값 버튼.

### 2.7 확정 템플릿 3개 (2026-11-19, question-templates 0절 반영)

> **최종 문장·빈칸 이름·값은 `docs/plan/2026-11-19-first-visit-question-templates.md` 를 따른다.** 아래 표는 그 문서 0절을 화면 배치용으로 옮긴 것이다. 두 문서가 다르면 question-templates 문서가 맞다. 값 목록 전체와 근거 문서는 그 문서 4-1~4-3에 있고, dev-front 는 거기서 글자 그대로 가져간다.

| 순서(질문 틀 버튼 순) | 틀 id | 질문 틀 버튼 이름 | 문장 (빈칸 = `[ ]`) | 빈칸 | 진행 확인 칩 | 상품 되묻기 칩 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `plan` | 프로모션 기획 | `[상품] 프로모션을 [혜택] 방식으로 기획하려고 해` | 상품 · 혜택(`dependsOn: product`) | 뜬다 — 의도한 것('네' → 상품 칩 없이 어드민) | 안 뜬다 |
| 2 | `placement` | 노출 구좌 | `[상품] [혜택] 프로모션 노출 구좌 잡아 줘` | 상품 · 혜택(`dependsOn: product`) | 안 뜬다 | 안 뜬다 |
| 3 | `policy` | 정책 확인 | `[상품] 프로모션에서 [정책 항목] 기준 알려줘` | 상품 · 정책 항목(`dependsOn: product`) | 안 뜬다 | 안 뜬다 |

- 패널을 독 입구로 처음 열면 1번 `plan` 이 골라진 상태다. 대시보드 "프로모션 기획" 카드도 `plan` 을 연다(§2.6).
- 상품 칸 값은 틀마다 다르다: `plan`·`placement` 는 `B tv+` / `지상파·종편·CP 월정액` / `영화 PPV` / `영화 외 PPV` 4개, `policy` 는 `월정액(PPM)` / `단건(PPV)` 2개. 틀을 바꾸면 빈칸을 모두 비우는 규칙(§2.3)이 그대로 맞는다.
- `placement` 문장은 빈칸 두 개가 공백 하나를 사이에 두고 붙어 있다(`[상품] [혜택]`). 문장 줄에서 두 빈칸 버튼 사이 간격은 다른 글자 사이와 같게 공백 한 칸만 두고, 따로 여백을 더하지 않는다.
- 세 틀 모두 빈칸이 2개라 §2.2 그림의 문장 줄은 독 최소 폭에서도 2줄 안에 들어간다.

**시스템 사용법 틀(`system`)이 빠진 이유** (question-templates 4-4)

- `…하는 방법 알려줘` 처럼 매뉴얼을 묻는 문장에 `쿠폰`·`캠페인` 이 함께 들어가면 규칙 기반 엔진이 판단 요청(`wantsAdvice`)으로 잘못 읽어, 매뉴얼 답 끝에 관계없는 마케팅 인사이트 안내 줄이 붙는다(실측: `CBS에서 쿠폰 정책 등록 하는 방법 알려줘`). 피하려면 어색한 말투나 절차 질문 규칙과 엇갈릴 수 있는 말을 써야 한다.
- 매뉴얼 질문은 대화 규약상 숙련도를 한 번 되묻는 경우가 있어(규약 96행) "빈칸만 채우면 바로 답" 이라는 템플릿 약속을 지키기 어렵다.
- 이번 차수에서는 규칙 수정이 범위 밖이다. 같은 문서 8절 결함 2가 고쳐지면 다음 차수에 다시 본다.
- **화면 영향**: 대시보드 카드 4 "시스템 사용법"은 원래부터 템플릿이 아니라 `/wiki?category=promotion&sub=system`(시스템 매뉴얼 문서 목록)으로 가므로 바뀌는 것이 없다(§1.3). 독의 질문 틀 버튼은 3개다.

틀을 만들 때 화면 쪽에서 요구한 조건과 확정본의 대조:

| 조건 | 확정본 |
| --- | --- |
| 1. 빈칸 바로 뒤에 받침에 따라 바뀌는 조사를 두지 않는다 | 지킴 — 빈칸 뒤가 `프로모션`·`방식으로`·`기준` 같은 고정 낱말 |
| 2. 빈칸은 템플릿당 2~3개 | 지킴 — 세 틀 모두 2개 |
| 3. 값 글자 12자 이내 권장 | 13자 2개 — 아래 §2.8에서 판단: **그대로 허용** |
| 4. 값 글자 = 보내는 글자 | 지킴 |

- 상수 모양 제안(이름·구조는 dev-front 재량, 한곳에 둘 것): 템플릿마다 `id`, `label`, 문장 조각 배열(글자 또는 빈칸 id), 빈칸 정의(`label`, 값 배열 또는 앞 빈칸 값별 값 배열, `dependsOn?`). 위치는 `src/lib/assistant.ts` 의 `QUESTION_TEMPLATES`(기획 문서 B6). 예시는 question-templates 4-5.
- 화면은 템플릿 수가 1~4개 어느 것이어도 같은 배치로 동작해야 한다(질문 틀 버튼이 1개여도 그 줄을 숨기지 않음 — 무엇을 채우는 중인지 이름이 보여야 하므로). 다음 차수에 `system` 이 돌아와도 배치는 그대로다.

### 2.8 13자 값 두 개 — 독 최소 폭에서 괜찮은가

대상: `지상파·종편·CP 월정액`(상품 칸, `plan`·`placement`), `30일 이하 월 전환동의`(정책 항목 칸, `policy`·`월정액(PPM)`). 둘 다 공백 포함 13자.

**판단: 괜찮다. 글자를 줄이지 않고 그대로 쓴다.** 근거(계산값):

| 항목 | 값 |
| --- | --- |
| 값 버튼 모양 | `.suggest button` — 글자 12px(Pretendard, `--mono` = `--sans`), 안쪽 여백 좌우 7px, 테두리 1px |
| 13자 값 버튼 너비 | 한글 8자 × 약 12px + 영문·숫자·`·`·공백 5자 × 약 3~7px ≈ 글자 약 120px → 버튼 **약 135~140px** |
| 패널 안 쓸 수 있는 폭 | 독 최소 폭 320px − 패널 좌우 여백 24px = **296px** |
| 한 줄에 들어가는 수 | 13자 버튼(약 140px) + 간격 5px + 옆 버튼 약 150px 까지 → **13자 값 옆에 다른 값 하나가 같은 줄에 들어간다** |
| 같은 목록의 옆 값 | 상품 칸: `B tv+`(약 45px)·`영화 PPV`·`영화 외 PPV`(약 75px) / 정책 항목 칸: `전환동의`·`약정 쿠폰`·`해지방어 쿠폰`(약 60~90px) — 모두 옆에 들어감 |

- 12자 권장은 "한 줄에 버튼 2개 이상"을 지키려는 기준이었다. 13자에서도 2개가 들어가므로 기준의 목적은 지켜진다. 1자 초과로 생기는 차이는 버튼 너비 약 12px 뿐이다.
- `지상파·종편·CP 월정액` 은 기존 세부 상품 칩(`IntentChip` 의 `지상파·종편·CP 월정액`)과 글자가 같아야 하고, `30일 이하 월 전환동의` 는 줄이면 규칙 기반 근거가 흐려진다(question-templates 4-3 실측). 화면 쪽 이유로 줄일 만큼의 문제가 아니다.
- **dev-front 가 지킬 것**: 값 버튼과 문장 줄의 빈칸 버튼에 `white-space: nowrap` 을 준다. 줄바꿈은 **버튼과 버튼 사이에서만** 일어나고 버튼 안 글자는 한 줄로 유지한다(`.suggest` 가 이미 `flex-wrap: wrap` 이라 버튼 단위로 다음 줄로 내려간다). 채운 빈칸 버튼(`지상파·종편·CP 월정액` 이 들어간 상태)도 같은 규칙이라 문장 줄이 버튼 앞뒤에서만 꺾인다.
- 296px 를 넘는 값은 없으므로 넘침 처리(말줄임)는 넣지 않는다. 앞으로 값이 20자를 넘게 늘면 그때 다시 본다.
- 위 너비는 글꼴 크기로 계산한 값이다. dev-front 반영 뒤 독을 320px 로 줄여 실제 화면을 찍어 확인한다(§7 검수 항목).

| 멈춤 | 입력창에 포커스가 있거나 `input` 에 글자가 1자 이상 있으면 타이머를 멈춘다(C2). 멈춘 동안 placeholder 는 마지막에 보이던 예시 그대로 |
| 다시 돌기 | 포커스가 빠지고 입력창이 비어 있으면 **다음 예시부터** 다시 4초 간격(같은 문장을 다시 보여 주지 않음) |
| 동작 줄이기 | `matchMedia('(prefers-reduced-motion: reduce)')` 가 참이면 타이머를 만들지 않고 첫 번째 예시만 고정(C3). 설정이 바뀌면(`change` 이벤트) 즉시 따른다 |
| 바꾸는 방식 | 글자만 바꾼다. 페이드·슬라이드 같은 움직임 없음(placeholder 는 애니메이션 대상이 아니고, 움직임을 줄이는 것이 목적과 맞음) |
| 정리 | 독이 닫히거나(언마운트) 화면을 옮겨도 타이머·`matchMedia` 리스너 해제(C6) |
| 접근성 | `aria-label="어시스턴트에게 질문"` 그대로(C4). placeholder 에 `aria-live` 를 걸지 않는다(4초마다 읽히면 방해) |
| 길이 | 예시 문장은 공백 포함 20자 이내 권장. 독 최소 폭 320px 에서 입력창이 약 250px 라 `예: ` 포함 약 20자까지 보이고, 넘으면 끝이 잘린다 |
| 겹침 금지 | `SUGGESTED_QUESTIONS`(빈 대화 예시 7개)·② 완성 문장과 같은 문장을 쓰지 않는다(기획 문서 ③) |

확정 예시 5개(`docs/plan/2026-11-19-first-visit-question-templates.md` 0절·5절, 순환 순서도 이 순서):

| # | placeholder 에 보이는 글자 | 예시 글자 수(공백 포함) |
| --- | --- | --- |
| 1 | `예: PPV 쿠폰 신작에만 걸 수 있어?` | 19 |
| 2 | `예: 전환동의 팝업 몇 버전부터 떠?` | 17 |
| 3 | `예: 쿠폰명 끝에 쿠폰 붙여도 돼?` | 16 |
| 4 | `예: 판촉 쿠폰 품의 결재선은?` | 14 |
| 5 | `예: Swing 공지는 언제 올려?` | 16 |

- 5개 모두 권장 20자 이내. 가장 긴 1번(19자 + `예: `)은 독 최소 폭(320px)에서 끝 1~2자가 잘릴 수 있으나 기본 폭(창의 33%, 1280 기준 약 422px)에서는 다 보인다. 잘려도 질문 뜻은 앞부분에서 읽히므로 그대로 둔다.
- 초안에 있던 `PPV 쿠폰 적용 범위는?` 은 ② `policy` 완성 문장과 겹쳐 빠졌다.

## 4. 클릭 수 — 전 → 후 (대표 과업 기준, 대시보드에서 시작)

| 과업 | 전 | 후 |
| --- | --- | --- |
| PPV 프로모션 기획 조건 묻기 | 챗봇 → (조건을 넣은 문장을 직접 작성) → 보내기 = 2클릭 + 작성. 조건을 빠뜨리면 되묻기 칩 1~2클릭 추가. 버튼만으로는 챗봇 → 기획 시작하기 → 네/아니요 → PPV = 4클릭 후에도 조건은 직접 입력 | 프로모션 기획 카드 → 상품 → 혜택 → 보내기 = **4클릭, 작성 0**, 상품 되묻기 0(B4). 진행 확인 칩은 뜨는 것이 의도(question-templates 4-1) — '네' 1클릭이면 상품 칩 없이 어드민이 열린다 |
| Today B tv 편성 확인 | 사이드바 편성/스케줄 → 홈 펼치기 → Today B tv = 3클릭 (또는 챗봇 → 홈 편성 스케줄 = 2클릭) | 편성 확인 카드 = **1클릭** |
| 혜택 정책 확인 | 위키 문서 › 프로모션 → 정책 → 문서 = 3클릭(목차 이동 포함 4) | 정책 확인 카드 → 문서 = **2클릭**(목차 포함 3) |
| 시스템 매뉴얼에서 사용법 찾기 | 프로모션 → 시스템 매뉴얼 → 문서 → 목차 = 4클릭. "시스템 바로가기"로 잘못 들어가면 매뉴얼로 가는 길 없음 | 시스템 사용법 카드 → 문서 → 목차 = **3클릭** |
| 진행 중 대화에서 질문 도움 받기 | 0개(예시 사라짐) | 독 `빈칸 채워 질문하기` 항상 있음 + placeholder 예시 4~6개 |

## 7. 검수 때 볼 것 (wiki-ux, dev-front 반영 PR 대조)

- 1280×800 독 닫힘/열림 두 상태에서 카드 + KPI 가 스크롤 없이 보이는지(스크린샷).
- 카드 4장 각각 1클릭 도착지가 §1.3 표와 같은지. 관리자·실무자 둘 다.
- 빈칸 2개 템플릿이 대시보드 기준 4클릭·키보드만으로 끝나는지, 보낸 말풍선 글자가 미리보기와 같은지.
- 독 최소 폭(320px)에서 13자 값 2개(`지상파·종편·CP 월정액`, `30일 이하 월 전환동의`)가 버튼 안에서 줄바꿈되지 않는지(§2.8).
- 진행 중 대화에서 입구가 보이는지, `pending` 중 보내기 비활성.
- placeholder: 포커스·입력 시 멈춤, 동작 줄이기 켜면 고정, 독 닫기 후 콘솔 오류 없음.
- 문구가 §5 표와 글자 단위로 같은지.
