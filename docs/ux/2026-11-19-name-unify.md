클릭 수는 바뀌지 않는다. 바뀌는 것은 "누른 메뉴 이름 = 열린 화면 제목 = 안내 문서에 적힌 이름"이 되어, 이동 후 "여기가 맞나" 확인하는 읽기 1번이 없어지는 것이다. 예: 이용 안내 HUB-06 "사이드바 **시스템 바로가기**" → 클릭 → 지금은 제목 `시스템`, 바꾼 뒤 `시스템 바로가기`.

## 1. 이름을 고른 이유

### 1.1 대시보드 (← 메인)

- 화면 안 문구는 이미 `대시보드` 가 다수다: `LocalHubOnboarding.tsx` 16·105·120·122행, `AuthGate.tsx` 117행, 이용 안내 `engines.md` 30행, 1차 설계 문서 전체. `메인` 은 사이드바와 3곳뿐이다.
- `홈` 은 쓰지 않는다. 편성/스케줄 › B tv › **홈** (B tv 앱의 홈 지면)과 겹친다.
- `캠페인 대시보드` (외부 Target 프로모션 화면, `CampaignApp.tsx`)는 앞에 `캠페인` 이 붙어 있어 구분된다. 그대로 둔다.

### 1.2 시스템 바로가기 (← 시스템 · 자주 사용하는 시스템)

- 사이드바 이름 `시스템 바로가기` 는 위키 `시스템 매뉴얼` 과 헷갈리지 않으려고 일부러 붙인 이름이다(`AppShell.tsx` 398행 주석). 화면 제목 `시스템` 이 이 구분을 지운다 → 제목을 사이드바에 맞춘다.
- 대시보드 패널은 별표한 것만 보여 주는 **같은 목록의 일부**다. 패널 제목도 `시스템 바로가기` 로 두고, 오른쪽 `전체 보기 →` (이미 있음)가 "일부"라는 것을 알려 준다. `최근 업데이트 문서` 패널과 같은 결(패널 제목 + 전체 보기).
- 별표 동작 문구는 "어디에 올라가는지"로 말한다: `대시보드에 올리기` / `대시보드에서 빼기`. 별표 묶음에 따로 이름(`자주 사용하는 시스템`)을 붙이지 않는다.
- 1차 카드 4 `시스템 사용법` (→ 위키 시스템 매뉴얼)은 다른 대상이라 그대로다. 이번 변경으로 `시스템 바로가기`(주소)와 `시스템 사용법`·`시스템 매뉴얼`(조작법)만 남아 둘이 더 잘 갈린다.

### 1.3 캠페인 신청 캘린더 (← 캠페인 (ACS))

- 화면 제목·독 버튼·원본(캠페인 대시보드의 "캠페인 신청 캘린더")이 이미 이 이름이다. 사이드바만 다르다.
- Target 프로모션(ACS 발송) 대상이므로 '캠페인' 사용 규칙에 맞다. 새로 '캠페인' 을 쓰는 곳은 없다.
- 사이드바 폭 확인: 1280px 에서 `캠페인 (ACS)` 칸 오른쪽에 약 100px 여유가 있어 9글자 `캠페인 신청 캘린더` 가 말줄임 없이 들어간다(`assets/2026-11-19-name-sheets-campaign.png`).
- 형제 메뉴 `App·push (ACS)` (모바일, 개발중)는 이번 범위가 아니다. 화면이 생길 때 같은 방식(화면 제목 = 메뉴 이름)으로 정한다.

### 1.4 Today B tv 편성표 (← 홈 편성 스케줄 (B tv))

- `Today B tv` 는 B tv 홈 레일의 실제 이름이고, 원본 시트·위키(MKI-B-02)·대시보드 카드 2(`홈 Today B tv 편성을 날짜별로 확인합니다`)·어시스턴트 대화 규약이 모두 이 말을 쓴다.
- 편성/스케줄 메뉴 안(사이드바, 화면 위치 줄)에서는 위 경로가 이미 "편성"을 말해 주므로 `Today B tv` 만 쓴다(형제 `빅배너`·`오핫콘` 과 같은 규칙). 메뉴 밖(독 버튼, 화면 태그)에서는 `Today B tv 편성표`.
- 독 버튼 글자가 16자 → 13자로 짧아진다(독 최소 폭 320px 에서 유리).

### 1.5 챗봇 (← 어시스턴트 · 무엇이든 물어보세요)

- 실무자가 누르는 버튼(`챗봇`), 이용 안내(`tour.md` "오른쪽 아래 **챗봇** 버튼", "챗봇에게 묻기"), 엔진 설정 이름(`챗봇 답변 엔진` — 대시보드 패널·설정 창·HUB-04 문서 제목), 요청 진입 값(`챗봇 대화`·`챗봇 리포트`)이 모두 `챗봇` 이다. `어시스턴트` 는 검색 결과 3곳·프로모션 자동화 연결 확인 2곳·대시보드 카드 힌트 1곳·스크린리더 이름 2곳뿐이다.
- 반대로 `어시스턴트` 로 맞추면 `챗봇 답변 엔진` 이름과 이용 안내 문서 제목까지 바꿔야 한다(라벨 범위를 넘음). 초보자에게도 `챗봇` 이 더 쉬운 말이다.
- 독 머리 `무엇이든 물어보세요` 는 이름 자리에 쓰인 안내문이라, 버튼을 누른 사람이 같은 것이 열렸는지 한 번 더 읽게 한다. 머리는 `챗봇`, 무엇을 물을 수 있는지는 바로 아래 범위 줄(`dock-scope`, 이미 `챗봇이 문서 근거로 정리해 드립니다`)이 맡는다.
- 1차 문서와의 관계: D-5b `어시스턴트에서 빈칸 채우기 →`, A-18 `어시스턴트에게 질문`, A-19 `무엇이든 물어보세요` 를 이 문서가 대체한다(1차 문서 §5 머리에 메모를 달았다). 카드·빈칸 패널·placeholder 의 위치·동작·나머지 글자는 그대로다. `빈칸 채워 질문하기` 등 A-1~A-17 은 손대지 않는다.
- 코드 이름(`AssistantDock`, `assistant.ts`, `ask-assistant` 클래스)과 서버 프롬프트 안의 역할 이름은 화면에 안 보이므로 바꾸지 않는다.
