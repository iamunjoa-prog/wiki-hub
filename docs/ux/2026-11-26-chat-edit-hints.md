### 2-1. 문서 보기 — 문구 B

```
┌ 문서 정보 ─────────── ■ 이용 안내 ┐
│ 코드 HUB-03 …                     │
└──────────────────────────────────┘
[ 💬 이 문서로 묻기                ]
틀린 곳은 위 버튼으로 말해 주세요.         ← 문구 B (12px, --text-2)
형식에 맞춘 수정안을 만들어 드려요.
이 페이지 목차
…
```

- **문구 B (권장, 폭 맞춤):** `틀린 곳은 위 버튼으로 말해 주세요. 형식에 맞춘 수정안을 만들어 드려요.`
- 기획안 원안 `틀린 곳이 있나요? 위 버튼을 눌러 말로 고쳐 달라고 하세요. 수정안을 만들어 드려요.` 은 오른쪽 칸 폭(`--w-toc` 240px)에서 12px로 3줄이 된다. 권장안은 문장마다 한 줄씩 2줄로 끊기고, D2 승인 표현 "형식에 맞춘 수정안을 만들어 드려요"를 글자 그대로 쓴다. 뜻은 같다(누를 곳 → 말하기 → 수정안). 원안을 고집하면 3줄을 받아들이면 된다 — 확인 필요 Q1.
- "위 버튼"이라고 쓸 수 있는 것은 B가 버튼 **바로 아래** 붙어 있기 때문이다. 자리를 옮기면 문구도 바꿔야 한다.
- 동선: 지금 "고치고 싶다 → 방법 찾기"가 HUB-03 까지 2클릭 + 읽기 → 바뀐 뒤 같은 화면에서 0클릭으로 읽고, [이 문서로 묻기](1) → 말하기 → 수정안 카드 → [제안 제출](2) → 편집 화면에서 확인 → [제출하기](3).
- 좁은 폭(오른쪽 칸 접힘)에서는 머리 줄 `doc-ask-inline` 버튼만 있고 B는 없다. 머리 줄은 버튼 3개가 한 줄이라 아래에 한 줄을 끼우면 제목과 본문 사이가 벌어진다. 좁은 폭 사용자는 HUB-03·챗봇 답(규약 A1)으로 안내받는다 — 확인 필요 Q2.

### 2-2. 새 문서 — 문구 C

```
본문 * (마크다운)                                    ← 이름(아래 Q3)
마크다운을 몰라도 돼요. 그냥 쓰거나, [챗봇에 '새 문서로 …'라고 말하면] 형식을 맞춘 초안을 만들어 드려요.   ← 문구 C, 12px .muted
[편집] [미리보기]
┌ textarea ┐
```

- **문구 C (기획안 그대로):** `마크다운을 몰라도 돼요. 그냥 쓰거나, 챗봇에 '새 문서로 …'라고 말하면 형식을 맞춘 초안을 만들어 드려요.`
- 폭 808px 폼에서 12px로 한 줄에 들어간다(약 60자).
- **"챗봇에 '새 문서로 …'라고 말하면" 부분을 글자 버튼으로** 만든다(밑줄 링크 모양, `<button type="button">`). 누르면 `openDockWith('새 문서로: {카테고리} › {하위 메뉴}에 ')` 로 어시스턴트 창을 열고 입력칸을 채운다. 폼에 쓴 내용은 그대로 남는다. 동선: 새 문서 화면에서 챗봇 길로 옮기기 **창 열기 1클릭 + 앞말 0타**(전: 상단바 [묻기](1) → 앞말을 스스로 떠올려 타이핑). 카테고리·하위 메뉴를 아직 안 골랐으면 `새 문서로: ` 까지만 채운다.
- 이 글자 버튼은 빨강이 아니다(`--text` 밑줄 글자). 빨간 버튼 수 변화 0.
- 이름 칸 "본문 * (마크다운)"은 C와 뜻이 엇갈린다("마크다운으로 써라" vs "몰라도 된다"). "본문 *"으로 줄이고 placeholder 도 "마크다운으로"를 빼는 것을 requests-planner 에 권한다 — 확인 필요 Q3. 이름을 그대로 둬도 C는 같은 자리에 넣는다(기획안 F2 "이름 옆").

### 2-3. 편집 중 `AI에게 부탁` — placeholder

- 자리: `SectionEditor.tsx` 102행 `placeholder`. 새 줄을 만들지 않는다. 그 칸 위에 이미 머리 줄("AI에게 부탁 · 「…」 장만 고쳐요"), 아래에 "보통 20초~1분" 줄이 있어 한 줄을 더하면 세 줄 안내가 된다.
- 기본값(기획안 P2): `예) 결재 기준 줄을 팀장 전결로 바꿔줘 — 형식은 맞춰 드려요`. 문구 확정은 requests-planner.
- 이 칸은 편집 모드에서만 보이고, 편집 모드에서는 문구 B가 숨는다 → 한 화면 한 줄 유지.
- 챗봇 수정안 카드에서 넘어온 편집(dev-front 작업 중 `ChatEditRequest`)은 그 요청 칸이 따로 있다. 그 칸에는 사용자가 말한 지시가 채워져 오므로 placeholder 가 보일 일이 거의 없다. 따로 문구를 넣지 않는다.

### 2-4. 위키 목록 — "처음이라면" 줄 끝

```
위키 문서 42건                                         [+ 새 문서]
처음이라면: 지식 허브 둘러보기 · 고칠 곳이 있으면: 말로 고치는 법
            └ HUB-01 링크(기존)                       └ HUB-03 링크(새)
```

- 기획안 원안은 `· 고치고 싶으면 챗봇에게 말하세요` 였다. 목록 화면에서는 챗봇에게 무엇을 어떻게 말할지 알 수 없어(어느 문서인지 정해지지 않은 자리), **방법이 적힌 곳으로 보내는 링크**로 바꾼다. 링크 글자 "말로 고치는 법"은 HUB-03 두 번째 장 제목("형식은 몰라도 됩니다 — 말로 고치는 법")과 같은 말이라 눌렀을 때 같은 말을 첫 화면에서 다시 본다(스크린샷 `now-wiki-doc-ask.png` 에서 두 번째 장이 첫 화면에 보임).
- 링크 대상: `docs.find((d) => d.code === 'HUB-03')` → `/wiki/{id}`. 장 앵커를 붙이지 않는다 — 두 번째 장이 이미 첫 화면에 있고, 앵커 이름이 바뀌면 링크가 깨진다.
- 동선: 목록 → 말로 고치는 법 **1클릭**(전: 이용 안내 칩/사이드바(1) → 문서 작성 규칙(2)).
- 이 줄은 "카드 필요=아니오"다. HUB-03 의 챗봇 줄이 C3 를 지키면 이 링크는 카드 전에 나가도 사실과 어긋나지 않는다.

## 5. 반영 순서 (C3)

1. 위키 목록 반 줄(2-4)과 `AI에게 부탁` placeholder(2-3)는 카드와 상관없이 먼저 나가도 된다.
2. 문구 B(2-1)와 문구 C의 챗봇 부분·글자 버튼(2-2)은 **수정안 카드 PR 과 같은 배포 또는 그 뒤**에 나간다. 카드가 없는 배포에서 B를 보이면 "수정안을 만들어 드려요"가 거짓이 된다. 같은 PR 에 넣는 것을 권한다(dev-front 가 지금 `WikiDoc.tsx`·`NewDoc.tsx` 를 함께 고치는 중이라 파일도 겹친다).
