## 1. 개편 방향

한 줄: **문서를 읽던 그 자리에서, 글자를 그대로 고치고, 오른쪽 칸에서 확인하고 제출한다.**

| 원칙 | 내용 |
| --- | --- |
| 페이지 이동 없음 | 편집은 문서 보기 화면의 **편집 모드**다. 주소는 `/wiki/:id?edit=<장 앵커>` (새로고침해도 편집 모드로 돌아온다). 기존 `/wiki/:id/propose` 는 `?edit=all` 로 보낸다 |
| 장(H2) 단위 | 고치는 단위는 `##` 소제목부터 다음 `##` 앞까지(안의 `###` 포함). 첫 `##` 앞 머리말은 "머리말" 장으로 친다. 한 번에 여러 장을 고쳐 한 번에 제출할 수 있다 |
| 마크다운 숨김 | 보이는 모양 그대로 고친다. 표·목록·주의 상자·링크는 버튼으로 만든다. 원문(마크다운)은 **고급 옵션**으로만 연다 |
| 손대지 않은 곳은 그대로 | 고친 블록만 다시 마크다운으로 쓰고, 손대지 않은 블록은 원문 글자를 그대로 둔다 (아래 R1). 열었다 닫기만 하면 변경 0줄 |
| 검사는 고치는 동안 | 공개 규칙·가린 표기·링크 끊김·편집 경고를 편집 중에 돌려, 문제 위치에 바로 표시한다. 줄 번호 대신 "「접속 정보」 장 표 3행" |
| 오른쪽 칸 전환 | 편집 중에는 오른쪽 칸(문서 정보 카드 + 목차)이 **편집 패널**(변경 요약 · 확인할 것 · 사유 · 제출)로 바뀐다 |
| 제출 버튼 하나 | 패널의 [제출하기] → 제출 확인 창 → [제출]. 확인 창은 화면 위에 뜨고 페이지는 바뀌지 않는다 |
| AI는 장 단위 | 장 도구줄의 [AI에게 부탁] — "이 장을 이렇게 고쳐줘". 결과는 그 장 안에 제안으로 보이고 [받기]/[버리기] |

## 3. 공개 규칙 경고·깨진 링크를 어디에 보여 줄까

검사 종류와 편집 중 표시 위치를 하나의 규칙으로 맞춘다. 검사는 지금 함수를 그대로 쓰고, **돌리는 때**와 **위치 말하는 법**만 바꾼다.

| 검사 | 출처 | 등급 | 언제 | 본문 표시 | 패널 `확인할 것` 문구 예 |
| --- | --- | --- | --- | --- | --- |
| 금액·수치·회사명·주소·연락처 | `/api/publicCheck` (`target: 'edit'`) | 경고 (제출 가능, 13절 R-A 유지) | 바뀐 블록이 생기면 600ms 뒤 (지금 디바운스 값) | 걸린 글자에 앰버 물결 밑줄. 마우스 올리면 `hitMessage` 문구 | `⚠ 접속 정보 › 표 5행 「OO원」 금액으로 보여요. "할인 폭이 큰 편"처럼 경향으로 쓰는 게 좋아요` |
| 비공개 이름 목록 일치 | 같은 API (`kind: 'name'`) | 경고 (수정 제안 규칙) | 같음 | 같은 밑줄. 칩으로 [제휴사로 바꾸기] | `⚠ … 공개하면 안 되는 이름이에요 [제휴사로 바꾸기]` |
| 가린 표기 채움 / 별표 2개 | `maskLeaks` | **차단** | 편집 중 계속 (로컬 계산) | 보기 모양 편집에서는 잠긴 칩이라 생기지 않는다. 원문 보기에서만 생길 수 있음 → 해당 블록 빨간 테두리 | `⛔ 가려 둔 이름 「구*화」가 채워졌어요 [되돌리기]` — 제출 버튼 아래 같은 문구 |
| 소제목 이름 변경·삭제 → 다른 문서 링크 끊김 | `brokenAnchors` | 경고 | 소제목 입력줄에서 글자를 바꾸는 즉시 | 소제목 입력줄 바로 아래 한 줄: `이 이름을 바꾸면 다른 문서 1곳의 링크가 이 장을 못 찾아요 [어디인지] [원래 이름으로]` | `⚠ 소제목 「접속 정보」 → 「접속 방법」: 링크 1곳 끊김` · [어디인지]를 누르면 문서 제목 목록(`지식/…` 경로 대신 문서 코드·제목) |
| 소제목 사라짐·본문 30% 감소·표 행 감소·코드 블록 수 변화·(보완 필요) 지움 | `editWarnings` | 경고 | 편집 중 계속 | 해당 장 `바뀐 곳` 항목에 ⚠ | 지금 문구를 해요체로 (예: `표 행이 12줄에서 8줄로 줄었어요`) |
| 같은 문서에 열린 제안 | `proposals` (`openProposals`) | 안내 | 편집 진입 시 1번 | 없음 | `ⓘ 이 문서에 검토 중인 다른 제안 1건 — 같은 곳을 고치면 나중 것이 충돌할 수 있어요` |

규칙:

- **이미 있던 내용은 짚지 않는다.** 이번에 새로 생기거나 바뀐 블록만 (지금 `usePublicWarnings` 의 `fresh` 필터 유지). 고칠 수 없는 경고를 쌓지 않는다.
- **위치는 장 › 블록으로.** "37번째 줄" 대신 `접속 정보 › 표 5행`, `예외처리 › 3번째 문단`. 원문 보기에서는 줄 번호를 같이.
- 패널 항목을 누르면 그 위치로 스크롤하고 걸린 글자를 2초 강조(앞선 개편안의 "장 제목 2초 강조"와 같은 동작).
- 색: 경고 = `--warn-text` 글자 + ⚠, 차단 = `--danger` + ⛔. 차단 상자는 차단이 있을 때만 생기고, 그때는 편집 바·편집 패널의 램프를 앰버 `● 제출 전 확인`으로 바꿔 ON AIR 빨강과 위험 색(`--danger`)이 한 화면에 같이 서지 않게 한다. 위험 색은 빨강 개수에 세지 않지만 온에어 빨강과 섞어 쓰지 않는다(`2026-11-26-home-engine-assistant-cards.md` A-7-1, R6). 되돌릴 수 없는 확인 단계 [지우기]는 `btn sm danger`(테두리형 `--danger`).
- 검사 실패(서버 못 닿음)는 패널 아래 회색 한 줄: `공개 규칙 검사를 못 했어요. 제출은 할 수 있어요` (지금처럼 제출을 막지 않음).

## 4. 저장 전 이탈 · 동시 수정 · 임시 저장

### 4-1. 임시 저장

| 항목 | 지금 | 개편 |
| --- | --- | --- |
| 언제 | 글이 바뀌고 2초 뒤 | 같음 + 장을 옮길 때 · 편집 끝내기 · 화면을 떠날 때 즉시 |
| 무엇을 | 본문 전체 문자열 | `{ baseVersion, body, reason, changedSections, savedAt }` — **기준 버전과 사유를 같이** |
| 보이는 곳 | 1단계 머리 작은 글씨 | 편집 바 `임시 저장 10:42` + 문서 보기 화면 머리 위 띠(①) |
| 되살리기 | 소리 없이 되살림 | 띠의 [이어서 고치기]를 눌러야 편집 모드로. [버리기]는 한 번 더 묻는다: "고친 내용 2개 장을 지울까요? 되돌릴 수 없어요" |
| 보관 | 무기한 | 30일 지나면 띠 문구에 "오래된 수정이에요" 덧붙임(지우지는 않음) |
| 위치 | 이 PC 브라우저(localStorage) | 같음. 띠에 "이 PC에만 저장돼요"를 작게 적는다 |

### 4-2. 저장 전 이탈

- 허브 안 이동(사이드바·검색·링크): **막지 않는다.** 떠나는 순간 임시 저장하고 아래에 3초 알림: `고친 내용을 임시 저장했어요. 문서를 다시 열면 이어서 고칠 수 있어요.` — 지금 라우터가 `BrowserRouter`(`main.tsx:12`)라 `useBlocker` 를 쓰려면 라우터를 바꿔야 한다. 자동 저장으로 잃을 것이 없으니 막는 창을 두지 않는 쪽을 택한다.
- 브라우저 탭 닫기·새로고침: 저장 안 된 2초 사이가 있을 때만 브라우저 기본 확인창(`beforeunload`). 문구는 브라우저가 정하므로 손대지 않는다.
- [편집 끝내기]: 바뀐 곳이 있으면 패널 위에 한 줄 확인 `고친 내용은 임시 저장돼 있어요. 보기로 돌아갈까요? [돌아가기] [계속 고치기]`.

### 4-3. 동시 수정 (서버 409 "문서를 다시 열어 수정해 주세요")

409는 대부분 "다른 제안이 먼저 승인됐는데 아직 배포 전"이다. 화면의 문서가 옛 본문이라 다시 열어도 같은 409가 난다(P11). 서버는 이미 `mainVersion`·`mainBody` 를 실어 보낸다 — 화면이 이걸 쓴다.

```
[제출] ─▶ 409 (mainVersion, mainBody)
          │
          ├─ 내가 고친 장이 최신본에서 그대로다 (다른 분은 다른 장을 고침)
          │    → 확인 창 안에서:
          │      "그 사이 다른 분이 이 문서를 고쳤어요 (v3 → v4).
          │       내가 고친 장과 겹치지 않아서 최신본에 옮겨 담았어요."
          │      [바뀐 곳 다시 보기]  [다시 제출]      ← 검사 다시 돌림. 1클릭
          │
          └─ 내가 고친 장을 다른 분도 고쳤다
               → 확인 창이 그 장만 나란히 보여 준다:
                 ┌ 다른 분이 고친 최신본 ─────┐ ┌ 내 수정 ───────────────┐
                 │ (보이는 글, 바뀐 곳 칠)     │ │ (보이는 글, 바뀐 곳 칠) │
                 └────────────────────────────┘ └─────────────────────────┘
                 [최신본으로 두기]  [내 것으로 덮기]  [최신본에서 다시 고치기]
                 마지막 버튼 = 최신본으로 편집 모드를 다시 열고, 내 수정은
                 패널 '참고: 내가 쓴 글'에 복사 버튼과 함께 남긴다
```

- 장이 같은지는 "그 장의 원문 글자가 기준 버전과 최신본에서 같은가"로 본다(장 단위라 판단이 쉽다).
- 409 뒤에는 화면이 기준 문서를 `mainBody`/`mainVersion` 으로 바꿔 들고 있는다(배포 전까지). 문서 보기 화면 머리에 `ⓘ 승인된 새 버전(v4)이 아직 화면에 반영 전이에요. 고칠 때는 v4로 고쳐요` 한 줄.
- 2차: 편집 모드에 들어갈 때 최신 버전을 먼저 물어(새 조회 API) 409를 미리 막는다. 그 전까지는 위 흐름으로 처리.
- 그 밖의 실패 문구는 "지금 할 일" 한 줄로: 401 `다시 로그인해 주세요`, 429 `오늘 제출 한도(30건)를 넘었어요. 내일 다시 제출해 주세요`, 413 `문서가 너무 길어요. 원문 보기에서 장을 나눠 제출해 주세요`. 고친 내용은 늘 남는다. (문구 최종은 requests-planner R7)

| 장 단위 AI가 앞뒤 문맥을 몰라 용어가 어긋남 | 다른 장과 다른 이름 | 2-5에서 문서 제목·목차·용어 요약을 함께 보낸다. 1차는 전체 본문을 보내되 그 장 밖 변경은 버린다 |
| 가린 표기 잠금이 정당한 수정(오타 고친 가린 표기)까지 막음 | 불편 | 칩째 지우고 원문 보기에서 새로 쓰는 길을 남긴다(`maskLeaks` 는 새로 생긴 가린 표기는 막지 않음) |
| 409 자동 옮겨 담기가 의미 충돌을 놓침 (다른 장의 숫자와 내 장의 숫자가 엇갈림) | 틀린 문서 승인 | 옮겨 담은 뒤 반드시 확인 창을 다시 보여 주고 "다른 분이 고친 장: 메뉴 구성"을 한 줄 적는다. 자동 제출하지 않는다 |
| 오른쪽 편집 패널 320 + 챗봇 창 동시 사용 | 본문 폭이 좁아짐 | 챗봇 창이 열리면 편집 패널은 본문 아래 붙는 바(바뀐 곳 n · 확인할 것 n · [제출하기])로 접힌다. 기존 좁은 폭 목차(`doc-toc-inline`) 방식과 같은 결 |
| 이름 `✎ 고치기` 가 "바로 반영"으로 오해됨 | 승인 절차를 모름 | 편집 바와 패널 아래에 "승인 뒤 다음 배포에서 반영돼요" 고정 문구, 확인 창 ③. 최종은 R4 |
| 이 PC에만 있는 임시 저장 | 다른 PC에서 이어 못 함 | 띠에 "이 PC에만 저장돼요" 명시. 서버 초안 저장은 범위 밖 |

## 8. 시안 메모 (PM용)

- 3장 권장: ① 문서 보기 + 장 위 마우스(`✎ 이 장 고치기` 보임, 임시 저장 띠) ② 편집 중(표 칸 1개 고침 + 새 문단 1 + 지운 문단 1, 패널에 경고 2) ③ 제출 확인 창. 여유가 되면 ④ 409 겹침 창.
- 문서는 PPC-ACS(공개 문서)를 그대로 쓴다. 경고 예시의 금액은 가짜 값도 쓰지 않고 **"OO원"** 으로 적는다.
- 담당자 이름은 가린 표기(`구*화`, `조*경`) 그대로, 잠긴 칩 모양으로 1곳 이상 보이게.
- `[R…]` 자리는 회색 점선 상자 + "requests-planner 확정 대기".
- 캠페인이라는 말은 ACS(Target 프로모션) 문서 본문에 이미 있는 그대로만. 편집 화면 UI 문구에는 쓰지 않는다.
