### 1.1 지금 흐름 (코드 경로)

**문서 → 질문**

- `src/pages/WikiDoc.tsx` 249–255행 `doc-head` 안 버튼 2개. 챗봇과 이어지는 길이 없다.
- 챗봇을 열려면 오른쪽 아래 `fab`(`AppShell.tsx` 541행 근처, 닫혀 있을 때만) → `AssistantDock` 이 열린다. 독은 지금 어느 화면에 있는지 모른다.
- 같은 결의 입구는 검색 결과 화면에만 있다: `SearchResults.tsx` 99행 `btn accent sm` `챗봇에게 묻기` → `ask(query)`.

**문서 맥락을 질문에 실어 보낼 길이 있는가 — 없다**

- `AppStore.tsx` `ask(query, opts)` 의 `opts` 는 `modeOverride`·`via` 둘뿐이다(202–207행). `via` 는 사용자 말풍선 위에 작게 보이는 이름일 뿐 서버로 가지 않는다.
- `assistant.ts` `requestEngine()` 이 `/api/ask` 에 보내는 몸은 `{ query, engine, history, modeOverride? }` 이다(1195–1199행). 문서 id·경로 칸이 없다.
- 규칙 기반 `answer()` 도 검색 입력은 이번 발화와 앞선 사용자 발화(`context`)뿐이다(993–1003행).
- 따라서 **서버 무변경으로 맥락을 싣는 유일한 길은 질문 문장 자체**다.

**문장에 무엇을 넣을지 — 문서 제목이 아니라 문서 코드**

| 넣는 것 | 근거 문서로 잡히나 | 부작용 |
| --- | --- | --- |
| 문서 코드 (`PPC-P-03`) | 잡힌다. 규칙 기반은 코드 일치에 10배 가중(`retrieval.ts` 322행)이고, 코드로 가리킨 문서는 점수가 처져도 근거에서 빼지 않는다(`assistant.ts` `namedInQuery`, 112행). 엔진도 실제로 PPC-P-03 을 근거로 냈다(`sources-now.png`) | 없음. 코드는 한글 단어가 없어 아래 판별에 걸리지 않는다 |
| 문서 제목 | 대체로 잡힌다 | **답이 틀어진다.** 제목 글자가 대화 판별에 걸린다: `문서 수정 제안과 승인 절차`(HUB-02)·`시스템 바로가기 수정·추가 방법`(HUB-06)은 `문서`/`수정`/`추가` 로 "위키 수정 안내"(`detectKnowledgeEdit`)로 빠진다. `프로모션 … 기획`·`준비` 류 제목은 "기획 진행 확인 칩"(`detectCampaignIntent`)이 끼어들고, `한눈에`(PPC-P-00)는 리포트 신호에 1점이 붙는다 |

→ **보내는 문장에는 문서 코드만 넣는다.** 제목은 사람에게만 보이는 자리(문서 표시 줄, 말풍선 위 `via`)에 둔다. 칩 문장 뒷부분도 같은 판별 단어(`문서`·`수정`·`추가`·`기획`·`진행`·`점검`·`종합`·`리포트` 등)를 쓰지 않게 골랐다.

**답 → 근거 문서**

- `AssistantDock.tsx` `Message` 162–170행: `msg.sources` 가 있으면 `.sources` 안에 `s.label` 그대로 버튼. 순서는 답 본문 → 리포트 카드 → 안내(notice) → `리포트로 자세히 받기` 칩 → **근거** → 정리 카드 → 진행 확인 칩 → `답변 · 엔진`.
- 라벨 글자는 `assistant.ts` 가 만든다: 근거는 `출처 · {제목}`, 위키 수정 안내 답은 `참고 · {제목}`(816행). 리포트는 카드 안에 근거를 따로 두므로 `sources: []`.
- 스타일 `styles.css` 839–841행: 11.5px mono, `--text-2` 글자, `--line` 테두리 — `답변 · Claude` 줄(11.5px mono)과 같은 무게라 부가 정보처럼 읽힌다.
- `SourceRef.anchor`(`types.ts` 151행)는 칸만 있고 지금 쓰는 곳이 없다.

## 2. 설계 — K5 `이 문서로 질문하기`

### 2.1 동선

```
위키 문서 화면
  └ [이 문서로 질문하기]  ── 1클릭
       ├ 챗봇이 열림(닫혀 있었으면) + 입력창 위에 "이 문서로 질문" 패널
       │    PPC-P-03 · PPV(단건) 프로모션 정책                [닫기]
       │    [PPC-P-03 핵심만 짧게 알려줘]
       │    [PPC-P-03 기준으로 실무에서 놓치기 쉬운 점 알려줘]
       │    입력창에 쓰면 앞에 "PPC-P-03 기준으로"를 붙여 보냅니다
       ├ 칩 누름 ── 2클릭, 바로 전송 (작성 0)
       └ 입력창에 직접 씀 → ↩ ── 1클릭 + 작성 + 1클릭
```

| 경우 | 지금 | 바꾼 뒤 |
| --- | --- | --- |
| 이 문서 요약 받기 | 챗봇 열기 → 문서 이름을 써서 질문 → 보내기 = 2클릭 + 작성 | 버튼 → 칩 = **2클릭, 작성 0** |
| 이 문서 기준으로 내 질문 | 2클릭 + 작성(문서 이름까지 써야 함) | 버튼 → 작성 → 보내기 = 2클릭 + 작성(문서 이름 안 씀) |
| 챗봇이 이미 열려 있을 때 | 1클릭 + 작성 | 버튼 → 칩 = 2클릭, 작성 0 |

### 2.2 화면 규칙

1. **버튼 자리**: `WikiDoc.tsx` `doc-head` 버튼 줄의 맨 앞(히스토리 왼쪽). 순서 `이 문서로 질문하기` · `⎇ 히스토리` · `✎ 수정 제안`. 모양은 검색 결과의 `챗봇에게 묻기` 와 같은 `btn sm accent`(새 스타일 없음). `✎ 수정 제안`(`primary`)은 그대로 둔다.
2. **누르면 바로 보내지 않는다.** 독을 열고 패널만 띄운다 — 무엇을 물을지는 실무자가 고른다(엔진 호출이 1~2분 걸리는 로컬 CLI 에서 원치 않는 질문이 나가지 않게).
3. **패널 자리**: 빈칸 채워 질문하기 패널(`TemplatePanel`, `AssistantDock.tsx` 773행)과 같은 자리 — 대화 목록 아래, 입력창 위. 두 패널은 동시에 열리지 않는다: 이 패널을 열면 빈칸 패널은 닫히고, 반대도 같다.
4. **칩 = 보내는 글자.** 칩에 적힌 문장을 그대로 `ask()` 한다(빈칸 패널의 "값 글자가 곧 보내는 글자" 원칙과 같음). 말풍선 위 `via` 에는 제목을 단다: `이 문서로 질문 · {문서 제목}`.
5. **직접 입력**: 패널이 열려 있는 동안 입력창에서 보내면 `{코드} 기준으로 ` + 입력 글자를 보낸다. 붙는다는 사실을 패널 안 한 줄로 미리 알린다(보이는 글자와 보내는 글자가 다르지 않게, 말풍선에도 붙은 문장이 그대로 보인다). 입력 글자가 이미 그 코드로 시작하면 다시 붙이지 않는다.
6. **한 번 보내면 패널을 닫는다.** 이어지는 질문은 대화 이력에 코드가 남아 있어 따로 붙이지 않는다(서버·규칙 기반 모두 앞선 사용자 발화를 맥락으로 쓴다).
7. **다른 화면으로 가면 닫는다.** 패널이 가리키는 문서(`/wiki/{docId}`)가 아닌 경로로 이동하면 패널을 닫는다. 같은 문서에서 다시 누르면 패널이 다시 열리고 칩으로 포커스가 간다.
8. **포커스**: 패널이 열리면 첫 칩으로, `닫기`·전송 뒤에는 입력창으로(빈칸 패널의 `focusNext` 와 같은 방식).
9. 독 폭 최소 320px 에서 칩 2개는 각자 한 줄로 떨어진다(`.suggest` 의 `flex-wrap`). 줄임표 처리하지 않는다.

### 2.3 상태를 어떻게 전하나 — `AppStore.tsx` 에 요청 1개 (승인 필요)

`openQuestionTemplate(id)` 와 **같은 모양**으로 하나를 더 둔다. 서버 무변경, `assistant.ts` 무변경.

| 추가 | 모양 | 하는 일 |
| --- | --- | --- |
| `openDocQuestion(docId)` | `openQuestionTemplate` 복제 | 독을 열고 `docQuestionRequest = { docId, n }` 을 올린다 |
| `docQuestionRequest` | `{ docId: string; n: number } \| null` | 독이 받아 패널을 연다. `n` 은 같은 문서를 다시 눌러도 알아차리게 하는 순번 |
| `clearDocQuestionRequest()` | | 독이 받은 뒤 지운다 — 독을 닫았다 열 때 패널이 또 뜨지 않게 |

- 대안(승인이 안 될 때): `WikiDoc` 은 `openDock()` 만 부르고, 독이 `useLocation()` 으로 `/wiki/:docId` 를 읽어 패널을 띄운다. 스토어는 안 바뀌지만 **문서 화면에서 챗봇을 열 때마다** 패널이 뜬다(버튼을 눌렀는지 구분 못 함). 문서를 읽으며 다른 질문을 하려는 사람에게 2줄짜리 잡음이 생기므로 추천하지 않는다.
- 칩 문장·접두어 상수는 `assistant.ts` 가 아니라 `AssistantDock.tsx`(또는 새 파일 `src/lib/docAsk.ts`)에 둔다 — `assistant.ts` 는 dev-front 가 고치는 중이라 겹치지 않게 한다.

## 3. 설계 — 2차 ⑤ 근거 문서 강조

### 3.1 모양

근거 1건:

```
┌ 답 본문 …
│
│ ─────────────────────────────────────
│ 이 답의 근거  PPV(단건) 프로모션 정책  PPC-P-03   [열기]
│
│ 답변 · Claude
```

근거 2건 이상(라벨은 한 번, 문서는 줄마다):

```
│ 이 답의 근거
│   PPV(단건) 프로모션 정책   PPC-P-03   [열기]
│   CBS 시스템 매뉴얼        PPC-CBS    [열기]
```

| 요소 | 규칙 | 쓰는 토큰·클래스 (새 색 없음) |
| --- | --- | --- |
| 자리 | **답 본문 바로 밑**. 지금 순서에서 근거를 notice·리포트 칩 앞으로 올린다: 본문 → 리포트 카드 → **근거** → 안내 → 리포트 칩 → 정리 카드 → 진행 확인 칩 → 답변 줄 | — |
| 구분선 | 근거 묶음 위에 1px 선 | `border-top: 1px solid var(--border)` |
| 라벨 | `이 답의 근거` (위키 수정 안내 답은 `참고할 문서`) | `.label`, 11.5px mono `--muted` |
| 문서 제목 | 13px 본문 글꼴, 진한 글자 | `--text`, 굵기 600 |
| 문서 코드 | 제목 옆 | `.tag` |
| 열기 | 오른쪽 버튼 `열기` → `/wiki/{docId}` (`anchor` 가 있으면 `#{anchor}` 를 붙이고 글자 `해당 부분 열기`) | `btn sm` |
| 지금 보는 문서일 때 | 근거 문서가 지금 화면의 문서와 같으면 `열기` 대신 muted 글자 `지금 보는 문서` (눌러도 갈 곳이 없다) | `.muted` |
| 줄 전체 | 제목 글자를 눌러도 열린다(버튼만 누르게 하지 않는다) | — |

- 제목·코드는 `s.label` 을 쪼개지 않고 `docs.find(d => d.id === s.docId)` 로 읽는다. 라벨은 앞머리가 `참고 ·` 인지만 본다(라벨 종류 판별). **`assistant.ts` 의 라벨 생성은 바꾸지 않는다.**
- 문서가 사라져 찾지 못하면 그 줄은 빼고, 남는 근거가 없으면 아래 "근거 없음" 처리를 따른다.

### 3.2 근거가 없는 답

`sources` 가 비어 있다고 모두 같은 답이 아니다. 아래 순서로 판별한다(위에 걸리면 아래는 안 본다).

| 답 종류 | 판별 (`ChatMessage` 칸) | 표시 | 이유 |
| --- | --- | --- | --- |
| 되묻기 (상품 유형·진행 확인) | `msg.intent` 있음 | **아무것도 안 붙임** | 칩이 다음 행동이다. 근거 줄을 붙이면 "답이 빈약하다"로 읽힌다 |
| 정리 단계 | `msg.brief` 있음 | 안 붙임 | 정리 카드가 내용이다 |
| 리포트 | `msg.report` 있음 | 안 붙임 | 카드 안에 근거가 따로 있다 |
| 리포트 실패 | `msg.reportFailed` | 안 붙임 | `짧게 답 받기` 칩이 다음 행동이다 |
| 대화로 만든 안내(반영 시작 안내 등) | `msg.query` 없음 | 안 붙임 | 질문에 대한 답이 아니다 |
| 범위 밖 · 근거를 못 찾음 · 엔진이 근거를 비워 보냄 | 위 어디에도 안 걸리고 본문이 있음 | muted 한 줄 `근거 문서 없음` + 버튼 `위키에서 찾아보기 →` (`/search?q={msg.query}`) | 근거 없는 답을 문서 근거 답과 같은 모양으로 두지 않는다. 다음 행동 1개를 준다 |

`위키에서 찾아보기 →` 는 대시보드 패널의 `전체 보기 →` 와 같은 글자 버튼 결이다. 검색 결과 화면에는 이미 `챗봇에게 묻기` 가 있어 되돌아올 길도 있다.

## 4. 수용 기준

**K5**

1. 위키 문서 화면 머리에 `이 문서로 질문하기` 가 `⎇ 히스토리` 왼쪽에 보인다. 모든 문서(42건)에서 같은 자리다.
2. 챗봇이 닫힌 상태에서 누르면 챗봇이 열리고 `이 문서로 질문` 패널이 입력창 위에 뜬다. 열린 상태에서 눌러도 같다. 이때 **아무 질문도 보내지지 않는다**.
3. 패널의 문서 표시 줄이 지금 문서의 코드·제목과 같다.
4. 칩을 누르면 칩 글자 그대로 사용자 말풍선에 보이고, 말풍선 위에 `이 문서로 질문 · {제목}` 이 보인다. 문서 머리 → 칩 = 2클릭.
5. 칩 2개 각각에 대해 규칙 기반(엔진 없음)과 엔진 답 모두 근거에 그 문서가 들어 있다. 진행 확인 칩·위키 수정 안내·리포트 대기가 끼어들지 않는다. 최소 확인 문서: PPC-P-03, HUB-02, HUB-06, PPC-P-00, MKI-05 (제목에 판별 단어가 든 문서).
6. 패널이 열린 채 입력창에 `쿠폰 신작에만 걸 수 있어?` 를 보내면 말풍선에 `PPC-P-03 기준으로 쿠폰 신작에만 걸 수 있어?` 가 보인다. 보낸 뒤 패널이 닫힌다.
7. 패널을 연 채 다른 문서·화면으로 이동하면 패널이 닫힌다. 빈칸 채워 질문하기 패널과 동시에 열리지 않는다.
8. 키보드: 패널이 열리면 첫 칩에 포커스, `닫기`·전송 뒤 입력창에 포커스.
9. `server/`·`api/`·`src/lib/assistant.ts` diff 가 없다.

**⑤**

10. 근거가 있는 답은 본문 바로 밑에 구분선과 `이 답의 근거` 가 보이고, 문서 줄마다 제목·코드·`열기` 가 있다. `열기`·제목 클릭 모두 그 문서로 간다.
11. 위키 수정 안내 답(`위키 문서는 어떻게 수정해?`)은 라벨이 `참고할 문서` 다.
12. 근거 문서가 지금 보는 문서이면 `열기` 대신 `지금 보는 문서` 가 보인다.
13. 되묻기(`프로모션을 기획하려고 해` → 확인 칩)·정리 카드·리포트·리포트 실패 답에는 근거 줄도 `근거 문서 없음` 도 붙지 않는다.
14. 범위 밖 질문(`오늘 점심 메뉴 추천해줘`)에는 `근거 문서 없음` · `위키에서 찾아보기 →` 가 붙고, 누르면 `/search?q=오늘%20점심%20메뉴%20추천해줘` 로 간다.
15. 독 폭 320px 에서 제목이 길어도(`실시간 채널 배너 (미니 EPG · 편성표 · WING UI)`) `열기` 가 줄 밖으로 밀려 사라지지 않는다(제목이 줄바꿈된다).
16. 새 색·간격 토큰이 `styles.css :root` 에 늘지 않는다.

## 7. 이번에 본 것 중 다른 담당 확인이 필요한 것

- 범위 밖 질문의 엔진 답에도 `리포트로 자세히 받기` 칩이 붙는다(`sources-none.png`). 근거가 없는 답에 리포트를 권하는 것은 어색하다 — 서버 `reportHint` 판정 쪽이라 `chatbot-planner`·`dev-server` 확인 필요. 이 설계 범위에서는 손대지 않는다.
- 앞선 대화에서 PPM 을 고른 상태에서 PPV 문서(PPC-P-03) 칩을 누르면, 규칙 기반의 상품 범위 필터(`assistant.ts` 768행 부근)가 그 문서를 근거에서 뺄 수 있다. 수용 기준 5 확인 때 함께 보고, 빠지면 `assistant.ts` 변경이 필요한 별건으로 올린다.
